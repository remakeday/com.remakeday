# 서비스 운영 시나리오 A·B·C — 비용과 판단

작성 2026-09-16 · 전제: 원티드 해커톤은 실제로 접속 가능한 서비스여야 한다. 기간은 오늘부터 2026-10-31까지 45일(약 1,080시간). 단가는 Anthropic은 Claude API 스킬 참조표(2026-06-24 캐시), Gemini·AWS는 기억값이라 공식 가격표로 확인해 갱신한다(AWS 서울 리전은 버지니아보다 20~30% 높다).
호출 수·토큰 양은 추정이 아니라 테스터6 실플레이 판 `2338ec9f`(5회차 완주, 발화 27회·신의 질문 15회·원숭이손 1회 수락)의 `harness_event` 로그 실측이다.

**해커톤 규모(수십~수백 명)에서는 A 또는 B.** 시연 안정성이 중요하면 B(월 5만~9만 원 차이). C는 A·B보다 10배 이상 비싸고 동시접속도 나빠서, 손익분기(Opus 5 기준 완주 500~750판, Sonnet 5 기준 1,500판)에 닿을 일이 없다.

## 1. 공통 — 외부 API 판당 비용 (A·B의 변동비)

### 1.1 한 판(5회차)의 호출 실측

| 역할 | 호출 수 | 입력 문자 | 출력 문자 | 담당 API |
|---|---:|---:|---:|---|
| manager_check (관리자 보정, 비트마다) | 14 | 179,544 | 4,584 | Core → Anthropic |
| evaluator_verdict (밤 채점, 진실 주장별) | 50 | 94,125 | 6,184 | Core → Anthropic |
| advisor_answer (신의 질문) | 13 | 31,528 | 3,465 | Core → Anthropic |
| planner (하루 계획) | 5 | 8,718 | 4,726 | Core → Anthropic |
| **Core 합계** | **82** | **313,915** | **18,959** | |
| agent (NPC 대화) | 27 | 112,125 | 4,003 | NPC → Gemini |

회차별 하네스 호출 25·24·21·21·17. 재생성·폴백 0이라 1회 호출 기준이다(재생성이 나면 그만큼 늘어난다).
포함되지 않은 것: 임베딩(Gemini, 채점 RAG — 무시 가능), F2 발화 분류기(발화당 1회 약 1천 자, Haiku급이면 판당 $0.02), F8 밤 단서(LLM 호출 없음).

### 1.2 토큰 환산

한국어와 JSON이 섞인 프롬프트라 **1자 = 0.7~1.0 토큰**. Core 입력 22만~31만 토큰·출력 1.3만~1.9만, NPC 입력 8만~11만·출력 3~4천. 정확히는 Anthropic `count_tokens`에 실제 프롬프트를 넣어 재계산한다.

### 1.3 판당 비용

| Core 모델 (Anthropic) | Core | NPC Gemini Flash급 | **판당 합계** | 원화(1,400원/$) | 완주 100명 |
|---|---:|---:|---:|---:|---:|
| Opus 5 ($5 / $25 per M) | $1.4~2.1 | $0.03~0.05 | **$1.5~2.1** | 2,000~2,900원 | $150~210 |
| Sonnet 5 ($2 / $10) | $0.6~0.8 | $0.03~0.05 | **$0.65~0.85** | 900~1,200원 | $65~85 |
| Haiku 4.5 ($1 / $5) | $0.3~0.4 | $0.03~0.05 | **$0.35~0.45** | 500~650원 | $35~45 |

- 계산: Opus 5 = 0.22~0.31M×$5 + 0.013~0.019M×$25. NPC = 0.08~0.11M×$0.3~0.5 + 0.004M×$3 (Gemini Flash급 가정; Flash-Lite $0.01, Pro $0.13 안팎).
- 비용의 90% 이상이 Core, 그중 **관리자 검사가 Core 입력의 57%**. NPC 모델 선택은 결론을 바꾸지 않는다.
- 테스터 평균 진행이 1~2회차라 실제 평균은 표의 절반 이하.


### 1.3b NPC까지 Anthropic으로 붙일 때 (단일 벤더)

NPC 27회·입력 8만~11만 토큰·출력 3~4천 토큰 기준 NPC 비용: Haiku 4.5 **$0.10~0.13**, Sonnet 5 $0.20~0.26, Opus 5 $0.50~0.65. Gemini Flash급($0.03~0.05)보다 판당 $0.07~0.6 더 든다.

| 조합 (Core + NPC) | 판당 합계 | 원화 | 완주 100명 |
|---|---:|---:|---:|
| Opus 5 + Haiku 4.5 | **$1.5~2.2** | 2,100~3,100원 | $150~220 |
| Sonnet 5 + Haiku 4.5 | **$0.7~0.95** | 1,000~1,300원 | $70~95 |
| Sonnet 5 + Sonnet 5 | $0.8~1.05 | 1,100~1,500원 | $80~105 |
| Haiku 4.5 + Haiku 4.5 | **$0.4~0.55** | 550~770원 | $40~55 |
| Opus 5 + Opus 5 | $1.9~2.75 | 2,700~3,900원 | $190~275 |

- 비용 차이는 작고(전체의 5~15%), 얻는 것은 **어댑터 1개·키 1개·청구 1곳**, 프롬프트 캐싱을 NPC 프롬프트(인물 페르소나·지식 블록이 매 호출 동일)에도 적용할 수 있다는 점. NPC는 27회 대화형 호출이라 지연이 중요한데 Haiku 4.5가 가장 빠르다.
- NPC 품질은 별개 문제다. 7세 톤·금칙어·기억 규칙(npc-dialogue-2)이 Haiku에서 어떻게 나오는지 `run_npc_dialogue_check.py` 41문답으로 재측정한 뒤 정한다. gemma4 12b 기준선은 중간값 2.6초·서비스 실패 0.
- 추천 조합: **Core Sonnet 5 + NPC Haiku 4.5**, 절감 셋 적용 시 판당 $0.35 안팎. 채점·관리자 품질이 부족하면 Core만 Opus 5로 올린다(+$0.8).

### 1.4 절감 셋 (구조 변경 없음) — 적용 시 Opus 5 판당 $0.5, Sonnet 5 $0.25 안팎

1. **프롬프트 캐싱** — 관리자·채점 프롬프트의 앞부분(시스템 지시·시나리오 설명)은 매 호출 동일. 캐시 읽기는 입력 단가의 10%라 Core 입력이 절반. 안정 부분 앞, 변하는 부분(NPC 상태·발화) 뒤, `cache_control` 한 곳.
2. **채점 호출 묶기** — 진실 주장 10개마다 1회(5밤=50회) → 밤마다 1회. 호출 1/10, 중복 입력 소멸.
3. **관리자 검사 빈도** — 비트마다 14회인데 기획서 8.3은 "밤마다 보정". 밤 1회 또는 2비트마다로 → 최대 항목이 1/3.

### 1.5 전환 시 확인

- Core 교체는 채점 일관성·관리자 판단·신의 질문 답변을 바꾼다. E7 러너(`backend/scripts/run_model_descent.py`, `run_selfplay.py`)로 1판 이상 돌려 폴백·재생성·판정 분포 확인(`docs/model_evaluation.md` 부록 형식).
- 어댑터는 현재 Gemini·Ollama만 있다(`backend/apps/engine/adapter/outbound/llm/`). Core를 Anthropic으로 보내려면 `OllamaLLM`과 같은 인터페이스의 Anthropic 어댑터 1개 추가 + `.env`의 `CORE_LLM_MODEL` 값. 어댑터 패턴이라 엔진 코드 무변경.
- 동시접속은 VRAM 제약 대신 API 속도 제한만 남는다. 지연은 로컬 gemma4(NPC 중간값 2.6초)와 비슷하거나 짧다.

## 2. A안 — 지금 PC를 서버로, 모델은 외부 API

- 구성: 현재 홈서버에 FastAPI + Postgres(Docker), cloudflared 터널로 `api.remakeday.com`, 프런트 Vercel(`remakeday.com`). 배포 세션이 이미 이 방향으로 `.env`를 바꿔 두었다(OAuth 리다이렉트·프런트 URL 프로덕션 도메인).
- 고정비: **$0** 추가(전기·회선은 기존 지출). GPU는 놀리거나 로컬 개발·평가 러너에 계속 쓴다.
- 변동비: §1.3.
- 장점: 가장 싸다. 로컬 모델과 외부 API를 `.env` 한 줄로 오갈 수 있어 비교 실험이 쉽다.
- 위험: 집 회선·정전·PC 재부팅·다른 작업(러너 실행, 이미지 생성) 부하가 곧 서비스 장애다. 시연 시간에 이 PC로 다른 일을 못 한다. 업로드 대역폭이 동시접속 상한.
- 언제: 접속자가 적고 시연 시간이 정해져 있으며 그 시간에 PC를 비워 둘 수 있을 때.

## 3. B안 — AWS EC2 서버, 모델은 외부 API (권장)

| 항목 | 사양 | 시간당(서울) | 45일 |
|---|---|---:|---:|
| EC2 | t3.small (2 vCPU·2 GB) — FastAPI + Postgres(Docker) | ~$0.026 | **~$28** |
| EC2 대안 | t3.medium (4 GB) | ~$0.052 | ~$56 |
| EBS | gp3 30 GB | — | ~$5 |
| 탄력적 IP·전송량 | 연결 상태·소량 | — | $0~3 |
| 프런트 | Vercel 무료 | — | $0 |
| **고정비 합계** | | | **$35~65 (5만~9만 원)** |

- t3.micro(1 GB)는 Postgres와 함께 빠듯하다(어제 검토 S2197). 최소 t3.small.
- RDS 분리는 db.t4g.micro 월 $20~25 추가 — 해커톤 기간엔 같은 인스턴스의 Docker Postgres로 충분.
- 새 AWS 계정이면 프리 티어(무료 크레딧 또는 t3.micro 750시간/월)로 고정비가 거의 0.
- 이전 작업: `start_demo.sh`와 동일한 구성(Docker Postgres + uvicorn)을 EC2에 올리고, cloudflared 대신 탄력적 IP + DNS(또는 cloudflared 그대로). Ollama는 필요 없다. `.env`의 모델 값을 외부 API로.
- 장점: A의 가용성 위험이 사라진다. 로컬 PC는 자유롭다.
- 위험: 비용은 작지만 0이 아니다. AWS 계정·보안그룹·키 관리가 추가된다.

## 4. C안 — 전부 AWS (GPU EC2에 모델까지)

gemma4:12b(7.5 GB) + NPC 모델을 함께 올리려면 24 GB VRAM.

| 인스턴스 | GPU | 시간당(서울, 추정) | 24시간·45일 | 하루 12시간 |
|---|---|---:|---:|---:|
| g6.xlarge | L4 24 GB | ~$1.0~1.1 | **$1,100~1,200** | $550~600 |
| g5.xlarge | A10G 24 GB | ~$1.3~1.5 | **$1,400~1,600** | $700~800 |
| 스팟(위 인스턴스) | 동일 | 온디맨드의 30~40% | $400~600 | $200~300 |

- 변동비 0. 모델·데이터가 전부 자기 통제 아래.
- 동시접속은 GPU 한 장이라 지금 로컬과 같다(NPC·Core 순차). 늘리려면 인스턴스가 배수로 는다.
- 스팟은 시연 중 끊길 수 있다. 시연 시간대만 온디맨드로 켜고 나머지는 꺼 두는 운용이 현실적.
- 언제: 외부 API를 쓸 수 없는 제약(데이터 반출 금지 등)이 있을 때만.

## 5. 결정에 필요한 것

1. 시연 시간이 정해져 있고 그 시간에 홈 PC를 비울 수 있는가 → 예면 A로도 가능, 아니면 B.
2. Core를 어느 Anthropic 모델로 할지 → 채점·관리자 품질을 E7 러너로 한 번 재측정한 뒤 결정. 비용은 Sonnet 5가 Opus 5의 40%.
3. §1.4 절감 셋 중 어디까지 적용할지 → 캐싱은 코드 몇 줄, 채점 묶기·관리자 빈도는 유스케이스 변경.
4. Anthropic 어댑터 추가 작업을 F2·F11 뒤에 넣을지.
