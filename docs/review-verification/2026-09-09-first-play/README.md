# 첫 플레이 사용자 테스트 — 2026-09-09

상태: **테스터1 완주·피드백 수집 / 최종48%(DB47.9점) 확인 / 전체 맥락·지표 재설계 브레인스토밍**.

## 목적과 판정

- 정답을 모르는 참가자의 첫 판(5회차)에서 최종 이해도 약50%, 집중 플레이에서 약70%라는 목표가 관찰되는지 확인한다.
- 일반 플레이와 집중 플레이는 서로 다른 첫 플레이 참가자로 구분한다. 집중 조건은 시작 전에 정하고 “장면과 대화의 근거를 충분히 살펴봐 주세요”라고만 안내한다. 점수 목표나 정답 단서는 알려 주지 않는다.
- 같은 사람의 두 번째 판, 정답을 아는 개발자, 자동 플레이는 첫 플레이 난이도 표본에 포함하지 않는다.
- 최초 1명은 진행 절차와 문제 구간을 확인하는 예비 테스트다. 조건별 참가자 수, 개별 최종 점수, 중앙값·범위, 50점/70점 이상 인원, 완주·중단 인원을 함께 기록한다. 소수 사례만으로 목표 달성을 확정하지 않는다.
- 이미지가 도움이 되었다는 관찰·회상은 기록할 수 있다. 이미지 없는 조건과 비교하지 않았으므로 이미지 추가의 인과적 개선 효과는 미측정으로 남긴다.
- BGM·음성·게임 규칙·점수 산식은 변경하지 않는다.

## 진행

1. 참가자에게는 [첫 플레이 안내](../../first-play-guide.md)만 전달한다. 정답 사전 지식, 첫 플레이 여부, 일반/집중 조건, 기기·화면 크기, 시작 시각을 기록한다.
2. 진행자는 브라우저 개발자 도구 Network에서 `POST /sessions` 응답의 `attempt_id`를 기록한다. 참가자에게 개발자 화면을 보여 주지 않는다. 새로고침은 새로운 판을 생성하므로 동일 판을 이어가는 수단으로 사용하지 않는다.
3. 회차별 점수와 막히는 시점을 관찰한다. 조작 도움만 제공하고 추리 질문에는 정답·추천 답안을 주지 않는다. 제공한 도움과 오류·대기 시간을 기록한다.
4. 다섯 번째 밤의 **점수 화면에서, 결말·개발 회고를 보기 전에** 참가자의 이해와 근거를 자유 응답으로 수집한다. 이후 결말·회고를 확인한다.
5. 중단도 결과로 남긴다. 오류 때문에 중단한 경우 난이도 문제와 실행 장애를 분리한다.
6. 해당 판의 DB와 인스펙터 기록을 읽기 전용으로 조회해 참가자의 답안·점수·근거를 대조한다. 기존 답안을 재채점하거나 DB를 초기화하지 않는다.

## 기존 기록의 위치

- `attempts.id`가 `attempt_id`, `loops.attempt_id`와 `loops.loop_n`이 판·회차 연결이다.
- `nights`: `free_text`, `tapped_note_ids`, 최종 `claims`, `submitted`, `total`, `cell_scores`, `per_truth_claim`을 `loop_id`로 연결한다. 초안과 실제 제출 답안을 구분한다.
- `events.session_id`가 판 ID다. `answer_draft`, `answer_normalized`, `answer_scored`, `utterance`, `harness_event`를 회차별로 대조한다. 요청 실패·이미지 열람 여부·실제 대기 시간은 모두 자동 기록되는 것이 아니므로 관찰 메모를 보완한다.
- 인스펙터: `http://localhost:3500/inspector/{attempt_id}`. 토큰은 기존 로컬 설정을 사용하고 결과 파일에 복사하지 않는다.
- 이 폴더의 `smoke.json`은 기술 점검이다. 그 안의 `attempt_id`는 실제 사용자 표본에서 제외한다.
