# 테스터1 — 로그 대조와 전체 맥락 설계 쟁점

2026-09-09. 진단·브레인스토밍 자료이며 승인된 구현 설계가 아니다. 게임 코드·이미지·채점·DB는 변경하지 않았다.

## 결과 확인

- 판: `b56dca9d-8b01-4fe7-9b52-4afabb80e3f7`. 사용자 보고의 점수와 직접 규칙 원문이 일치한다.
- 점수: **0 → 50.2 → 36.5 → 55.2 → 47.9**. 화면은 `Math.round`로 표시하므로 최종 **48%**가 맞다.
- 5회차 완료, 모든 회차 `world_outcome=truck`. 판 생성부터 완료까지 약72분25초(대기·휴식 포함).
- 원본: [DB 로그](tester1-log.json), [집계](tester1-metrics.json), [참가자 피드백](tester1.md).
- 한 사람의 결과이고 조건·사전 지식은 미확인이다. 목표50%에 가까운 점수가 나왔다는 이유로 난이도·이해 전달 목표 달성을 선언하지 않는다.

## 1. 노트·장면·질문이 서로 다른 정보를 사용한다

확인한 코드:

- `loop_interactor.py:_accrue_next_fragment`는 회차에 지정된 파편 중 아직 저장되지 않은 것을 순서대로 하나 추가한다. 현재 장면의 사건이나 방금 대화한 내용과 연결하는 조건이 없다.
- 1회차에는 오전 전환에 “트럭 소리.”, 다음 전환에 “발 아래 콘크리트가 차다.”가 들어간다. 2회차에는 “민석이 방송실 근처를 서성인다.” 등이 해당 비트 서술과 별도로 추가된다.
- 노트는 밤에 선택하면 답안 후보에 포함되는 재료다. 밤 UI에는 파편/확인 사실/규칙과 관찰 분류가 있지만, 낮에서 왜 저장되는지와 어떻게 다시 쓸지 설명하는 연결이 부족하다.
- `night_interactor.py:_make_cause_chain`은 비트 서술과 일부 이벤트로 별도 LLM 요약을 만든다. 저장된 파편, 이미지의 관찰 설명, 프론트엔드의 대기 중 세계 힌트는 직접 입력하지 않는다.
- 신의 개입은 이 요약만 읽는다. 플레이어가 본 것과 답변자가 아는 것이 다르다.

실제 사례:

- 저녁 이미지 설명은 남은 쟁반이 세 개라고 알려 주지만, 1·2회차 “채연 말고 밥을 남긴 사람”에는 “그런 일은 없었다”가 반환됐다. 다른 쟁반의 주인이 밝혀지지 않은 것과 사건 자체가 없었다는 것은 다르다.
- 3회차 노트에 “충식은 어제 이송됐다”, “귀표”가 있지만 해당 회차의 `cause_chain`에는 둘 다 없다.
- “귀표는 무엇인가?”의 확인 노트가 “스피커에서 관리자의 목소리가 나오고 배급 줄이 생김.”이다. 사실 문장 형태를 갖췄어도 질문에 답하지 않는다.
- `ADVISOR_ANSWER_SYSTEM`은 기록의 누락을 “그런 일은 없었다”로 답하도록 하는 예시를 포함한다. 기록 부재와 거짓의 구분이 설계부터 흐리다.

## 2. 자동 대화가 직전 경험을 이어받지 않는다

- `_make_ambient` 입력은 두 인물의 설정·목표·현재 계획·규칙이다. 현재 비트의 서술, 이미지, 최근 대화 기억을 입력하지 않는다.
- `AMBIENT_SYSTEM`에는 “서로 딴소리해도 된다”가 명시돼 있다.
- 생성 결과는 인물의 기억과 세계 사건 로그에 추가된다. 근거 없는 잡담도 이후 답변·요약의 근거가 될 수 있다.
- 실제 1회차: “밥 먹었어?” → “기록해. 병검진 트럭 왔어.” → “열이 안 내려갔어.” → “그럼 기록해.”
- 하루 계획 생성은 5회차 모두 `혼자 있다`와 허용 어휘 `혼자 있는다`의 불일치로 폴백했다. 대화가 사용할 계획의 품질도 먼저 흔들린 상태다.

## 3. 신의 개입의 응답과 효용을 구분해야 한다

| 응답 분류 | 건수 / 전체12개 |
|---|---:|
| 그건 알 수 없다 | 5 |
| 그런 일은 없었다 | 2 |
| 기록은 이렇다 | 5 |

- 확인 노트 5개 생성은 유용한 답변 5개를 의미하지 않는다. 귀표 사례처럼 질문과 무관한 노트가 포함된다.
- “민석은 누구에게 보고하는거야?” → 확인 노트 “민석은 수첩에 적었다.”도 질문한 보고 대상을 답하지 않는다.
- 기존 `hit_cause_chain=true`는 7개지만, 여기에는 “그런 일은 없었다” 2개가 포함된다. 이것을 질문 성공률로 쓰면 안 된다.
- “왜”, 정체·바깥·미래·속마음 질문은 현재 정책에서 알 수 없다고 답한다. 사용자의 추리 목적에 비해 질문 범위가 좁고, 답하지 못했을 때 다음 관찰로 연결하는 경로가 없다.

## 4. 직접 규칙의 의미가 바뀐다

| 사용자 원문 | 저장된 행동 |
|---|---|
| 민석이 내 질문에 자세하게 답할 수 있도록 한다. | 민석: 질문한다 강제 |
| 채연은 묻는말에 자세하게 대답한다. | 채연: 질문한다 강제 |
| 은상은 소문의 진실을 무조건 나에게 이야기 해준다. | 은상: 소문을 낸다 강제 |

- 직접 입력 3건 모두 의도와 다른 행동으로 저장됐다. 이 표본의 수동 검토 결과이며 전체 모델 오류율은 아니다.
- 허용 어휘에 “답한다/근거를 설명한다/출처를 밝힌다”가 없다.
- `ADVISOR_MAP_RULE_SYSTEM`은 표현이 다르면 가장 가까운 어휘로 옮기라고 지시한다. `_map_custom`도 토큰·부분 문자열 유사도로 근사한다. 의도·대상·조건·수신자를 보존하는 검사가 없다.
- 채연에게 “답한다”를 요청했는데 “질문한다”로 바뀌면서 기존 원숭이손의 질문 금지와 충돌까지 발생했다.
- 필요한 규칙을 지원할지, 지원하지 못할 때 어떻게 대안을 제시할지 결정해야 한다. 지원하지 않는 의도를 다른 행동으로 조용히 바꾸는 동작은 제거 대상이다.

## 5. 추천·원숭이손의 설명과 실제 행동도 어긋난다

- 추천 입력에는 질문 원문·요약·기존 규칙이 있지만, 제출 가설·선택한 근거·질문의 답·미해결 쟁점이 연결되지 않는다.
- 1·3·4회차 후보는 “무슨 수를 쓰고 있는지 알 수 없도록”, “불안감을 조성하는 귓속말 방지”, “손목띠의 의미 파악에 집중하게”처럼 행동이 빠진 이유만 반환됐다. UI는 label만 보여 준다.
- 2회차는 대상 “은상이”가 명부와 다르다는 이유로 추천 생성이 실패했다. 폴백이 대상과 행동을 기계적으로 조합해 “민석: 배급을 다 먹는다 금지” 등을 만들었다. 이 후보들은 사용자의 질문에서 도출된 추천이 아니다.
- 3회차 원숭이손 설명은 검진을 통한 건강 확인·확산 방지를 말하지만 저장된 규칙은 **채연의 검진 금지**다.
- 원숭이손의 숨은 부작용 문자열에는 “플레이어의 사생활 침해” 등 세계 밖 표현이 있다. 이 설명만으로 실제 세계에 해당 부작용이 구현·발생했다고 확정할 수 없다.

## 6. 답안은 매번 새로 쓰게 되고, 점수도 안정적이지 않다

- `NightScreen`은 자유서술과 선택 노트를 빈 값으로 시작한다. 이전 밤의 실제 제출 내용을 불러오는 기능이 없다.
- 사용자 요청: 직전 회차 내용을 초안으로 먼저 채우고, 새 근거를 추가하거나 기존 주장을 수정하게 한다. 이전 내용을 정답으로 확정하는 것과는 구분해야 한다.
- 4→5회차의 주요 원인 서술은 유지됐지만 `motive-2: 그 두려움은 사실이다`가 partial→none으로 바뀌었다. 동기 점수 41.7→20.8이 총점 55.2→47.9 하락을 설명한다.
- 2회차에는 “아프면 이송당하고 사라지는거 같아.”를 동물 정체 명제의 partial 근거로 인정했다. 채점 적합성 의심 사례다.
- 모든 실제 결말은 truck인데 정답 명제에는 “이상자 3명 넘어 구역 폐쇄”가 고정으로 있다. 세계의 공통 진실과 이번 판에서 실제 일어난 분기를 나눠, 무엇을 추론하도록 요구할지 재설계해야 한다.
- 이번에는 저장 판정과 산식을 대조했으며 실제 LLM 재채점은 하지 않았다. 48점을 참가자의 객관적 이해 수준으로 확정하지 않는다.

## 7. 관리자·이미지·회고의 전달

- 관리자는 설정과 아침 서술, 일부 NPC 답변에 존재한다. “아예 구현되지 않았다”는 문제는 아니다. 참가자가 결말까지 기억할 정도로 역할과 결정이 전달되지 않은 문제다.
- 첫 비트의 `broadcast`는 비어 있고, 설정에 있는 긴 첫 아침 문장 `morning_text` 대신 엔진은 별도 짧은 아침 문장을 응답한다. 존재·권한·폐쇄 결정의 관계를 장면에서 경험시키는 경로를 검토해야 한다.
- E03은 채연의 경계 상태에 올바르게 매핑돼 있다. E01·E02와 비교하면 머리 모양·체격 인상·구도·명암이 달라 보인다(직접 이미지 비교에 따른 시각적 판단). 잘못된 파일 매핑으로 확인된 것은 아니다. E01·E02를 참조해 같은 인물의 경계 자세로 재제작하는 방향을 검토한다.
- 회고는 규칙 등록·충돌·하네스 개입 건수를 보여 주지만, “내가 의도한 것 → 번역된 규칙 → 실제 일 → 검사가 한 일”을 사례로 이어 보여 주지 않는다.

## 8. 현재 측정한 값과 아직 측정할 수 없는 값

- 직접 대화 요청30개, 자동 대화96줄, 노트19개(파편14·확인5).
- 원숭이손 수락2개, 직접 규칙3개, 추천 규칙1개, 충돌1개.
- 검사 문제를 기록한 호출22개, 폴백10개: 계획5·NPC 답변3·추천1·자동 대화1.
- `record_harness`는 문제가 있는 호출만 저장한다. 전체 모델 호출 수가 없어서 10/22를 전체 실패율로 쓰면 안 된다.
- `unknown_person`이 차량·번호·알려·뜻이·소문 같은 단어를 걸러낸 로그가 있다. 검사 개입의 일부는 오탐 의심 사례다.
- 실제 행동 기회·실행·미실행이 규칙별로 연결되어 있지 않으므로 규칙 준수율은 미측정이다. 도구 부작용1건도 원숭이손의 인과적 효과로 확정할 수 없다.

## 브레인스토밍 초안 — 같은 사건을 끝까지 연결하기

선택할 중심 경험:

1. **가설 검증 중심(제안):** 관찰 → 근거 저장 → 내 가설 → 확인 질문 → 다음 회차 실험 규칙 → 실제 변화 비교 → 가설 수정. 추리와 하네스 경험을 함께 묶을 수 있다.
2. **추리 안내 중심:** 막힌 지점에 질문·관찰 후보를 제공한다. 접근성은 높지만 직접 발견하는 비중이 줄어들 수 있다.
3. **자유 개입 중심:** 세계 행동을 폭넓게 바꾸고 결과를 해석한다. 자유도가 높지만 현재 엔진의 행동 표현과 인과 기록을 크게 확장해야 한다.

가설 검증 중심으로 갈 때의 제안:

- **노트:** 실제 관찰 장면 뒤에 생성하고 “어디서 본 것인지”를 유지한다. 관찰·소문·내 추측은 다른 신뢰 상태로 저장한다. 노트 선택이 자동 정답 보충으로 작동하지 않게 한다.
- **질문:** 플레이어가 본 근거와 공개 가능한 세계 사실을 같은 사건 ID로 조회한다. 비밀 정답 전체를 신에게 주는 방식은 피하고, “확인된 사실/아직 확인되지 않음/모순됨”을 구분한다. 모르는 질문도 확인할 수 있는 다음 행동으로 연결한다.
- **규칙 후보:** “이 근거 때문에 이 가설을 시험한다 → 이 행동을 바꾼다 → 다음 회차의 이 장면에서 차이를 확인한다”를 제시한다. 결과를 미리 보장하지 않는다.
- **직접 규칙:** 의도·실행 행동을 나란히 미리 보여 주고 적용 전에 확인한다. 의미를 보존할 수 없으면 지원 범위를 설명하고 가까운 실행 가능 대안을 명시적으로 선택하게 한다.
- **원숭이손:** 현재 막힌 관찰에 편의를 제안하고, 이후 실제로 생긴 이득·대가를 같은 규칙과 사건으로 추적한다. 생성된 부작용 문장을 실제 효과로 취급하지 않는다.
- **누적 답안:** 이전 제출 원문·선택 근거·최종 편집 내용을 잃지 않고 불러온다. 변경한 부분과 새 근거를 구분하며, 이번 세계에서 달라진 사실은 다시 확인한다.
- **관리자:** 첫 방송에서 역할을 인지시키고, 검진·보고·구역 결정에서 같은 행위자로 이어 보이게 한다. 정체 반전은 마지막에 남긴다.
- **회고:** 참가자의 실제 규칙 한 건을 사례로 의도→해석→행동→검사→결과를 보여 준다. 게임의 추리 성과와 시스템 품질을 별도로 설명한다.
