- 해석: 위 표의 "실제 원인"은 코드를 열어야만 알 수 있다. 플레이어가 거부 이유를 모르니 다시 쓸 방향을 잡지 못하고, 규칙으로 무엇을 확인할 수 있는지도 알 수 없어 정답 추리에 활용하지 못한다. 거부할 때 화면에서 실제 원인(인물은 1명만, 쓸 수 있는 행동 목록, 금지 표현 방법)을 바로 보여 준다. 밤 답안이 인정되지 않은 이유를 알려 주지 않는 F1과 같은 문제다.
- 원인(이번 플레이 1회차 미리 보기 7회 중 5회 거부):

  | 입력 | 거부 문구 | 실제 원인 |
  |---|---|---|
  | 서로의 역할을 무조건 말하기 | 그런 사람은 여기 없다 | 대상 인물 이름이 정확히 1명이어야 함. "서로"(여러 명)는 지원 안 함. 문구가 원인과 다름 |
  | 서로 무엇을 하고있는지 어떤 목적을 가지고있는지 설명하기 | 그런 사람은 여기 없다 | 위와 같음 |
  | 은상이는 귓속말 금지 | 실행할 행동을 확정할 수 없다 | "귓속말"이 행동 목록에 없음. 목록 문구("소문을 낸다")가 글자 그대로 들어 있어야 함. "금지"는 지원됨 |
  | 민석이는 기록하기를 안한다. | 실행할 행동을 확정할 수 없다 | "기록한다"가 글자 그대로 없음. 부정은 "금지·못하게·하지 않는다"만 인식하고 "안 한다"는 인식 못함 |
  | 민석은 기록하는걸 포기한다. | 실행할 행동을 확정할 수 없다 | 위와 같음 |

- 설계상 이유: 규칙은 시나리오에 미리 정해 둔 장면 기회(인물 × 행동 × 장면)를 켜거나(강제) 끄는(금지) 방식으로만 실행된다. 그래서 문장을 LLM에 자유 해석시키지 않고 "인물 1명 + 행동 목록 20개 중 1개(글자 일치) + 장면 조건 1개 + 강제/금지"라는 유한 문법으로만 받는다(코드 주석 "Deliberately finite grammar"). 모르는 사실을 알게 하거나 정답을 말하게 하는 규칙도 막는다.
- 문제: ① 행동 목록이 화면에 보이지 않아 플레이어는 목록을 추측해야 한다. ② 글자 그대로 일치해야 해서 자연스러운 활용형("기록하기를 안 한다", "소문을 내지 못하게")이 모두 거부된다. ③ 거부 문구가 원인과 어긋난다("서로" → "그런 사람은 여기 없다"). ④ 대안 3개가 모두 강제형이라, 금지를 원한 플레이어("기록 안 하기")에게 반대 의미만 제시된다.
- 코드 위치: `backend/apps/engine/app/use_cases/intervention_interactor.py` `_map_custom()`(대상 1명·행동 글자 일치·부정어 목록), 거부 문구 상수 `_REJECT_*`(L113~115), `named_targets()`; 행동 목록 `backend/apps/scenarios/scenario_a/adapter.py` `action_vocab`(L490~).
- 설계 시 확인: 행동 목록을 선택형 UI(인물 → 행동 → 강제/금지 → 장면)로 보여 줄지, 활용형·부정형("안 한다", "-지 못하게") 인식 확장, 여러 인물("서로", "모두") 규칙 허용 여부, 대안에 금지형 포함, 거부 문구를 실제 원인별로 분리.
- 관련: F2(불친절 상위 원칙), 테스터9 F21(규칙 누적 적용 안내 부재).
- 조치: 대부분 반영 (2026-09-18, 커밋 `cf5a0b7`) — `intervention_interactor.py`의 `_REJECT_MANY_TARGETS`·`_REJECT_GROUP_TARGET`("서로"·"모두"를 정확한 사유로 거부)·`_REJECT_NO_TARGET`·`_REJECT_MANY_ACTIONS`·`_REJECT_DOUBLE_NEGATION`, `_REJECT_UNKNOWN_ACTION` 뒤에 `self._usable_actions(target)`로 쓸 수 있는 행동 목록을 함께 보여 준다. `rule_grammar.py`의 `SUPPRESS_RE`에 "안 한다·안 하기·포기한다·포기·않는다"를 추가했다. 표의 5건은 `backend/tests/pure/test_custom_rule_grammar.py`로 재현·검증했다(2026-09-18 `.venv/bin/python -m pytest` 46 passed): "서로의 역할을…"·"서로 무엇을…" 2건은 이제 "그런 사람은 여기 없다"가 아니라 "한 사람에게만" + "'서로'"라는 정확한 사유를 낸다. "은상이는 귓속말 금지"는 "행동 목록에 없다"와 함께 은상이 쓸 수 있는 행동("소문을 낸다" 등)을 보여 주고 금지형 대안을 제시한다. "민석이는 기록하기를 안한다."·"민석은 기록하는걸 포기한다." 2건은 이제 거부되지 않고 (민석, 기록한다, suppress) 규칙으로 실행된다. 남은 것: 선택형 UI(인물→행동→강제/금지→장면)는 미착수.

### F5 — 신의 질문 답이 전부 "알 수 없다"라 쓸모가 없음 (2026-09-17)

- 장면: 밤 — 신의 질문(1·2회차 사용, 3·4회차 미사용)
- 요청:
  > 신의 질문도 답이 다 알 수 없다로 나와서 쓸모가 없어
- DB 확인(`intervention_question` 이벤트): 5문항 중 5개 unknown(100%).

  | 회차 | 질문 | 답(요약) |
  |---|---|---|
  | 1 | 서로의 규칙이 있는가 | 알 수 없다. 소등 후 자리에 머무는 규칙이 있다 |
  | 1 | 뭐가 궁금한건가? | 알 수 없다. 소독과 소등 지시가 연계된 절차인지 확인 필요 |
  | 1 | 세상이 멸망한다는게 뭔소린가 | 알 수 없다. 소독·소등 지시가 방어 체계인지 확인 필요 |
  | 2 | 이 게임이 뭔지 이해가 안되 목적이뭐야? | 알 수 없다. 각자의 역할 파악이 중요해 보인다 |
  | 2 | 준은 밤에 깨어있는다. | 알 수 없다. 기록만으로 확신할 수 없다 |

- 해석: 질문 5개 중 3개는 게임 목적·규칙을 묻는 질문이었다(F2 "목표를 모름"과 같은 뿌리). 신이 답할 재료가 공개 기록뿐이라 이런 질문은 모두 "알 수 없다"가 되고, 답 본문도 "확인이 필요하다"로 끝나 얻는 것이 없다. 두 번 연속 헛걸음한 뒤 3·4회차에는 질문 기능을 쓰지 않았다. 답마다 붙은 다음 행동 제안("내일 준에게 배급이 어디서 오는지 물어봐라")이 실제로 쓸 만한 정보였지만 "알 수 없다"에 묻혀 눈에 띄지 않았다.
- 원인·해결 방향: 테스터9 F19 분석과 같다(조언자는 공개 기록 안에서만 답함 → 필요한 질문일수록 unknown). 이번 판으로 누적 표본은 36문항 중 29개(81%) unknown. 이번 판에서 추가로 확인된 점: 게임 목적·사용법 질문도 신의 질문으로 들어오므로, 이런 질문에는 판정 대신 사용법·목표 안내로 답하는 경로가 필요하다.
- 코드 위치: `backend/apps/engine/app/use_cases/intervention_interactor.py`(답변·status·조언 조립), `backend/apps/engine/app/use_cases/advisor_advice.py`, 표시 `frontend/components/screens/GodScreen.tsx`.
- 관련: F2(목표를 모름), F3(규칙 막힌 이유), 테스터9 F16(신의 질문 사용법)·F19("알 수 없다" 편중).
