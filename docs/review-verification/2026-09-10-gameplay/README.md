# 게임 안내·장면 대화·조건부 보고 규칙·가독성 수정

사용자 승인한 브레인스토밍을 반영했다. 초기 3줄 안내와 접힌 상세 규칙, 낮의 도움말, 6장면/대화8→4회 표시, 명시적인 저장/거절 알림, 이미지에만 손상 연출,18px 본문/16px 보조·줄간격 1.7을 적용했다. 이전 밤 직접 쓴 글 복원과 짧은 신의 답변은 유지했다.

여섯 장면에 3줄씩 상황에 맞는 대화를 작성했다. 참여 인물과 실제 행동이 맞을 때만 나오며 자동 대화용 모델 호출은 0회다. 규칙 때문에 행동이 막혔거나 인물이 사라지면 원래 대화를 재생하지 않는다. 장면2는 준이 손목띠 숫자를 민석에게 묻고, 민석이 벗으면 안 된다는 반응을 한다. 장면3은 채연과 민석이 배급/기록을 두고 주고받는다. 이야기의 정답이나 숨겨진 정체를 대사에 덧붙이지 않았다.

조건부 보고 규칙은 인물·보고 주제·내 질문이라는 조건을 보존한다. 현재 시나리오에서는 보고하는 인물인 민석을 지원한다. 다른 인물/수신자/추가 시간 조건 등을 포괄적인 관찰 설명으로 바꾸지 않는다. 보고와 보다의 활용형을 구분하고, 장소 질문이나 '보고 얘기 말고'도 제외한다.

실제 exaone3.5:7.8b 샘플에서 배급 수량/보고 내용을 지어내는 문제가 확인됐다. 프롬프트 강화와 온도 조정만으로 해결되지 않아 이 규칙의 핵심 답변은 실제 장면 행동에 따라 작성한 5개 분기에서 선택하게 했다. 일반 자유 대화는 기존 NPC 모델이 담당한다. 보고의 구체적 내용은 인물의 작성된 지식이며 방문·기록·배급 행동을 충족한 뒤에만 알려준다. 발언은 플레이어에게 reported 출처로 보존한다.

## 검증

- 변경 전 안내 부재, 기록 낭독 대사, 잘못된 질문 조건, 모델이 작성한 가짜 보고 내용을 확인하고 수정했다.
- 별도 `pigfarm_test` 전체 **386 passed**. 실제 플레이 DB를 초기화하거나 기존 기록을 수정하지 않았다.
- 프론트엔드의 모의 API + headless 브라우저 검사 4개 통과: gameplay-clarity(390/1440px), connected-investigation, five-loop-flow(0/100% 결말 각각 5일), scene-illustrations. 브라우저 실행 오류 0건.
- TypeScript 검사 통과, 아키텍처 계약 4개 유지, 엔진 코어 금칙어 0건.
- 독립 리뷰에서 보고/보다 동음어 오발동과 보고 주체 변경 2건을 수정했다. 이후 순수 테스트 45개와 장면 6개 × 행동 조합 8개 검증이 통과했고, 중요한 잔여 지적은 없다.
- 최종 메모리 실행에서 일반 준/채연 질문은 각각 NPC 호출 1회(약 0.98/0.82초), 보고 규칙 질문 2개는 모델 호출 0회였다. 3번째 장면에서는 준비와 의도를, 5번째 장면에서는 자신의 보고 내용을 설명한다. 답변 원문은 `live-npc-results.json`에 있다.
- 검증 후 백엔드를 재시작했다. `/health`의 DB 상태는 ok이며 `/play`는 HTTP 200이다. 프로세스 정보는 `server-status.json`에 있다. GUI 브라우저는 열지 않았다.

일반 자유 대화의 모든 의미 정확성을 보증하는 것은 아니다. 장면 대사와 해당 보고 규칙 응답은 작성한 분기와 실제 행동 조건으로 통제한다. 자유 대화에는 모델 특유의 추론·표현 오류 가능성이 남는다. 이미 저장된 이전 대사와 점수를 다시 쓰지 않았으므로 기존 노트에는 과거 문장이 남아 있을 수 있다. 새 장면과 새 응답부터 변경된다.
