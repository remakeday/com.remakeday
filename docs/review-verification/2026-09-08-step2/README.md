# 자유발화 채점 개선 — 2026-09-08

## 재현과 수정

실제 로컬 Ollama `gemma3:12b`로 `NightInteractor.draft → _judge → scoring_rules`를 실행했다. 저장 포트만 메모리로 대체했으며 LLM 판정을 fake로 대체하지 않았다. 시나리오 A 정답 사실을 알고 작성한 진단 답안이므로, 첫 플레이에서의 발견 가능성이나 50~70% 도달률을 측정한 결과는 아니다.

수정 전 [before.jsonl](before.jsonl)에서 같은 사실을 담은 장문 82.9, 단문 75.6, 역순 76.7, 구어체 88.8점을 기록했다. 과거 보고의 정확한 ‘장문 0%’ 원문은 이번 입력 세트에 없으며, 그 수치 자체를 재현했다고 주장하지 않는다.

확인된 손실은 다음과 같다.

1. Normalizer가 최대 8개로 축약하며 정체·원인·동기를 누락하거나 확신 표현을 바꿨다. 역순 답에서는 숨김·검진 누락·전파가 빠졌다.
2. “병이 퍼지는 것을 막는다”를 “확산을 막기 위해”로 바꾸면 `확산을`, `막기`, `위해`가 새 토큰으로 판정되어 유효한 주장 전체가 폐기됐다. “열이 나서” → “열로 인해”도 폐기됐다.
3. 동기를 추가한 답이 20.4 → 16.0점으로 오히려 낮아졌다. 아픔·숨김·이송 두려움의 관계가 정규화에서 손상됐다.

`source_claims`는 자유서술과 선택한 노트를 원문 그대로 나눈다. 문장부호 뒤 공백 또는 줄바꿈에서 분리하고, 8칸을 넘으면 8번째 칸에 나머지를 모은다. 소수·부정·추측·인과 표현을 바꾸지 않는다. 감정이나 틀린 추론도 임의로 지우지 않으며 정오는 Evaluator가 판정한다. LLM 요약과 어휘 기반 날조 필터, 사용하지 않는 프롬프트·출력 DTO는 제거했다. `fabricated_dropped` 저장 필드는 호환용 빈 목록으로 유지한다. 기존 기록을 재채점하거나 수정하지 않았다.

이 수정만 적용한 [after.jsonl](after.jsonl)에서는 기본 네 표현이 모두 100점이었다. 추가 [edge-cases.jsonl](edge-cases.jsonl)에서 문장부호 없는 장문은 40.8점이었다. 원문은 모두 남았지만, 모델이 후보 하나의 내부 절을 2·5·7번 후보로 잘못 세어 인덱스 검증에 3회 실패하고 `none`으로 폴백했다. 각 LLM 입출력과 하네스 위반을 파일에서 확인할 수 있다.

번호를 설명하는 프롬프트 보완은 단독 장문에서 100점을 얻었지만, [전체 비교](prompt-regression.summary.json)에서 부분 정답 51.0점·감정 14.6점으로 과도한 점수를 주어 채택하지 않았다. 최종 구현은 판정 프롬프트를 원래대로 유지하고, `evaluator_verdict_output(candidate_count)`가 구조화 출력의 `matched_index`를 실제 후보 번호들의 enum 또는 null로 제한한다. 기존 인덱스 검증도 유지하며, 점수 가중치·정답 명제·partial 배점은 변경하지 않았다.

## 재실행

```bash
cd backend
.venv/bin/python scripts/run_free_text_scoring.py \
  --out ../docs/review-verification/2026-09-08-step2/recheck.jsonl --n 2 --check
.venv/bin/python -m pytest tests/engine -q --tb=short
.venv/bin/lint-imports
```

실제 LLM 검증은 `backend/.env`의 모델·Ollama 주소를 사용하고 DB를 사용하지 않는다. `--check`는 전체 13종에 대해 정답형 90점 이상, 동등 표현 편차 10%p 이내, 반복 편차 10%p 이내, 동기 추가 시 증가, 문장 간 지시어 표현 편차 10%p 이내, 오답·부정·혼합 답안 30점 미만, 감정만 쓴 답 0점을 검사한다. 실패 시 종료 코드 1, 결과와 게이트는 `.summary.json`으로 저장한다.

전체 엔진 테스트는 `tests/conftest.py`에 지정된 별도 `pigfarm_test` DB를 사용한다. 이번 환경에서는 `pigfarm-db` 컨테이너가 중지되어 처음에 연결 거절이 발생했고, 컨테이너 시작 후 실행했다. 운영 게임 데이터는 초기화하지 않았다.

## 한계

- 원문 보존은 코드로 보장하지만 의미 판정은 LLM에 의존한다. 낮은 오답 점수가 완전한 오답 거부를 뜻하지 않는다.
- 현재 정답 명제의 생략된 맥락 때문에 오답 “민석이 병을 퍼뜨렸다”가 “저녁까지 퍼졌다”에 부분 매칭되는 사례가 있다. 명백한 부정문에서도 일부 점수를 주는 오판이 관찰됐다. 이 항목은 채점 명제·근거 판정의 추가 개선 대상으로 남긴다.
- 입력 길이를 크게 늘린 스트레스 테스트, 다른 모델과 시나리오의 실제 LLM 정확도, 정답을 모르는 첫 플레이 사용자 검증은 수행하지 않았다.
- 프론트엔드는 변경하지 않았다. API는 기존 최대 8개 항목·수정 1회·5회차 흐름을 유지한다.
