# 밤 원문 이어 쓰기와 질문 답변 개선

- 밤 입력창은 직전 제출 밤의 `free_text`를 줄바꿈·공백까지 그대로 복원한다. 확인 화면에서 수정하는 `claims`와 선택한 근거는 별도로 유지한다. 선택한 이전 근거도 그날 채점에 포함된다. 기존 플레이 기록이나 점수를 수정하지 않았다.
- 직접 쓰기와 제출을 위에 배치했다. 관찰 기록 선택과 그림 모음은 기본으로 접고, 열 때만 API를 호출한다.
- 신의 질문은 짧은 자연어 답변을 먼저 보여주며, 원본 근거와 메타데이터는 펼쳐서 확인한다. 한 응답의 근거는 최대 2개다.
- 모델은 공개된 세계 설명, 최대 8개/원문 6,000자 이내의 기록, 같은 회차의 최근 질문·답변 2쌍을 사용한다. 정상 처리 시 모델 호출은 2회에서 1회가 된다. 스키마/출처 오류의 제한된 재시도는 유지했다. 질문 원문의 부정·시점은 바꾸지 않는다.
- 같은 대사도 회차·장면이 다르면 별도 사건으로 보존한다. 명시적으로 물은 회차를 우선 검색한다. 숨겨진 진실/원인 체인/미공개 미래 장면을 모델에 제공하지 않는다.

## 검증

- 변경 전 실패 확인: 원문 대신 claims 복원, 상속된 근거 누락, 세계 설명 없는 두 단계 질문 처리, 밤의 불필요한 노트/그림 선로딩.
- 별도 `test_db` 데이터베이스 전체 테스트 **334 passed**. 2~5번째 밤의 원문 누적·다른 판 격리, 출처 원문 검증, 부정/전언/미래 상태, 질문 예산, 반복 회차의 근거 회귀 포함.
- TypeScript 검사 통과. Import Linter 아키텍처 계약 4개 유지, 엔진 코어 금칙어 0건.
- 모의 API + 실제 프론트엔드 headless 검사: 모바일 밤 입력창 우선 표시, 원문 그대로 전송, 근거 선택/해제, 선로딩 없음, 그림 모음 키보드 접근성과 포커스 복원, 짧은 답변과 접힌 근거, 규칙 미리보기/적용, 회고.
- 5회차 화면 흐름 14개 검사 통과(최종 0%/100% 각각), 브라우저 오류 0건. 실제 플레이 API는 호출하지 않았다.
- 실제 `gemini-3-flash-preview` 6개 질문: 호출 각 1회, 재시도/폴백 0회, 응답 **5.08~10.42초**, 프롬프트 2,000~2,289자. 조건 질문, 후속 이유 질문, 숨은 정체 질문, 양/음 질문, 미래 조건을 확인했다. 원본은 `live-model-results.json`.
- 예: “채연이 아프면 어떻게 돼?” → 상태가 좋지 않은 사람의 이송 규칙을 설명하고, 채연의 검진 결과는 미공개임을 구분했다. 정체 질문에서 숨겨진 정답을 노출하지 않았다.
- 독립 읽기 전용 리뷰에서 회차 간 동일 문장 중복 제거 문제 1건 발견. 실패 테스트로 재현하고 회차/장면 보존 및 회차 우선순위로 수정했다. 추가 중요 지적 없음.

## 실행 상태와 한계

검증 후 이 프로젝트의 백엔드를 재시작했다. `/health` DB ok, `http://localhost:3500/play` HTTP 200. 루트 `/`는 `/play`로 연결된다. 브라우저 GUI를 열지 않았고 테스트 브라우저는 종료했다.

실측은 6문항 표본이며 모든 대화의 정답성을 보증하지 않는다. 자유 생성의 의미 정확성은 프롬프트와 실제 모델 검토에 의존한다. 코드 검사는 출처 ID/원문 일치와 공개 범위를 보장하며, 모든 자연어 추론을 증명하지 않는다. 현재 provider 응답 시간과 기존 RPM 제한은 남는다. 밤 최종 채점의 모델 호출 구조는 이번 변경 범위에 포함하지 않았다. Safari 무한 새 창 현상은 이전에 자동 열기 방지 설정을 추가했지만, Safari 환경의 정확한 발생 원인을 이번 화면 테스트로 확정한 것은 아니다.
