# 5회차 이해도와 최종 회고 구현 계획

사용자 승인 범위: 로드맵 1번 게임 규칙 수정. 자유발화 판정 개선, 단서·오디오 연결은 다음 단계다.

## 설계

- 총점은 상황 70점(원인 35 + 동기 35), 정체 30점. 최초 가중치이며 첫 플레이 50/70% 도달 여부는 추후 플레이테스트로 검증한다.
- 부작용은 채점 후보·분모에서 제외한다. 기존 JSON의 side_effect는 호환용 0으로 남긴다.
- 1~4회차는 점수와 무관하게 멸망 연출 → 질문/규칙 → 다음 회차. 5회차에만 종료한다.
- 점수는 세계의 생존 여부를 바꾸지 않는다. passed/closed_by는 기존 응답 호환용 분류다.
- 모든 최종 점수에 이해도 결과와 개발 회고를 제공한다. 진행 중에는 회고를 잠근다.
- 회고는 원숭이손 수락, 추천/직접 규칙 등록, 충돌, 도구의 부작용 기록, 모델 출력 보정 기록을 구분한다. 등록은 실행 성공이 아니며 검증하지 않은 성공률은 만들지 않는다.
- 진입의 '멸망을 막는다' 약속을 '왜 멸망했는지 알아낸다'로 수정한다.

## 구현 순서

1. 외부 LLM·저장소만 가짜로 대체한 submit 테스트로 고득점 중간 회차, 저득점 최종 회차, 부작용 제외를 먼저 실패시킨다. 회고 접근·집계도 테스트한다.
2. scoring_rules, night_interactor, inspector_interactor를 수정한다. 기존 저장 구조와 규칙 동작을 유지한다.
3. play 상태 전환과 결과 화면을 수정하고, 회고의 JSON 원문을 읽을 수 있는 요약으로 바꾼다. API 계약도 갱신한다.
4. 독립 엔진 테스트, TypeScript 검사, API를 모의한 실제 브라우저 흐름으로 검증한다. 운영 DB를 수정하지 않는다.

### 검증 범위와 다음 단계

실제 LLM 답안의 표현별 정답률은 이번 검증에 포함하지 않았다. 다음 2번에서 같은 의미의 장문/단문 답안이 같은 이해도로 평가되는지 확인한다. 신규 단서 이미지·음성·BGM 연결 및 첫 플레이 50%/집중 플레이 70% 목표의 사용자 검증은 후속 작업이다.

회고의 부작용 수는 도구 실행 기록 전체이며 원숭이손과의 인과 검증값이 아니다. 규칙 등록·충돌 수는 제공하지만 규칙 이행 성공률은 미측정이다. 기존 플레이 기록은 재채점하지 않는다.
