# 밤 기록은 참고 목록으로만 · 질문형 주장 안내 (휴먼테스트 순서표 3번)

등급: **A (채점 로직)** — 구현 에이전트는 계획·구현, 검토는 컨트롤러가 별도 리뷰어로.

근거: 테스터9 F17·F11 재정정(근거 원문 조각 "오후 검진을 시작합니다."가 무관한 cause-5에 인정 → 조각이 빠지자 64.2→55.4), 테스터11 O1(기록을 옮긴 문장은 점수, 제 말 요약은 오답)·O2(질문형 가설 전부 불일치).

## 항목 A — 고른 기록을 채점 후보에서 뺀다 (사용자 결정: F17 안 B)

### 설계 변경 — 기획서 v8.1 §7.2와 달라지는 점

- 기획서 §7.2 파이프라인 첫 단은 "[노트] ↓ 탭해서 답안에 넣는다"다. 이번 변경 뒤 **노트는 답안에 들어가지 않는다.** 밤 화면의 노트 목록은 글을 쓰며 펼쳐 보는 **참고 목록**이고, 주장(채점 후보)은 플레이어가 직접 쓴 글(`free_text`)에서만 나온다.
- 이유: 관찰 원문을 탭만 해도 주장이 되어 ① 추리 없이 관찰을 많이 고를수록 점수가 오르는 역유인(테스터11 O1) ② 원문 조각이 무관한 명제에 매칭되는 오인정(테스터9 F11: cause-5 ← "오후 검진을 시작합니다.")이 실제로 났다. §7.2의 원칙 "유저가 쓴 것만 주장으로 쪼갠다"를 더 엄격히 따르는 방향이다.
- 기록 원문을 글에 직접 옮겨 적으면 그건 플레이어가 쓴 문장이므로 주장이 된다(차단하지 않는다).
- 노트 탭(표시) 상태는 유지한다 — `tapped_note_ids` 저장과 다음 밤 복원(`previous_answer.tapped_note_ids`, 요청의 `inherited_note_ids`)은 참고 목록의 표시 복원 용도로만 남는다.

### 동작

| 구분 | 전 | 후 |
|---|---|---|
| `source_claims` | `free_text` + 고른 노트 원문 | `free_text`만 |
| 제출 조건(화면) | 노트 1개 이상 **또는** 글 | 글이 비어 있지 않을 때만. 비면 안내 문구 |
| 서버 draft | 빈 글 + 노트 → 노트 원문이 주장 | 빈 글 → 주장 0개(거절하지 않음 — 자가 플레이 "침묵" 페르소나 호환, 점수 0) |
| 노트 패널 이름 | "관찰 기록에서 근거 고르기 · 선택 N개" | "기록 보며 쓰기 · 표시 N개" + "기록은 참고용이다. 판정은 직접 쓴 글로만 한다" |

### 채점 일관성·기존 판 호환 판단

- **채점 후보**: `submit`은 `judge_candidates(night.claims)`를 그대로 쓴다. 새 draft의 `claims`에는 노트 원문이 없으므로 채점기 후보·`matched_user_claim`·`AnswerWrongClaims`가 모두 플레이어 문장만 가리킨다(매칭 문장 표시 일관).
- **ratchet(`scoring_rules.apply_ratchet`)**: 코드 변경 없음. 잠금 조건은 "직전 밤 매칭 문장이 이번 후보에 그대로 있음"이다. 이전 밤에 **노트 원문 조각으로 인정된 명제는, 이번 글에 그 문장이 없으면 잠금이 풀려 빠진다.** 노트 조각은 플레이어가 쓴 문장이 아니므로 "문장을 바꾸지 않았으면 판정이 나빠지지 않는다"는 ratchet 취지 밖이다. 조각을 글에 직접 옮겨 적었다면 후보에 있으므로 잠금이 유지된다. → 진행 중인 판은 배포 후 첫 밤에 조각 기여분만큼 점수가 내려갈 수 있다(테스터9 3일째 64.2→55.4와 같은 모양). 의도된 변화로 받아들인다.
- **배포 순간 진행 중이던 draft**: 이미 저장된 `night.claims`(조각 포함)는 제출 때 그대로 채점된다. 저장 데이터를 다시 쓰지 않는다 — 한 밤 한정 과도기.
- **DB 스키마·이벤트 스키마 변화 없음.** `AnswerDraftEvent.tapped_note_ids`는 계속 기록한다.
- **영향 추정(개발 DB, 상한):** 기록을 탭한 밤 113개 중 49개가 노트 원문 매칭으로 점수를 받았다. 새 규칙이면 통과선(50%)이 뒤집히는 밤 5개, 5회차 결말이 뒤집히는 판 1개. 과거 LLM 정리·셀프플레이 판이 섞인 수치라 상한으로 읽는다.
- **난이도:** 신이 "맞다"라고 한 사실이 노트에서 자동으로 주장이 되던 길이 사라져 체감 난이도가 오른다 → 난이도 조정(F11·F19)에 반영해야 한다.
- **셀프플레이 러너 불연속:** "성실" 페르소나는 노트 탭으로 점수를 받던 판이라 09-17 전후 수치가 이어지지 않는다. 재측정 결과를 `model_evaluation.md`에 적을 때 "09-17 이후 노트 비채점"을 표기한다.

## 항목 B — 질문형 주장 표시 (사용자 결정: 안 B)

- 확인 화면에서 질문형 주장 아래에 "질문이에요. '~다'로 단정해서 고쳐 보세요." 표시. 고치기를 이미 쓴 뒤에는 "질문이에요. 고치기를 이미 써서 이대로 제출돼요."로 바꿔 1회 제한과 충돌하지 않게 한다. 자동 변환·채점 제외 없음.
- **판별 위치: 백엔드 순수 함수** `domain/entities/claim_rules.is_question_claim(text)`. draft·PATCH 응답에 `is_question: boolean[]`(`claims`와 같은 길이·순서).
  - 이유 ① 테스트 용이성: 프론트엔드에는 단위 테스트 도구가 없고(Playwright 스크립트뿐), 한국어 어미 오판 사례는 pytest 매개변수 표로 촘촘히 검증하는 편이 낫다. ② 일관성: 주장을 쪼개는 곳(`source_claims`)·편집 저장(`edit_claims`)과 같은 층에서 판정하므로 화면이 받는 `claims`와 플래그가 어긋나지 않고, 이후 인스펙터·평가 러너도 같은 규칙을 쓸 수 있다.
- 규칙(문장 단위로 나눠 하나라도 질문형이면 참):
  - `?`·`？`가 있으면 질문.
  - 끝 문장부호·`;`·`~`·`ㅋ/ㅎ/ㅠ/ㅜ`와 끝 `요`를 떼고 어미를 본다.
  - `냐` / `ㄹ받침+까`(할까·일까·을까), `습니까·ㅂ니까` / `ㄴ받침·던+가`(인가·는가·은가·아픈가·건가) / `ㅆ·ㅄ받침+나·니`(했나·있니·없나), `프·되+나·니`(아프나·되니) / `는·ㄴ받침·ㄹ받침+지`(하는지·인지·할지).
  - 평서문 보호: `~다`로 끝나면("왜 그런지 모르겠다") 어미가 맞지 않아 거짓. `니까`(아프니까)·`그렇지`·`하나`(수)·`언니`는 거짓.

## 최종 리뷰 반영(수정 1회)

A등급 최종 리뷰 합의본을 한 번에 반영했다. 항목 B의 규칙·문구 중 아래와 다른 서술은 이 절이 우선한다.

1. **질문형 판별 보수화** (`domain/entities/claim_rules.py`) — 오표시보다 놓침을 택한다.
   - 물음표는 문장 끝에 있을 때만 질문이다(뒤에 따옴표·괄호·`!.~…;ㅋㅎㅠㅜ`·공백은 허용). 인용 대사 속 물음표(`채연이 "배고파?"라고 물었다`)는 평서.
   - `누군가·뭔가·언젠가·어딘가·무언가`로 끝나면 질문이 아니다.
   - `ㄴ받침+지`는 마지막 어절이 3음절 이상일 때만 질문(편지·먼지·반지·단지·왠지·은지 제외). "그게 뭔지"·"누구 건지"는 놓친다(허용).
   - 테스트 표에 오표시 12건·끝 물음표 변형 3건 추가(기존 36건 유지).
2. **질문 안내 문구** (`ConfirmScreen.tsx`, 해라체) — 고치기 전 "질문이다. '~다'로 단정해 고쳐 쓴다. 다음 밤 글에도 고쳐 써야 이어진다." / 고치기 뒤 "질문이다. 고치기를 이미 써서 이대로 제출된다."
3. **기획서 정본** (`REMAKE_DAY_기획서_v8.1.md` §7.2 파이프라인 그림·"파이프라인이 하나로 이어진다" 문단, §7.3 제출 화면 문장) — 노트는 참고 목록이고 채점 후보가 아니다, 신이 맞다고 한 사실도 글에 직접 써야 주장이 된다. 패치 기록 한 줄 추가.
4. **빈 글 안내** (`NightScreen.tsx`) — 주황 경고를 보조 텍스트(`opacity-60`)로, 문구 "한 줄 이상 쓰면 정리할 수 있다." `connected-investigation.cjs` 기대값 갱신(실행은 컨트롤러).
5. **고아 코드** — 운영 코드에서 쓰지 않는 `NoteRepository.by_ids` 제거. 테스트 가짜 2곳과 `run_free_text_scoring.py`는 `notes=None`(draft는 노트를 읽지 않는다). `night_interactor._disclose_night_clue` 주석 정정.
6. **기록** — 위 "채점 일관성·기존 판 호환" 절에 영향 추정·난이도·러너 불연속 세 줄.

반영 안 함: `inherited_note_ids` 죽은 매개변수(API 계약 필드), 기록 복붙 주장(수용), 확인 화면에서 고친 주장의 다음 밤 복원(문구 2번으로 안내), 밤 화면 2단 배치(후속).

남은 것(범위 밖, 기록만): ① 인용 대사 안에서 물음표 뒤에 공백이 오면 문장 분리가 따옴표 안에서 일어나 질문으로 표시된다(`채연이 "누구야? 왜?" 하고 물었다`). ② 기획서 v8.1에 노트 탭을 답안 입력으로 적은 곳이 §7.2·7.3 밖에도 남아 있다(§4.x 신의 질문 "탭 한 번으로 주장이 된다", 제출 표 "노트 탭 + 자유 텍스트", 에이전트 입력 "탭한 노트 항목", 측정·MVP 목록).
