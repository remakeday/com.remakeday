# REMAKE DAY — 관찰과 실험을 연결하는 재설계

날짜: 2026-09-09

상태: **사용자 승인 / 연결형 추리와 이미지 A안 구현 / 최종 기술 gate 검증 중**.

합의한 중심 경험은 “내 가설을 다음 회차에서 실험하는 추리”다. 이 문서는 그 방향을 실제 플레이 흐름과 검증 조건으로 구체화한다.

사용자는 본 설계 방향과 [이미지 구성 논의안](../../review-verification/2026-09-09-first-play/visual-brainstorm.md)의 A안을 승인했다. 구현 범위는 상태별 초상 중 E03 한 장을 교체하는 안에서 **E01/E04/E07/E10 고정 초상, 사건 그림 clue-07…12, 실제로 본 장면만 모으는 밤 갤러리**로 확정됐다.

근거: [테스터1 진단](../../review-verification/2026-09-09-first-play/tester1-findings.md). 테스터1은 최종48%(DB47.9점)에 도달했지만 노트·질문·규칙·결말이 서로 연결되지 않는다고 보고했다.

## 1. 목적과 범위

- 플레이어는 관찰한 근거로 가설을 만들고, 질문과 규칙을 통해 다음 회차에서 확인하며 이해를 갱신한다.
- 멸망의 이유를 이해하는 목적, 점수와 관계없는 5회차 진행, 마지막 제출 후 결말→개발 회고 공개를 유지한다.
- 원인35·동기35·정체30의 가중치를 유지한다. 정답 명제의 맥락과 현재 세계에서의 적용 가능성은 재검토한다. 규칙 성공 자체는 이야기 이해도 점수에 더하지 않는다.
- BGM·음성은 제외한다. 대화 상대 식별에는 E01/E04/E07/E10 고정 초상을 사용하고, 감정·상태 변화는 실제 장면과 대사로 보여 준다.
- 기존 플레이·점수는 원본으로 보존한다. 이번 개편의 비교 검증에는 테스터1 로그 복사본과 별도 테스트 데이터를 사용한다.

## 2. 참가자가 경험할 한 회차

1. **아침:** 이번에 확인할 가설과 적용된 규칙을 짧게 보여 준다. 첫 회차에는 관리자 방송이 무엇을 통제하는지 경험으로 소개한다.
2. **낮:** 장면·이미지·대화에서 관찰을 얻는다. 노트가 추가되면 원래 장면을 다시 볼 수 있다.
3. **밤:** 이전에 제출한 글과 선택 근거를 불러온다. 새 근거를 추가하고 기존 주장을 수정한다.
4. **결과:** 현재 답안에 대한 점수와 근거 상태를 보여 준다. 이번에 본 사실과 아직 모르는 이유를 구분한다.
5. **신의 개입:** 제출 가설과 연결된 질문으로 무엇을 확인할지 좁힌다. 현재 공개된 정보로 답하지 못하면 그 한계와 다음 관찰 경로를 안내한다.
6. **규칙:** 어떤 가설 때문에 누구의 어떤 행동을 바꾸려는지 확인하고 적용한다.
7. **다음 아침과 낮:** 규칙에 해당하는 행동 기회에서 실제로 무슨 일이 달라졌는지 관찰한다. 변화 없음·충돌·판정 불가도 결과다.
8. **다섯 번째 밤 이후:** 이야기의 결말을 본 뒤, 자기 실험의 의도·해석·행동·검사 결과를 개발 회고에서 확인한다.

### 플레이 예시

플레이어는 은상이 소문을 옮기는 장면을 보고 “소문이 사실을 부풀리는 것 같다”는 가설을 적는다. 신의 개입에서 해당 발언과 확인된 출처를 대조한다. 이후 “은상이 소문을 전할 때 알고 있는 출처도 함께 말한다”는 규칙을 선택한다. 다음 회차의 소문 장면에서 실제 발언과 출처를 관찰하고, 밤에 가설을 보완한다.

인물이 모르는 진실을 새로 알게 하지는 않는다. “진실을 무조건 말한다”를 지원할 수 없다면, 그 요청을 그대로 실행하는 척하지 않고 “알고 있는 출처를 밝힌다”라는 대안을 명시한다. 대안은 플레이어가 선택해야 적용된다.

## 3. 정보의 연결 원칙

동일한 공개 관찰은 화면·노트·질문·회고에서 같은 출처로 추적한다.

- 공개 관찰에는 판·회차·장면·관찰 ID, 행위자, 내용, 출처를 둔다. “이미지에서 보았다”, “직접 대답을 들었다”, “소문을 들었다”를 구분한다.
- 인물 발언을 들었다는 사실과 그 발언의 내용이 참이라는 판정은 다르다. 소문이나 NPC의 추측을 자동으로 확정 사실로 승격하지 않는다.
- 플레이어의 가설은 본인의 주장으로 저장한다. 가설이 세계 기록으로 다시 들어가 스스로를 증명하는 경로를 만들지 않는다.
- 신의 개입은 해당 시점까지 플레이어에게 공개된 기록과 그 기록의 명시적 확인 범위를 사용한다. 숨겨진 정답 전체를 넘겨서 설명하게 하지 않는다.
- LLM 요약은 원본 관찰의 대체물이 아니다. 요약에 빠진 사실도 출처로 조회할 수 있어야 한다.
- 이후 회차의 소거 규칙과 현재 장면의 등장인물 제한을 지킨다. 과거 노트는 과거 기록으로 표시하고 현재 인물의 존재를 새로 확정하지 않는다.
- 이미지·규칙·서술의 사실이 함께 성립하지 않으면 해당 이미지나 문구를 현재 장면에 사용하지 않는다.

## 4. 기능별 행동

### 노트와 대화

- 노트는 관련 관찰을 실제로 제시한 뒤 추가한다. 회차별 목록을 무조건 한 항목씩 꺼내는 방식을 없앤다.
- 첫 노트에는 “관찰한 내용을 모아 밤의 추리에 사용할 수 있다”는 용도를 짧게 안내한다.
- 낮에서도 노트와 원본 장면을 확인할 수 있게 한다. 노트 열람은 발화·시간 예산을 소비하지 않는다.
- 자동 대화는 현재 장소·장면 사실·관련 인물의 최근 발언·규칙을 입력받는다. 대화를 매번 채우기보다 연결되는 내용이 없으면 생략한다.
- 대화에서 발생한 새 사건과 단순 발언을 구분한다. LLM이 말한 것만으로 세계 사건이 발생했다고 처리하지 않는다.

### 질문

- 자유 질문과 회당3회 예산을 유지한다. 질문 예시는 현재의 근거·가설에 맞춘다.
- “확인됐다”, “기록과 모순된다”, “아직 확인되지 않았다”를 구분한다. 기록에 없는 것만으로 “없었다”고 단정하지 않는다.
- 답은 질문이 요구한 대상·사실을 실제로 다뤄야 한다. 관련 없는 사실을 “확인 노트”로 저장하지 않는다.
- 현재 정보로 답할 수 없다면 확인 가능한 인물·장면·기록을 안내한다. 안내는 현재까지 공개된 요소와 실제로 제공할 수 있는 행동에 한정한다.
- 관련 근거를 조회하지 못했을 때는 부족한 상태를 그대로 반환한다. 다른 사실이나 임의의 결론으로 채우지 않는다.

### 규칙 추천과 직접 입력

- 후보는 현재 가설 또는 질문에 연결한다. 각 후보에 근거, 바꿀 행동, 확인할 장면을 함께 보여 준다.
- 실행 가능한 후보만 제시한다. 의미 없는 조합으로 후보3개를 억지로 채우지 않는다. 가능한 후보가 적으면 적게 보여 준다.
- 직접 입력은 적용 전 미리보기에서 **사용자 원문 / 실행할 의미 / 제한 또는 대안**을 보여 준다.
- 대상·조건·행동·수신자·강제/금지의 의미를 보존해야 한다. “답한다”를 “질문한다”로 바꾸는 어휘 유사도 매칭은 사용하지 않는다.
- 첫 확장 범위는 테스터1이 요구한 설명·정보 공개 행동이다. 본인이 아는 관찰을 설명하거나 소문의 알려진 출처를 밝히는 행동을 지원한다. 진실을 새로 생성하거나 모든 질문에 답하는 능력은 부여하지 않는다.
- 기존 규칙과 충돌하면 어떤 행동이 왜 함께 성립하지 않는지 적용 전에 표시한다. 실제 실행 정책도 같은 해석을 사용한다.
- 실행 의미를 확정할 수 없으면 적용하지 않는다. 지원 가능한 대안을 선택하거나 다시 쓰게 한다.
- 다음 회차에서는 규칙에 해당하는 행동 기회와 실제 결과를 기록한다. 규칙 등록을 실행 성공으로 취급하지 않는다.

### 원숭이손

- 현재 관찰이나 반복되는 어려움에 연결되는 편의를 제안한다. 설명은 실제 적용하는 행동과 일치해야 한다.
- 제안한 이득과 구현된 대가가 모두 장면에서 발생할 수 있는 선택만 사용한다. 임의로 생성한 부작용 설명만 붙이지 않는다.
- 선택 당시 대가 전체를 미리 공개할 필요는 없지만, 발생한 결과는 이후 근거와 회고로 추적할 수 있어야 한다.
- 대가가 발생할 조건이 충족되지 않았다면 “발생하지 않음”으로 기록한다. 다른 도구의 부작용을 원숭이손의 결과로 합산하지 않는다.

### 이전 답안과 채점

- 같은 판의 직전 밤 제출 내용을 다음 밤의 수정 가능한 초안으로 불러온다. 제출 원문·선택 근거·확인 화면에서 편집한 최종 내용이 손실되거나 중복되지 않게 한다.
- “지난 회차에서 이어 쓴 초안”임을 표시한다. 이번에 추가된 관찰과 이미 선택했던 근거를 구분한다. 자동으로 제출하거나 정답을 보충하지 않는다.
- 새 판은 이전 판의 답안을 자동 입력하지 않는다. 회차 간 누적과 재도전은 구분한다.
- 공통 세계 진실과 분기에 따라 달라지는 사실을 구분한다. 특정 폐쇄 분기를 보지 않은 플레이어에게 그 사건을 실제 발생한 것으로 요구하지 않는다.
- 정답 명제는 “그 두려움”처럼 단독 판정에서 지시 대상을 잃는 표현을 피한다. 인물·행위·이유를 명시한다.
- 점수, 명제별 근거, 독립 검토 결과를 함께 확인한다. 답안이 달라졌다는 이유만으로 점수 단조 증가를 강제하지 않되, 같은 이해를 표현한 답안의 불합리한 판정 변화는 회귀 사례로 검증한다.

### 관리자·이미지 A안·마지막 회고

- 관리자는 첫 방송에서 배급·검진·보고의 담당자로 인지되게 하고 이후 결정에 반복해서 연결한다. 농장주라는 정체는 마지막 반전으로 남긴다.
- 상태별 초상 교체 대신 E01·E04·E07·E10을 인물별 고정 초상으로 사용한다. 사건 그림 clue-07…12는 현재 회차·비트·등장인물·실제 행동 조건이 맞을 때만 공개하며 얼굴·손 비노출과 숨은 정체 보호를 유지한다.
- 밤의 관찰 갤러리에는 해당 참가자가 실제로 본 그림만 회차·장면·짧은 관찰과 함께 보여 준다. 원본 그림과 출처를 다시 열고 실제로 본 장면끼리 비교할 수 있지만, 보지 않은 분기나 자동 인과는 추가하지 않는다.
- 회고는 해당 참가자의 실험 한 건을 먼저 보여 준다. 의도→해석된 규칙→기회→실제 행동→검사·수정→결과 순서다.
- 실제 수행 실패나 잘못된 해석도 보여 준다. 실패가 의도한 교육적 장치였던 것처럼 사후 설명하지 않는다.
- 이야기 이해도와 시스템의 동작 품질은 별도 지표로 제시한다.

## 5. 최소 계측과 판정

| 항목 | 계산·판정 | 저장할 근거 |
|---|---|---|
| 노트 출처 연결 | 원본 관찰이 연결된 노트 / 생성 노트 | 관찰·노트·장면 ID와 출처 종류 |
| 질문 유효 응답 | 질문을 실제로 다루고 근거에 맞는 응답 / 검토한 전체 질문 | 질문·전체 응답·근거 ID·답변 가능 범위·사람 검토 |
| 추천 맥락 적합 | 보유 근거·가설과 연결되고 실행 가능한 후보 / 검토한 제시 후보 | 가설·근거·실행 의미·제안 이유 |
| 직접 규칙 의미 보존 | 원문의 실행 가능한 의미를 보존한 해석 / 검토한 직접 입력 | 원문·해석·대안·확인 여부·검토 판정; 거절은 별도 집계 |
| 규칙 준수 | 평가 가능한 기회 중 규칙을 지킨 횟수 / 평가 가능한 기회 | 규칙·조건·기회·실제 행동·충돌·판정 |
| 검사 정확성 | 검토 표본의 오탐·미탐을 각각 집계 | 성공 포함 모델 호출·검사·재시도·대체·독립 검토 |
| 이해와 체험 | 회차별 점수·독립 검토·중단·맥락 혼란·대기 | 답안 버전·근거·시각·중단 이유·사후 인터뷰 |

- 분자·분모·검토 표본 수·시나리오/프롬프트/모델/규칙 버전을 함께 저장한다. 기회나 표본이 없으면 N/A로 표시한다.
- 사실을 확인할 수 있는 제한된 실행은 코드로 판정하고, 의미·관련성 검토는 근거를 붙여 사람 검토와 분리한다. 같은 모델의 자기평가를 최종 정답으로 사용하지 않는다.
- 원숭이손 효과는 연결된 사건으로 집계한다. 다른 조건과 비교하지 않은 수치는 인과적 효과라고 부르지 않는다.
- 테스터1의 48%는 개편 전 기준 사례로 보존한다. 이후 테스터1 재플레이는 사용성·개선 확인에 사용하며, 첫 플레이 난이도는 정답을 모르는 새 참가자로 확인한다.

## 6. 구현 경계와 실패 처리

- 기존 엔진·시나리오 구분을 유지한다. 관찰·가설·규칙·실행 결과의 계약은 엔진에서 정의하고 구체적인 이야기 사건·공개 조건은 시나리오가 제공한다.
- DB와 프레임워크는 어댑터에 둔다. 프론트엔드는 공개 가능한 DTO만 받으며 숨은 정답·원숭이손의 미공개 대가를 포함하지 않는다.
- 기록 저장 실패 시 연결됐다고 표시하지 않는다. 재시도는 같은 관찰이나 규칙을 중복 생성하지 않아야 한다.
- 기존 판에 없는 새 측정값은 추정해서 채우지 않고 “기록 없음”으로 남긴다. 이전 응답·화면과의 호환 범위는 구현 계획에서 해당 계약별로 확정한다.
- 새 로깅은 기능의 사건 연결에 필요한 범위로 시작한다. 별도 분석 서비스나 범용 규칙 언어는 만들지 않는다.

## 7. 구현 순서와 완료 기준

1. **근거와 답안 연결:** 장면→노트→질문 기록을 연결하고 이전 답안 불러오기를 구현한다. 귀표·남은 쟁반 질문이 엉뚱한 사실이나 사건 부정으로 바뀌지 않아야 한다.
2. **대화와 규칙:** 대화 맥락, 계획 생성·인물 검사 오탐, 추천·직접 규칙 미리보기·실행을 정리한다. 테스터1의 세 직접 입력이 원문의 의미 또는 명시적으로 선택한 대안으로만 적용되어야 한다.
3. **서사와 회고:** 관리자 전달·원숭이손의 이득과 대가·고정 초상·clue-07…12·실제 결과 회고를 연결한다. 보여 준 장면과 저장된 사건이 같아야 한다.
4. **통합 검증:** 5회차 진행·0/100점 결말·회고·재시도·모바일을 회귀 검증한다. 실모델에서는 테스터1의 실패 사례와 근거·가설 연결을 확인한다.
5. **사용자 검증:** 테스터1이 달라진 흐름을 확인한 뒤 새 참가자로 첫 플레이를 측정한다. 점수뿐 아니라 질문 효용·규칙 의미·맥락 이해 결과를 함께 검토한다.

한 회차 흐름과 이미지 A안은 사용자 승인을 받아 구현됐다. fake API와 실제 frontend의 기술 통합, frontend 독립 검토, 이미지 독립 검토는 별도 보고서에 근거가 있다. 최종 backend 전체 DB suite는 307 passed이고 focused pure suite 최신 owner·직전 독립 reviewer 결과는 각각100 passed다. 최종 07:35 실제 Ollama 통제는 kind21/21과 원문 인용30개를 맞혔지만 SPC2 반대 사실을 supported로 답해 RM1 의미 승인을 받지 못했다. 이 한계를 공개한 수동 preview로 최신 8500과 frontend `/play`를 기동했다. 다음 단계는 Gemini/Ollama 판정 adapter 전환 구현과 그 결과 검증이며, adapter 존재만으로 의미 gate를 통과한 것은 아니다. 사람 재플레이와 첫 플레이 난이도·체감 효용 측정은 기술 완료와 별도의 후속 검증이다.
