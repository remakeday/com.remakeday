- 검토 등급: **A (DB 스키마 변경 + 공개 API 추가)**. 제출 선언 전에 들어가야 하는 마지막 기능이다.
- 결정: 브레인스토밍 2026-09-19 (저장 구조·자유 의견·부분 응답·화면 배치·집계 대상·오늘 범위 6건 사용자 확정)

## 0. 문제

게임을 끝까지 한 사람이 어떻게 느꼈는지 남는 기록이 없다. 완주율은 이미 이벤트 로그로 계산되지만, 재미·참신성·AI 체감 같은 주관 평가는 수집 경로 자체가 없다.

제약이 하나 있다. **제출 선언 뒤에는 앱 코드를 고칠 수 없다.** 수집 경로(화면·API·테이블)는 지금 넣어야 하고, 보여 주는 쪽(리서치 사이트)은 별도 저장소라 언제든 만들 수 있다. 그래서 오늘은 수집만 만든다.

## 1. 확정한 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 저장 구조 | 새 테이블 `survey_votes` | 판당 한 표를 DB가 보장하고, 항목별 평균이 숫자 컬럼 평균이라 집계가 단순하다 |
| 자유 의견란 | 두지 않는다 | 사용자 결정. 화면을 단순하게 유지 |
| 부분 응답 | 허용 | 문턱을 낮춰 표를 더 모은다. 항목마다 응답 수가 달라지므로 공개 페이지에 항목별 표본 수를 함께 적는다 |
| 화면 배치 | 설문이 먼저, 건너뛰기도 같은 크기 | 물어보는 것은 확실히 하되 강요하지 않는다 |
| 집계 대상 | 사람 판만 | 개발·자동 플레이가 섞이면 완주율이 실제보다 낮게 나온다 |
| 오늘 범위 | 수집만 | 리서치 사이트는 프리즈 대상이 아니라 급하지 않다 |

### 컨트롤러 판단 3건 (사용자 부재 중 결정, 되돌릴 수 있음)

1. **중복 투표는 오류 대신 조용히 첫 표만 남긴다.** 새로고침·더블클릭에 오류 화면을 띄울 이유가 없다.
2. **건너뛰기도 행으로 기록한다.** "건너뛴 사람"과 "그냥 나간 사람"이 구분돼야 참가율이 정확해진다.
3. **프랙탈 11파일을 다 만들지 않는다.** 이 저장소의 실제 관행은 테이블마다 11파일이 아니라 `game_state_orm.py`·`game_repository.py`에 모아 두는 것이다(attempts·loops·nights·notes·rules·npc_states가 모두 한 파일). 설문은 도메인 로직이 없어 같은 관행을 따른다.

## 2. 데이터 모델

### 새 테이블 `survey_votes`

```
id          uuid      PK
attempt_id  uuid      NOT NULL UNIQUE     -- 판당 한 표
user_id     uuid      NULL, index         -- 집계에서 사람 판을 거르는 열쇠
skipped     boolean   NOT NULL DEFAULT false
fun         smallint  NULL  CHECK 1..5    -- 재미·몰입도
novelty     smallint  NULL  CHECK 1..5    -- 참신성
ai_agency   smallint  NULL  CHECK 1..5    -- AI 활용 체감
polish      smallint  NULL  CHECK 1..5    -- 완성도
recommend   smallint  NULL  CHECK 1..5    -- 추천 의향
created_at  timestamptz NOT NULL DEFAULT now()
```

**제약**
- `attempt_id` 유니크 — 한 판에 한 표. 중복 요청은 이 제약에 걸려 조용히 무시된다.
- 각 점수 컬럼 `NULL 또는 1~5` — 부분 응답 허용.
- `skipped = true`면 다섯 점수가 모두 NULL이고, `skipped = false`면 적어도 하나는 값이 있어야 한다. 별점 없이 보낸 요청은 건너뛰기로 저장하므로 두 조건 사이에 빈틈이 없다.

**외래키는 걸지 않는다.** 이 저장소의 기존 관행이다(`attempts.user_id`도 인덱스만 있고 FK가 없다). 관계는 아래 ERD와 이 문서로 남긴다.

### ERD 변경

```
users ──1────< survey_votes >────1── attempts
        user_id                attempt_id (UNIQUE)
```

- `attempts` 1 —— 0..1 `survey_votes` — 한 판은 표를 한 번 내거나 내지 않는다.
- `users` 1 —— 0..N `survey_votes` — 한 사람이 여러 판을 평가할 수 있다.
- 기존 테이블은 **하나도 바뀌지 않는다.** 새 노드 하나만 붙는다.

### 마이그레이션

alembic 리비전 하나. `survey_votes` 생성과 인덱스·제약만 만든다. 기존 데이터에 손대지 않으므로 되돌리기도 테이블 삭제 한 줄이다.

## 3. API

```
POST /attempts/{attempt_id}/survey
```

기존 `owned` 라우터에 붙는다. 로그인과 판 소유자 확인을 그대로 물려받아, 남의 판에는 투표할 수 없다.

**요청**
```json
{"skipped": false, "fun": 5, "novelty": 4, "ai_agency": 5, "polish": 3, "recommend": 4}
```
- `skipped`만 `true`로 보내면 나머지는 없어도 된다.
- 각 점수는 1~5 정수이거나 `null`. 범위를 벗어나면 422.

**응답 200**
```json
{"recorded": true}
```
- 이미 표가 있으면 `{"recorded": false}`. 오류가 아니다. 첫 표가 유효하다.

**계약 문서**에 이 절을 추가하고, 422 상한 목록에도 적는다.

## 4. 화면

`ClearScreen.tsx` 맨 위에 설문 블록이 먼저 나온다. 회고와 "다시 시작"은 설문을 보내거나 건너뛴 뒤에 나타난다.

```
        이 게임은 어땠나
  재미·몰입도      ☆ ☆ ☆ ☆ ☆
  참신성           ☆ ☆ ☆ ☆ ☆
  AI 활용 체감     ☆ ☆ ☆ ☆ ☆
  완성도           ☆ ☆ ☆ ☆ ☆
  추천 의향        ☆ ☆ ☆ ☆ ☆

     [ 평가 보내기 ]   [ 건너뛰기 ]
```

- 항목 문구는 사용자가 준 표 그대로 쓴다. 각 항목의 뜻(질문 문구)은 별점 아래 작은 글씨로 한 줄 붙인다.
- 두 버튼은 같은 크기·같은 위치다. 건너뛰기를 숨기거나 작게 만들지 않는다.
- 별점을 하나도 안 매기고 "평가 보내기"를 누르면 건너뛴 것과 같이 처리한다.
- 보낸 뒤에는 짧은 감사 한 줄을 남기고 설문 블록을 접는다. 되돌리기는 없다.
- 네트워크가 실패해도 회고와 다시 시작은 열린다. 평가 때문에 게임이 막히면 안 된다.

**접근성** — 항목마다 라디오 그룹, 별 하나하나가 버튼이고 이름은 "재미·몰입도 3점" 형식이다. 키보드로 조작된다.

## 5. 나중에 만들 집계 (오늘 범위 밖)

리서치 저장소(`research.remakeday.com`)에 스크립트를 하나 두고, DB를 읽어 집계 JSON을 `_data/`에 쓴다. 기존 `refresh_research_data.py` → `_data/research_figures.json` → 페이지가 읽는 흐름과 같다.

보여 줄 수치는 넷이다.

| 수치 | 계산 |
|---|---|
| 완주율 | 5회차 밤까지 채점된 판 ÷ 만들어진 판 |
| 투표참가율 | 표를 낸 판 ÷ 클리어 화면 도달 판. 분모는 완주율 분자와 같은 집합(5회차 밤 채점 완료)이고, 건너뛴 판은 분모에만 든다 |
| 항목별 평점 | 항목마다 NULL을 뺀 평균, 응답 수 병기 |
| 전체 평점 | 다섯 항목 평균의 평균 |

**사람 판만 센다.** 개발 계정과 사용자 없는 자동 플레이 판을 뺀다. 필요한 정보는 판과 표에 이미 있어 오늘 더 넣을 것이 없다.

**공개 페이지에는 집계만 올린다.** 개인 식별자는 나가지 않는다. 리서치 저장소의 공개 검사 스크립트가 한 번 더 막는다.

## 6. 작업 순서와 테스트

| Task | 내용 | 확인 |
|---|---|---|
| T1 | 마이그레이션 + ORM + 리포지토리 | 테이블 생성·되돌리기, 유니크 제약이 두 번째 표를 막는지 |
| T2 | 인터랙터 + 엔드포인트 + 계약 문서 | 200·중복 200(recorded false)·남의 판 404·범위 밖 422·건너뛰기 행 |
| T3 | 클리어 화면 설문 블록 (Codex astra) | tsc, 헤드리스 |
| T4 | 헤드리스 시나리오 추가 | 별점 후 전송, 건너뛰기, 실패해도 다시 시작이 열리는지 |
| T5 | 전체 검증·배포 | 백엔드 전체·헤드리스 전체·실서버 스모크 |

**전체 확인** — 백엔드 pytest 전부, `lint-imports`, `tsc`, 헤드리스 전종, 재기동 뒤 실서버에서 표가 실제로 쌓이는지 한 판.
