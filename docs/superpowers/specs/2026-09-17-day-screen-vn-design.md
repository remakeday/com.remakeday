## 0. 문제

낮 화면(`frontend/components/screens/DayScreen.tsx`, 830줄) 한 화면에 장면 그림·인물 선택·채팅 로그·입력창이 동시에 있다(F6). 서버가 장면 서술·규칙 결과·원숭이손 부작용을 한 문단으로 합쳐 보내서(`scene_execution.execute_scene`의 `" ".join(narration)`) 무엇이 장면이고 무엇이 규칙 결과인지 구분되지 않는다(F13·F20). 단서 조각은 기록에만 조용히 쌓이고(F23), 도움말과 기록 진입점이 흩어져 있다(F4).

## 2. 화면 흐름

**공통 HUD (상단 한 줄)**

```
3일째 / 5일                                  [기록·안내]
```

[기록·안내]는 전체 화면 패널을 연다. 기존 상단 `<details>` 플레이 안내와 그림 아래 "단서 기록 열기" 버튼은 없앤다. 신의 개입 화면에서도 기록을 열 수 있어 F18 후반이 해결된다.

**낮 화면 — 장면 하나**

1. **장면 도입**: 장면 그림을 크게(여러 장이면 넘기기). 그림 아래 대사창에 서술 줄이 한 줄씩 — 장면 서술 → 방송 → 인물 행동·규칙 결과 → 설명 규칙 대사 → 원숭이손 부작용 → 인물 혼잣말 → 단서 조각. 클릭·스페이스·▶로 넘기고 "모두 보기"로 건너뛴다.
2. **도입 끝**: 마지막 줄에 닿으면 대화 모드로. 그 장면에 원숭이손 제안이 있으면 이때 팝업(내용·대가 암시 문구는 현행 유지, 뜨는 시점만 도입 뒤로).
3. **대화 모드**:
   - 인물 선택 4칸(채연·민석·은상·준). 이 장면 대화를 마친 인물은 흑백(선택은 막지 않음, 선택 시 입력창 잠김 — 현행).
   - 선택한 인물 초상을 크게. 표정은 지금처럼 mood(calm·uneasy·wary).
   - 대사창에 답변이 한 줄씩. 마지막 줄까지 봐야 입력창이 다시 열린다.
   - 입력줄 `[질문 입력][묻기] ▮▮▮▯▯`, 옆에 "다음 장면"(처리 중 "다음 장면 준비 중…").
4. **대사창 ◀**: 오늘 하루의 모든 줄을 시간 순으로 거슬러 올라간다. 줄 종류마다 화자 라벨·글꼴·색·아이콘이 다르다.
5. **하루 끝**: 밤 화면으로. 5회차에는 그 전에 트럭 방송 단서가 끼어든다(9b에서 연결).

**음성**: 관리자 방송 줄에 음성을 붙여 그 줄이 보일 때 재생한다. 인물 음성은 배제 결정 유지.

**다른 화면**: 아침·밤·신의 개입은 HUD만 추가하고 본문은 그대로. 밤의 "기록 보며 쓰기"(3번 작업)도 그대로.

**모바일(390px)**: 초상 높이를 줄이고, 인물 선택은 가로 4칸, 대사창·입력줄은 하단 고정. 테스터8 F1 스크롤 초기화(`play/page.tsx`) 유지.

## 3. 서버 줄 데이터

**새 응답 필드 `lines`** — `POST /sessions/{attempt_id}/loops`(회차 시작), `POST /loops/{loop_id}/beats/next`, `POST /loops/{loop_id}/paw/respond`, `POST /loops/{loop_id}/utterances`. 기존 `narration`·`ambient`·`broadcast`·`reply`는 유지한다(기존 헤드리스·셀프플레이 러너 호환, 단계적 이전).

```ts
interface Line {
  kind: "scene" | "action" | "rule_result" | "statement" | "broadcast"
      | "npc" | "paw_effect" | "fragment" | "system";
  speaker: string | null;        // 인물 코드·"관리자"·null
  text: string;
  image_id: string | null;       // 이 줄에서 바꿔 보여 줄 장면 그림
  voice_id: string | null;       // 음성이 있는 줄(관리자 방송)만
  observation_id: string | null; // 단서 기록과 연결(NEW·그림 열기)
}
```

**종류 결정 — 서버가 지금 문단을 합치는 지점에서 그대로**

| 지금 합쳐지는 것 | kind |
|---|---|
| 장면 기본 서술 `beat.narration` | `scene` |
| 규칙 없이 일어난 인물 행동 서술 | `action` |
| 규칙이 강제·억제한 행동 서술(`winner` 있음) | `rule_result` |
| 설명·출처 규칙으로 나온 "민석: …" 줄 | `statement` (speaker=인물) |
| 원숭이손 부작용 관찰 문장 | `paw_effect` |
| 단서 조각(`loop_interactor` 조각 공개) | `fragment` |
| 관리자 방송 `broadcast` | `broadcast` (speaker="관리자", voice_id) |
| 인물 혼잣말 `ambient.lines` | `npc` |
| 인물 대화 답변 `reply` | `npc` — 서버 순수 함수로 문장 단위 분할(따옴표 안 마침표는 나누지 않음) |
| 무의미 입력 대체 문장(`gated`)·단서 발견 알림 | `system` |

**구현 원칙**

- `execute_scene`이 문자열 대신 줄 레코드를 쌓고, `narration`은 그 `text`를 이어 붙여 계속 만든다.
- 서버에 kind별 분기 로직은 없다 — kind는 데이터 값. 모양은 프론트의 표시 표가 정한다.
- 문장 분할 함수는 `backend/apps/engine/domain/entities/`에 순수 함수로, 표 기반 테스트.
- DB 마이그레이션 없음. 줄 목록은 응답 조립 때 계산하고 저장하지 않는다.
- "오늘 하루 전체" 뒤로 가기는 프론트가 받은 `lines`를 하루 동안 누적해 만든다. 새로고침 시 사라지나 `/play`는 원래 새로고침 복원이 없다.
- NEW 표시는 관찰의 회차·장면이 직전 밤 이후인지로 판정한다. 읽음 여부는 저장하지 않는다.
- 계약: `docs/spec/api_contract.md`에 `lines`, `frontend/contracts/api.ts`에 `Line` 타입.
- 단서 조각 문장과 실제 대사의 불일치(예: "준이 귀표라는 단어를 쓴다"인데 대사에 없음, F23)는 시나리오 문장 작업으로 따로 둔다.

**`DayScreen.tsx`는 조립과 상태만.**

- 화면 모드 `intro`·`dialogue` 두 가지. 전환 규칙은 모드마다 한 객체에 둔다(State 패턴, 작은 reducer) — intro에서 마지막 줄 도달 → 원숭이손 팝업 또는 dialogue, dialogue에서 "다음 장면" → intro. `if (mode === …)`를 흩뿌리지 않는다.
- 줄 누적 `todayLines` + 현재 위치 `cursor`. 입력 잠금 판정은 "cursor가 마지막 줄인가" 한 곳.
- 줄 그리기는 `lineStyles` 표 조회만, 조건 분기 없음.
- API 호출·원숭이손 수락 즉시 장면·음성 재생 로직은 옮기기만 하고 동작은 바꾸지 않는다.

**없어지는 것**: 상단 `<details>` 플레이 안내, 그림 아래 "단서 기록 열기" 버튼과 기존 단서 기록 대화상자, 입력창 위 "오늘 남은 대화 N회" 문장, 채팅 로그 목록.

**기존 동작 보존 점검 목록**: 무의미 입력 대체 문장, 대화 완료 인물 선택 시 입력 잠김, 처리 중 라벨, 원숭이손 수락 즉시 장면·삽화, 삽화 캡션, 원숭이손 대가 암시 문구, 스크롤 초기화, 5회차 하루 끝 연결 지점.
