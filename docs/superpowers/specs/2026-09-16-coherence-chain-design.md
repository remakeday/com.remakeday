## 1. F2 — 무의미 입력 처리

### 문제
플레이어 입력은 분류 없이 NPC 모델로 간다(`loop_interactor._utter`). "ㅋㅋㅋㅋ", "……", "왜왜왜왜"에도 모델이 문맥을 지어내 답하고, 첫 발화에 동기를 자백하기도 한다(테스터6 1회차 "왜 안어" → 이송 공포 자백).

### 설계
두 단, 모두 모델 호출 전.

**1단 규칙 게이트** (`domain/entities/utterance_rules.py`, 순수 함수)
- 무의미 판정 조건(하나라도): 한글 완성 음절이 0개 / 같은 문자(자모·기호 포함) 3회 이상 연속 반복만으로 구성 / 문장부호·공백만
- "왜?", "응", "뭐" 같은 한 글자 유효 입력은 통과한다(완성 음절 1개 이상, 반복 아님)
- 판정되면 그 인물의 `fallback_lines`에서 한 줄을 골라 반환한다. 모델 호출·기억 학습·신뢰 변화 없음

**2단 분류기** (`use_cases/utterance_classifier.py`, `run_with_harness(role="classifier")`)
- 게이트를 통과한 입력을 `question | request | chat | nonsense` 넷 중 하나로. 프롬프트는 입력 한 줄과 네 라벨 정의만. 기존 Core 모델(gemma4:12b, think off, temperature 0), 출력은 라벨 하나
- `nonsense` → 1단과 같은 처리
- `chat` → NPC 프롬프트에서 `[하루 시작 전부터 아는 것]` 지식 블록을 제외하고 호출. 예산은 쓴다
- `question | request` → 현행 경로
- 분류 실패(하네스 폴백) → 현행 경로(막지 않는다)

**예산**
- 무의미 판정 시 같은 장면(loop, beat) 첫 1회는 예산 면제, 두 번째부터 차감. 카운터는 `loops` 상태에 `nonsense_count_in_beat`
- `UtteranceEvent`에 `classification`, `gated: bool`, `budget_charged: bool`을 남긴다(측정 ①·④용)

### 테스트
- 게이트: "ㅋㅋㅋㅋ", "......", "왜왜왜왜", "ㅠㅠ", "   " → gated / "왜?", "응", "왜 안어", "밥 남겼어?" → 통과
- 분류기: 모의 LLM으로 네 라벨 각 1건, 폴백 1건
- 예산: 같은 비트 1회 면제·2회 차감, 비트 바뀌면 리셋
- 통합: gated 입력에서 `harness_event` 0건, `npc_states` 무변화

## 2. F7 — 신의 질문 답변

### 문제
테스터6 15문답 전부 `unknown`. 답이 (1) 판정 없이 기록을 요약하고 (2) 플레이어가 이미 본 문장을 되돌려주고 (3) 합니다체와 명령체가 섞이고 (4) 면책 문장과 무관한 리드("한 가지 더 —")가 붙는다. 리드 표의 사실 공개는 5.6 이탈이며 무맥락의 근원이다.

### 설계

**답변 형식 (고정 3부, 짧은 한다체)**
```
[판정]  맞다 | 아니다 | 그건 알 수 없다   (3종 — 아래 축소 사유 참조)
[근거]  한 문장. 되돌려주기가 아니라 기록 둘을 잇는 관계 또는 질문이 놓친 사실 하나
[조언]  "네 기록의 「{닻}」. 내일 {인물}에게 {질문}을 물어봐라." 또는 "…{행동}을 걸어 봐라." (없으면 생략)
```
판정은 3종으로 축소 — "그런 일은 없었다"는 기록 부재와 미발생을 혼동시킨다는 테스터1 소견(docs/review-verification/2026-09-09-first-play/tester1-findings.md)에 따라 제외.
- "왜" 질문(이유·의도·정체)은 판정 대신 첫 문장을 "왜인지는 내가 말할 수 없다. 그 전에 일어난 일은 말할 수 있다."로 고정하고 근거 부분에서 **사건**을 답한다. `unresolved_question` 판정을 재사용
- "확인했다"류 단정은 근거 ID가 있을 때만. 없으면 "네 기록에는 없다"로 재작성(하네스 `grounding`에 검사 추가)
- 면책 문장("이 기록만으로 확인되지 않았다"), "한 가지 더 —" 제거. `AdvisorLeadDTO.text`(사실 문장)는 답변에 싣지 않는다

**조언 생성 (세계 구조 기반, 진실 무관)**
- 후보 = 잠재 행동(dormant scene_actions) + 인물 지식(KnowledgeDTO)의 존재. 둘 다 시나리오 구조이며 hidden_truth가 아니다
- 닻 = 플레이어 공개 관찰 중 후보와 같은 actor 또는 cue 단어를 공유하는 관찰. 닻이 없으면 조언 없음
- 행동 = 인물 지식이면 "{인물}에게 {지식 주제}를 물어봐라", 잠재 행동이면 "{인물}: {행동} 규칙을 걸어 봐라"
- `AdvisorLeadDTO`는 `text`를 제거하고 `anchor_cues`, `target`, `ask`(또는 `rule_action`)로 재정의. 회차 게이트(`loop_n`)는 유지. 쟁반 행방(ration-truck direction)은 삭제
- 리드는 한 판에 한 번(현행 `advisor-lead-*` 노트 키 유지)

**질문 유도 UI**
- 질문 입력 위 한 줄: "이 목소리는 오늘 일어난 일만 안다. 무엇을 했는지 물어라." 답 네 형식을 칩으로 표시
- "맞다"로 판정된 사실은 노트에 `confirmed` 종류로 저장(현행 `confirmed_note_id` 경로가 실제로 동작하는지 통합 테스트로 확인)

**말투**
- 프롬프트에 "짧은 한다체. 합니다체 금지. 한 답변 3문장 이내"를 넣고 하네스에 `합니다|습니다` 검사 추가

### 테스트
- 사실 질문("채연이 오늘 배급을 남겼어?") → 판정 `맞다`, 노트 confirmed 1건
- 없던 일("준이 방송실에 갔어?") → `아니다.`(기록과 모순) 또는 `그건 알 수 없다.`(기록 없음)
- 왜 질문 → 첫 문장 고정, 근거에 사건, 판정 없음
- 근거 없는 "확인했다" 생성 → 재생성 유도(모의 LLM)
- 조언: 닻 없으면 생략 / 닻 있으면 고정형 / 리드 text가 답변에 없음
- 합니다체 출력 → 재생성

## 3. F11 — 원숭이손

### 문제
소원이 "설명 강제" 1종, 대가는 발화 예산 -1(세계 무변화), 관리자 생성기 `make_paw` 미연결. 부작용 칸에 쓸 사건이 생기지 않아 테스터6 부작용 0점.

### 설계 (기획서 5.7 구현)

**출현**
- 1회차 2비트 무조건 1회(현행). 2회차 이후: 전날 밤 총점 **40% 이상**이면 그날 1회(기획서 값, 사용자 확정 2026-09-16). 판당 최대 2
- 거절은 무비용. 같은 판 2회 연속 거절 시 더 나오지 않는다
- A/B `shown_reason` 표시는 현행 유지

**소원 표 (시나리오 작성, `scenario_a/adapter.py`에 `paw_wishes`)**

| 키 | 소원(규칙) | 소원의 세계 서술 | 숨은 부작용 분기(같은 날 뒤 비트) | 부작용 관찰 문장 |
|---|---|---|---|---|
| skip-checkup | 검진은 채연을 보지 않는다 (suppress 채연:검진을 받는다) | 4비트: 담당자가 채연 침상을 지나친다 | 5비트: 저녁 쟁반이 셋에서 넷으로, 은상이 담요를 두른다 | "저녁에 은상도 담요를 벗지 않는다. 쟁반 넷이 남았다." |
| mute-eunsang | 은상은 오늘 말을 하지 않는다 (suppress 은상:소문을 낸다 + 발화 침묵) | 2비트: 은상이 구석에 앉아 입을 열지 않는다 | 5비트: 민석이 방송실로 간다(강제), 서술에 "은상이 이상하다고" | "민석이 은상 얘기를 하러 방송실 문 앞에 갔다." |
| deaf-minseok | 민석은 오늘 방송을 듣지 못한다 | 1비트: 민석이 방송 중 다른 곳을 본다 | 3비트: 민석이 기록하지 않고 채연에게 묻는다(잠재 행동 "묻는다") | "민석이 수첩 대신 채연에게 무엇을 남겼는지 물었다." |
| sleep-jun | 준은 오늘 하루 종일 잔다 (준의 모든 장면 행동 suppress + 발화 침묵) | 2비트: 준이 담요를 뒤집어쓰고 있다 | 5비트: 은상의 소문에서 출처가 사라진다(known_source 없음) | "은상이 누구에게 들었는지 말하지 못한다." |

- 각 행의 서술·대사·삽화는 **시나리오 디렉터가 확정**한다. 위는 기획서 5.7 표를 분기로 옮긴 초안이다
- 부작용 분기는 기존 장면 행동 분기(평소·억제·잠재)로 표현한다. 새 엔진 개념은 "규칙이 걸렸을 때만 나오는 대사"와 "발화 침묵" 둘뿐

**이미지 (소원별 낮 삽화 — 부작용은 체감이 조건이므로 그림이 있어야 한다)**

낮 화면은 장면 행동마다 삽화를 띄운다. 소원 서술·부작용 분기에 삽화가 없으면 그날만 그림이 비어 "바뀌었다"가 아니라 "빠졌다"로 읽힌다. 소원 1종당 소원 장면 1장 + 부작용 흔적 1장. 비율 3:2(비트 삽화 관례), 규칙은 이미지제작서 v1 상속, 별도 부록 Q로 프롬프트를 쓴다.

| 소원 | 소원 장면 삽화 | 부작용 흔적 삽화 | 제작 |
|---|---|---|---|
| skip-checkup | 담당자가 채연 침상을 지나친다 — **clue-02 재사용**(채연 검진 반응) | 저녁 쟁반 넷, 담요 두른 등 둘 — **clue-03 재사용** 검토, 안 맞으면 신규 Q02 | 재사용 1~2 |
| mute-eunsang | 은상이 구석 침상에 등을 돌리고 앉아 있다 (Q03) | 민석이 방송실 문 앞, 은상 쪽 침상이 프레임 가장자리에 (Q04) | 신규 2 |
| deaf-minseok | 방송 중 스피커 불이 켜졌는데 민석의 등이 반대쪽을 향한다 (Q05) | 수첩이 덮인 채 놓여 있고 채연 침상 쪽으로 몸이 기운다 (Q06) | 신규 2 |
| sleep-jun | 준의 침상, 담요가 머리까지 덮여 있다 (Q07) | 은상이 혼자 앉아 있고 옆자리가 비어 있다 (Q08) | 신규 2 |

- 규칙: 얼굴·손 없음(등·담요·물건으로), 주황은 deaf-minseok의 스피커 불 하나뿐
- 쿠키 N10~N12(부작용 일반형)는 클리어 화면용이라 낮 삽화로 쓰지 않는다
- 원숭이손 제안 팝업(G01)은 현행 유지
- 삽화 ID는 시나리오 `paw_wishes`의 각 분기 `illustrations`에 지정한다(장면 행동과 같은 방식). 그림이 나오기 전에는 삽화 없이 서술만으로 흐름을 검증한다

**대사 변경**
- `SceneDialogueDTO`에 `required_rules: list[str]`(소원 키) 추가. 걸린 날만 재생. 소원별 2~3줄(예: 준 "은상아, 왜 말 안 해?" / 은상 "……" / 민석 "이상하네. 알려야 하나.")
- 발화 침묵: 규칙 `effect="silence"`. `_utter`에서 대상 인물이면 모델 호출 없이 서술 한 줄("은상은 입을 다문 채 고개를 젓는다")을 반환하고 예산은 쓴다(말을 건 것이다). 하네스 검사가 아니라 경로 분기로 처리해 확실히 한다

**선택 (관리자 층)**
- 1회차: 표에서 무작위가 아니라 고정(`skip-checkup`, 가장 무해해 보이고 부작용이 가장 뚜렷)
- 2회차 이후: 전날 밤 `cell_scores`에서 가장 낮은 칸을 읽어 그 칸을 겨냥한 소원을 고른다. 정체 0 → `sleep-jun`(정보원 소실이 정체 단서를 끊는다), 동기 0 → `skip-checkup`, 원인 0 → `mute-eunsang`. 규칙 선택은 코드, 제안 문구만 `make_paw`가 쓴다(연결). 모델 실패 시 표의 기본 문구
- 규칙 저장은 현행 `rules`(source=monkey_paw, hidden_side_effect=부작용 관찰 문장). 판 단위 지속

**채점**
- 부작용 칸 주장은 규칙 로그에서 자동 생성(7.3 현행): "{소원}을 받은 날 {부작용 관찰 문장}". 플레이어 서술이 이를 확인하면 열린다
- 현행 발화 예산 감소 대가(`scene_execution` paw-cost)는 제거

### 테스트
- 소원별: 걸린 날 소원 서술·부작용 서술·조건부 대사가 나오고, 안 걸린 날은 없음
- 침묵: 대상에게 발화 시 모델 호출 0, 예산 -1, 서술 반환
- 출현: 1회차 무조건 / 40% 미만 미출현 / 2회 연속 거절 후 미출현 / 판당 2 상한
- 겨냥: cell_scores 최저 칸 → 대응 소원
- 채점: 부작용 주장이 규칙 로그에서 생성되고, 부작용 문장을 쓴 답안에서 side_effect 셀 > 0
- 회고: "설계된 대가"에 부작용 관찰 문장 표시(현행 유지)
