로드맵 1번·2번 자유발화 채점 개선과 기존 단서 이미지 연결 뒤 진행한 테스터1의 5회차 플레이에서 최종48%(DB47.9점)와 기능 간 맥락 단절을 확인했다. 그 피드백을 바탕으로 **관찰→노트→질문·규칙→다음 장면→밤 답안→회고**를 연결하는 개편과 승인된 이미지 A안을 구현했다. Gemini 호출은 process-wide 10 RPM pacing을 적용하며 Flash Lite는 선택하지 않은 대안이다. 최종 Ollama 통제의 SPC2 오답 이력은 그대로 보존하고, Gemini full corpus 의미 결과는 별도 검증이다. BGM과 음성 대사는 사용자 요청으로 이번 작업에서 제외했다.

## 다음 할 일 — 테스터 2번 시작 예정

**테스터 2번 시작 예정. 이 PC에서는 문서 정리만 마친다.** 사용자가 이 파일을 다른 PC의 에이전트에게 전달하고 **“테스터 2 시작”**이라고 지시하면 그곳에서 준비를 재개한다. 아직 실제 사람 플레이는 시작하지 않았고 새 attempt_id·시작 시각·회차 점수는 미수집이다.

다른 PC의 에이전트는 먼저 실제 접속할 게임 URL과 그 URL에 연결된 backend health를 확인한다. 다른 PC가 서버를 호스팅한다고 가정하지 않으며, 이 PC의 `http://localhost:3500/play` 확인 결과를 다른 PC의 접속 성공으로 간주하지 않는다. 확인된 URL에서 사용자가 **새 게임**을 시작할 때 새 attempt_id와 시작 시각을 기록하고 5회차 플레이를 진행한다. 완료 뒤 “테스터2 완료”라고 알려 주면 해당 판의 로그를 읽기 전용으로 대조한다. 테스터1 판과 DB47.9점은 그대로 보존하며 재채점·DB reset·운영 기록 수정은 하지 않는다.

플레이 중에는 정답을 알려 주지 않고 다음 흐름이 자연스럽게 이어지는지만 본다.

- 장면과 대화에서 얻은 정보가 출처가 있는 낮 노트로 이어지는지
- 신에게 한 질문과 답의 원문 근거가 도움이 되는지, 모르는 사실을 아는 것처럼 답하지 않는지
- 추천 규칙과 직접 쓴 규칙의 원문·해석·한계·대안이 이해되는지
- 직전 밤에 최종 편집한 답과 고른 근거가 다음 회차 초안에 이어져 수정하기 쉬운지
- 고정 초상, 사건 그림, 밤의 본 장면 갤러리가 실제 플레이 맥락과 맞는지
- 원숭이손의 이득·대가, 실제 규칙 실행, 최종 결말·개발 회고·지표가 서로 모순되지 않는지
- 관리자/인스펙터에는 사용자 화면보다 자세한 근거·모델 검사 기록이 남되 사용자 추리를 방해하지 않는지

알려진 결함도 함께 관찰한다. 실제 모델은 명시된 반대 사실을 잘못 지지하거나, 이유·조건에 대한 관련 기록을 근거로 질문 자체가 확인된 것처럼 답할 수 있다. 출처 누락이나 부정 질문 오답이 보이면 질문 원문과 화면 답을 그대로 남긴다. 최종50%·집중70% 목표와 기능·이미지의 체감 개선은 아직 사람 검증을 통과하지 않았다.

[테스터2 준비 기록](review-verification/2026-09-09-second-play/tester2.md)의 attempt_id·시각·회차 점수는 실제 플레이 전까지 비워 둔다. 자동·기술 점검 판은 테스터2 사람 표본에 포함하지 않는다.

## 확정한 방향

- 게임의 목적은 멸망을 막는 것이 아니라 **왜 멸망했는지 이해하는 것**이다.
- 이해도 점수는 **상황 70점(원인35 + 동기35), 정체30점**으로 구성한다. 이 비중은 초기값이다.
- 정체 추론은 우리가 사람과 다른 종이거나 동물·돼지라는 점을 알아내는 것이다.
- 원숭이손(코드 변경의 부작용)과 신의개입(규칙 설계·하네스 엔지니어링)은 답안 정답 요건에서 제외한다.
- **점수와 관계없이 5회차까지 진행하고, 5회차 제출 완료 후에는 0%여도 개발 회고를 공개한다.** 1~4회차에는 100%여도 회고가 열리지 않는다.
- 게임 중에는 이야기와 추리에 집중하고, 마지막에 이야기 결말 → 개발 의미와 플레이 기록 순서로 보여준다.
- 첫 플레이 5회차 완료 시 약50%, 집중하면 약70%에 도달할 수 있는 단서·채점 구조가 목표다. 실제 달성 여부는 아직 검증하지 않았다.

## 구현한 작업 — 연결형 추리와 승인 이미지 A안 (2026-09-09)

- 공개 관찰에 판·회차·비트·장면·행위자·출처·관찰/전언 상태를 붙이고, 낮 노트와 원본 장면, 질문 근거, 실제 규칙 결과, 회고를 같은 observation ID로 연결했다.
- 직전 밤의 최종 편집 답안과 선택 근거를 다음 밤의 수정 가능한 초안으로 복원한다. 이전 근거와 이번 회차의 새 근거를 구분하며, 새 판에는 답안을 넘기지 않는다.
- 신의 답변은 공개된 원본 기록의 ID와 정확한 본문을 서버에서 복원한다. 질문 명제에 대한 지지·반증·미확인을 구분하고, 공개되지 않은 사실이나 모델 문장을 확정 노트로 승격하지 않는다.
- 추천 규칙은 현재 근거·가설·실제 행동 기회에 연결된 경우만 제시한다. 직접 규칙은 원문, 실행 의미, 한계·대안, 충돌을 미리 보여 주며 같은 원문과 preview ID를 명시적으로 확인해야 적용된다. 테스터1의 직접 입력3건은 자동 치환 없이 지원 불가와 같은 대상의 실행 가능한 대안을 보여 준다.
- 규칙 등록과 실제 실행을 분리했다. 다음 장면의 기회·행동·충돌·결과와 원숭이손의 이득·발화 여유 대가를 연결된 사건으로 기록하고, 회고에는 의도→해석→기회→행동→검사·수정→결과를 표시한다. 사람 검토가 없는 의미 지표는 N/A다.
- 승인한 A안에 따라 대화 상대는 상태별 교체 대신 **E01/E04/E07/E10 고정 초상**을 사용한다. 사건 그림 `clue-07`…`clue-12`는 실제 등장인물·행동·회차·비트 조건에서만 공개한다. 밤에는 플레이어가 실제로 본 그림만 회차·장면·관찰 내용과 함께 갤러리에서 다시 열고 비교할 수 있다.
- 상세 설계는 [연결형 추리 설계](superpowers/specs/2026-09-09-connected-investigation-design.md), 구현·검증 경계는 [통합 보고](review-verification/2026-09-09-connected-implementation/integration-report.md)를 참조한다.

## RM1이 최종 통제를 통과하지 못할 때 결정할 범위

아래 두 안은 다음 구현이 아니라 사용자가 검토할 제품 선택지다. 지금까지의 `supported`/`contradicted` gate와 실패 raw는 어느 안에서도 지우지 않는다.

1. **진위 판정을 유지한다.** 사용자가 core 기본 모델로 Gemini 3 Flash를 선택했다. 실제 adapter 연결은 확인됐고 동일 corpus 의미 검증이 남았다. health의 `embedding: gemini`는 기존 임베딩 제공자이며 새 `core: gemini:gemini-3-flash-preview`와 역할이 다르다. Gemini 3.1 Pro는 연결 비교만 했고 Flash Lite는 선택하지 않은 대안이다.
2. **현재 local 모델을 유지하고 답변 계약을 바꾼다.** 진위를 단정하는 대신 출처 원문, 확인된 정보, 확인되지 않은 정보, 다음에 관찰할 장면을 중심으로 답한다. 예를 들어 PC3에는 `결과는 공개되지 않았다`라는 실제 기록을 찾아 회차·장면·원문을 보여주고, 사용자가 공개 여부를 확인할 수 있게 한다. 기존 진위 gate를 폐기하지 않고 실패 이력으로 보존하며, 새 수용 기준은 별도 설계와 사용자 승인을 받아야 한다.
