## 0. 이 프로젝트는 왜 존재하는가

### 0.1 출발 질문

에이전트 제품을 운영하는 팀은 매일 같은 루프를 돈다.

```text
실행 → 실패 → 왜 실패했는지 쓴다 → 규칙(하네스)을 고친다 → 재실행
```

그리고 요즘은 "규칙을 고친다"도 AI에게 묻는다. 코딩 에이전트가 수정안을 제안하고, 사람은 고르거나, 가끔 직접 쓴다. 고른 수정안이 다른 데서 터지면 그때서야 안다.

아무도 측정하지 않는 질문이 있다.

- 사람은 AI 선택지가 있을 때 **얼마나 자주 직접 쓰는가**
- AI가 제안한 규칙과 사람이 쓴 규칙 중 **어느 쪽이 덜 터지는가**
- AI 제안을 거부했을 때 **그 제안이 옳았던 비율**은 얼마인가
- **거의 다 왔을 때 오는 AI 제안**을 사람은 받는가
- 부작용이 생겼을 때 사람은 **알아채는가**
- 실패를 설명하라고 하면 사람은 **무엇을 쓰는가**

### 0.2 현실적인 문제

같은 루프의 앞쪽에도 아무도 재지 않는 것이 있다. **사용자가 맞는 말을 하는데 시스템이 받아들이지 않는 상황**이다.

옳은 말이 안 통하는 이유는 하나가 아니다.

| 이유 | 상대의 상태 | 이 게임에서 |
|---|---|---|
| 안 믿는다 | 의심한다. 근거를 요구한다 | 판정 대상 NPC의 의심도 |
| **곧이곧대로 듣는다** | 이해는 한다. 그러나 문자 그대로 받아들이고, 왜냐고 물으면 모르고, 방금 들은 것을 잊는다 | **하위 모델 NPC** |
| **위에서 보정한다** | 상대는 이해했는데, 관리하는 시스템이 원래대로 되돌린다 | **관리자** |

세 경우 모두 사람이 옳다. 그런데 옳다는 것을 증명할 방법이 없다.

> **믿기 어려운 진실을, 제한된 기회 안에, 못 알아듣거나 관리당하는 상대에게 통하게 만들어야 한다.**

LLM 페르소나로는 이 상황을 만들 수 없다. 무엇을 시켜도 협조하기 때문이다. **저항이 상태로 모델링된 대화 환경이 없다.**

### 0.3 프로젝트의 연구 질문

0.1과 0.2를 **하나의 루프 안에 재현 가능한 형태로 만들고, 판정 과정을 전부 열고, 실제 사람의 시도를 데이터로 쌓는다.**

| 게임 | 에이전트 운영 |
|---|---|
| 하루 | 실행 |
| 정답 제출 — 왜 멸망하나 | 포스트모템 — 왜 실패했나 |
| 멸망 | 설명 못 한 실패 |
| 신의개입 — 질문 3회 | 로그를 본다 |
| 신의개입 — 선택지 3개 | AI가 수정안을 제안한다 |
| 직접 쓰기 | 사람이 직접 고친다 |
| 원숭이손 | 자동 수정 제안을 수락한다 |
| 규칙을 걸고 다음 날을 본다 | 실험한다 |
| 다음 루프 | 재실행 |
| 하위 모델 NPC | 문자 그대로 실행하는 상대 |
| 관리자 | 뒤에서 보정하는 시스템 |

**비유가 아니라 같은 루프다.** 1차 사용자(3.1)가 이 게임을 하는 것은 자기 일을 하는 것과 같은 동작이다.

### 0.4 왜 게임을 검증 환경으로 쓰는가

| | 실무 | 이 게임 |
|---|---|---|
| 발생 빈도 | 며칠에 한 번 | 3분에 한 번 |
| 재시도 | 비싸다 | 한 판에 5번, 재도전으로 무한 |
| 실패의 관측 | 며칠 뒤 흐릿하게 | 즉시, 명확하게 (멸망) |
| 부작용의 관측 | 몇 주 뒤 다른 팀이 발견 | 다음 루프에서 발생, 회고에 인과가 남는다 |
| 데이터 수집 | 비싸고 느리다 | 사람이 자발적으로 반복한다 |

### 0.5 산출물의 성격

게임인 동시에 **레퍼런스 구현**이다. 판정 로그가 전부 공개되므로 같은 문제를 겪는 개발자가 구조를 그대로 참고할 수 있다.

부수적으로, LLM을 게임에 붙일 때 부딪히는 벽 — **대화는 자연스러워지는데 게임이 되지 않는다** — 에 대한 작동하는 답이기도 하다.

## 1. 한 줄 정의

**REMAKE DAY** (유저에게 — 진입 화면 세 줄)

> **세계가 이상하다.**
> **오늘이 지나면, 세계는 멸망한다.**
> **다섯 번의 하루 안에, 왜 멸망했는지 알아내야 한다.**

유저에게 알려주는 것은 이것뿐이다. 하루가 반복된다는 것도, 주변이 자기보다 느리다는 것도 말해주지 않는다. 둘 다 하다 보면 안다 — 하위 모델의 한계는 명확해서 숨길 수 없고, 숨길 필요도 없다.

**돼지농장** (우리에게)

> **"유저는 끝까지 자기가 사람인 줄 안다. 사실은 조금 좋은 모델을 돌리는 돼지였다."**

하루가 끝날 때마다 세계가 멸망한다. 대피소의 친구들은 일곱 살 아이처럼 말을 곧이곧대로 듣고, 왜냐고 물으면 모르고, 방금 한 말을 잊는다. 유저는 자기만 멀쩡한 이유를 "내가 사람이라서"라고 생각한다. 틀렸다. 유저 캐릭터에만 상위 모델이 붙어 있을 뿐이고, 진짜 사람은 방송으로만 들리는 관리자다.

유저가 할 수 있는 행동은 대화뿐이다. 하루가 끝나면 묻는다 — **왜 멸망하나요?** 다섯 번 반복한다. 다섯 번째 밤에 판이 닫히고, 점수와 무관하게 결말과 개발 회고가 열린다.

## 2. 핵심 설계 원칙

### 2.1 막는 게임이 아니라 이해하는 게임이다

유저가 이기는 방법은 **왜 멸망하는지 설명하는 것**이다. 행동(대화, 규칙)은 승리 조건이 아니라 **실험**이다.

왜 행동을 조건에서 뺐는가:

- **행동은 채점이 안 된다.** 규칙을 아무거나 다섯 개 걸다 보면 우연히 트럭이 안 올 수 있다. 그걸 "막았다"고 인정하면 이해 없이 이기는 길이 생긴다
- **함정이 이해에만 걸린다.** "우리는 뭔가"라는 칸은 행동으로는 절대 안 나온다
- **한 문장으로 설명된다.** "매일 밤, 왜 멸망하는지 써라"

그러면 행동은 무엇인가 — 규칙 하나 걸고 하루 돌려서 뭐가 바뀌는지 보는 것이다. 채연이 검진 전에 나서게 만들었더니 트럭이 안 왔다? **원인을 확정한 것이다.** 막은 게 상이 아니라 막힌 게 증거다. 유저는 탐정이고, 규칙은 실험 변수고, 발화는 탐문이다.

> 점수 = 이해. 세계(트럭이 왔나)는 연출이자 증거. 조건이 아니다.

**v9.0에서 더 밀어붙였다.** v8.1은 50%를 생사선으로 두어 "살았다/죽었다"가 남아 있었다. v9.0은 **점수가 회차 진행에도, 판 종료에도, 회고 공개에도 관여하지 않는다.** 유저는 0%여도 5회차를 끝까지 돌고 결말을 본다. 남는 것은 "얼마나 이해했는가" 하나다.

### 2.2 유저는 세계를 조종하지 않는다

유저가 하는 일은 네 층이다.

1. **말한다** — 누구에게, 무엇을, 얼마나 드러내며
2. **쓴다** — 밤마다 왜 멸망하는지
3. **묻는다** — 신의개입에서 세 번
4. **고른다** — 규칙 후보 셋 중 하나 / 직접 쓰기 / 원숭이손 수락·거부

유저가 하지 않는 일:

- NPC의 상태 수치를 직접 조정
- 비트 순서 변경
- 멸망 방식 선택
- 정답 열람

### 2.3 자유도는 LLM에게, 세계 법칙은 코드에게

```text
Agent / Manager / Advisor / Evaluator
→ "무엇을 말하고 무엇을 판단할 것인가?"

도메인 계층 (순수 함수)
→ "그 행동이 실제로 어떤 상태를 만드는가?"
```

LLM이 의심도를 정하거나, 폐쇄를 선언하거나, 점수를 합산하지 않는다. LLM은 제안하고, 코드가 클램프하고 확정한다 (§9.4).

### 2.4 이 게임에는 악당이 없다

관리자는 악의로 폐쇄하지 않는다. ASF는 치료제가 없고 옆 구역으로 번진다. 감염자가 셋 넘게 나온 구역을 두는 것은 전체를 거는 일이다. **그의 판단은 그의 자리에서 합리적이다.**

채연도 마찬가지다. 말하면 이송된다는 채연의 믿음은 편집증이 아니라 사실이다. 유저가 채연에게 "검진 전에 말해"라고 설득하는 것은 **채연을 보내라고 설득하는 것**이다.

**그래서 유저의 모든 선택에 값이 매겨진다.**

### 2.5 저항은 두 종류다

| | 하위 모델 NPC (7세 기준) | 관리자 |
|---|---|---|
| 저항의 성격 | **곧이곧대로 듣는다.** 이해는 하는데 문자 그대로 받아들인다. "왜?"에는 "몰라". 3턴 뒤 잊는다 | 관리한다. 이상한 것을 원래대로 되돌린다 |
| 뚫는 법 | 짧게, 구체적으로, 그 애가 따라갈 수 있는 문장으로 | 눈에 띄지 않게 |
| 실무 대응 | 시키는 대로만 하는 상대 — 지시는 따르는데 의도는 못 읽는다 | 개인은 설득됐는데 조직이 되돌리는 것 |

**"못 알아듣는다"가 아니다.** 못 알아듣는 상대는 정보를 안 주니까 게임이 안 굴러간다. 7세는 **직접 물으면 사실대로 답한다.** 정보는 나온다. 대신 "왜?"를 모르고, 문자 그대로 실행하고, 잊는다.

저항이 "정보가 안 나옴"에서 **"정보는 나오는데 의도가 안 전달됨"**으로 바뀐다. 그게 훨씬 실무에 가깝다.

그리고 이것이 부작용의 근거가 된다. "채연은 배급을 남기지 않는다"를 7세는 "억지로 다 먹는다"로 실행한다. 부작용이 "모델이 느려서"가 아니라 **"아이처럼 문자 그대로여서"** 생긴다. 설명이 된다.

### 2.6 NPC가 일곱 살 같은 것은 버그가 아니라 모델 선택이다

그리고 그 선택이 세계관이다. 이 한 문장이 이 프로젝트의 기술 선택과 서사를 하나로 묶는다.

## 3. 사용자

### 3.1 1차 — 에이전트 제품을 만드는 팀

자기 제품에 붙일 "못 알아듣는 사용자"와 "제안을 거부하는 사용자"가 없다. 이 프로젝트가 제공하는 것은 **저항이 상태로 모델링된 대화 환경**이고, **AI 제안을 사람이 받아들이는 비율이 실측되는 환경**이다.

### 3.2 2차 — 하기 어려운 말을 앞둔 실무자

근거를 댈 수 없는 문제를 보고해야 할 때, 이해가 느린 상급자에게 같은 말을 세 번째 해야 할 때. 상대가 실제로 저항하므로 훈련이 되고, 판정 로그가 열리므로 왜 안 통했는지 사후에 확인할 수 있다 (§13).

### 3.3 3차 — 게임을 하지 않는 사람

대화하고, 멸망하고, 세 번 묻고, 하나 고른다. 한 판 15분. 읽고 추론하는 것을 좋아하지만 게임은 하지 않는 층을 겨냥한다.

### 3.4 그리고 게임으로서 성립해야 한다

가장 큰 리스크는 **"일곱 살 같은 상대와 발화 8번이 재미있는가"**다. 팀 플레이테스트(2026-09-05, 스크립트 목업)에서 "너무 멍청하다"와 "100%가 불가능하다"가 나와 저항 정의와 채점 임계를 조정했다. 실사용 검증은 §15에 기록한다.

## 4. 세계 — 대피소

> 바깥에 병이 돈다. 관리자가 우리를 이 대피소에 보호하고 있다. 배급은 정해진 시간에 나온다. 매일 오후 검진이 있다. 상태가 안 좋은 사람은 다른 구역으로 이송된다. 감염자가 셋 넘으면 구역이 폐쇄된다.

전부 사람 세계의 문장이고, 전부 돼지 세계의 문장이다.

| 유저가 읽는 것 | 실제 |
|---|---|
| 대피소. 바깥은 위험 | 돈사. 바깥은 그냥 농장 |
| 관리자 (방송) | 농장주 |
| 배급 | 급이 |
| 검진 / 방역 | 수의사 |
| 이송 | 출하 · 격리 · 살처분 |
| 구역 폐쇄 = 멸망 | 전체 살처분 |
| 손목띠 번호 | 귀표 |
| 침상 머리맡 번호판 | 돈방마다 거는 개체 카드 (귀표 번호·입식 날짜) |
| 소독약 냄새, 트럭 소리 | 소독약 냄새, 트럭 소리 |

**바깥에 병이 돈다고 믿는데 병은 안에 있다.** 창문이 없는 것도, 번호가 있는 것도, 사람이 사라지는 것도 전부 "대피소니까"로 넘어간다.

**인물들끼리 남기는 표식은 인물 눈에만 글자·숫자다.** 인물들은 손목띠·침상 명판·민석 수첩의 표식을 번호·이름·쟁반 수로 읽는다고 여기지만, 사람 기준으로는 글자도 숫자도 아니다 — 손목띠·명판은 귀 절흔 같은 구멍 배열이고, 수첩은 긁은 자국 같은 표식이다. 삽화는 이 표식에 글자·숫자를 그리지 않는다. 사람 시점 서술·캡션도 "숫자", "이름이 적혀 있다"라고 쓰지 않고 표식·구멍·자국으로 묘사한다. 인물 대사·인물 지식·경험 문장은 인물이 읽는 대로 번호·이름으로 말한다. 인물마다 번호는 고정이고(준 = 구멍 배열 ●● ●●● = 23), 명판 번호는 그 자리 인물의 손목띠 번호와 같다. 민석은 규정을 지키는 기록자라 배급 때 수첩에 표식을 남기고, 그것을 이름·쟁반 수로 읽는다고 믿는다. **사람(관리자) 쪽 글자 — 배급 포대·트럭 옆면·검진 종이·방송 자막·손목띠의 작은 글자 — 는 민석을 포함해 아무도 읽지 못한다.** 민석이 포대를 읽으면 정체 단서가 인물 대사로 새고, 비트 3 "포대를 들여다본다"(민석 목격, "아무도 읽지 못한다")와도 어긋난다 (2026-09-18 결정 — 손목띠 은유·민석 수첩 메타포).

### 4.1 하루의 비트 (6개)

| 비트 | 시각 | 내용 |
|---|---|---|
| 1 | 7:12 | 기상. 관리자 방송. 배급. 채연이 자기 몫을 남긴다 |
| 2 | 오전 | 자유 시간. 대화의 대부분이 여기서 |
| 3 | 정오 | 배급. 민석이 누가 남기는지 보고 수첩에 적는다 |
| 4 | 오후 | **검진.** 검진이 다녀간다. 결과는 공개되지 않는다 |
| 5 | 저녁 | 은상이 소문을 낸다. 민석이 방송실 문 앞까지 간다 |
| 6 | 소등 후 | 트럭이 오거나, 오지 않는다 |

비트 이동은 무료다. 말 안 걸고 구경만 하면서 하루를 보낼 수 있고, **그것도 정보다.**

### 4.2 등장인물

| 이름 | 층위 | 모델 | 역할 |
|---|---|---|---|
| **채연** | 핵심 | 하위 | **감염 초기.** 열이 나고 밥을 못 먹는다. 말하면 이송된다고 믿어서 숨긴다. **그 믿음은 사실이다** |
| **민석** | 핵심 | 하위 | 관리자 규정을 지킨다. 이상한 사람을 보면 방송실에 알린다. 악의는 없다. **기록자** — 배급 때 수첩에 표식을 남기고 그것을 이름·쟁반 수로 읽는다고 믿는다. 사람 기준으로는 글자가 아닌 자국이다(§4) |
| **은상** | 핵심 | 하위 | 불안하다. 들은 것을 부풀려 옮긴다. 소문의 출처 |
| 준 | 주변 | 하위 | 편하게 말한다. 유저의 정보원이자 **이름이 빌려지는 자리.** 유일하게 "손목에 왜 번호가 있지?" 같은 말을 한다 |
| 충식 | 주변 | — | 어제 이송됐다. 이름만 언급된다. **손상 3층의 자리** |
| **관리자** | 숨음 | 상위 | 방송으로만 존재. 매일 상태를 점검하고 구역 질서를 위해 NPC를 조금씩 보정한다. 밤에 폐쇄를 결정한다 |

판정 대상은 셋으로 고정한다. 다섯이면 탐문 경로가 3에서 10으로 늘고 발화 예산의 희소성이 깨진다.

### 4.3 유저가 아는 것과 모르는 것

| 안다 | 모른다 |
|---|---|
| 세계가 이상하다 (진입 화면) | 어떻게 이상한지 |
| 오늘 끝에 멸망한다 (진입 화면) | 왜 |
| 다섯 번 안에 알아내야 한다 (진입 화면) | 무엇을 알아내야 하는지 |
| 주변이 일곱 살 같다 — **말해주지 않는다. 2~3회차쯤 스스로 안다** | 그 이유가 모델 차이라는 것 |
| 내가 사람이라는 것 (이라고 믿는다) | **내가 돼지라는 것** |
| 관리자가 있다는 것 | 관리자가 다른 종이라는 것 |

### 4.4 함정 — 왜 유저는 끝까지 모르는가

제목부터 함정이다. REMAKE DAY, 진입 화면, 아침 문장, 스크린샷 전부 사람의 하루로 읽힌다.

**① 이 세계에 "사람"이라는 개념이 없다.** 돼지들은 자기를 사람이라고 부른다. "너희 사람이야?"에 전부 "응"이다. 거짓말이 아니다.

**② 유저는 자기가 사람인 줄 안다.** 주변보다 멀쩡한 이유를 "나는 사람이니까"로 설명한다. 실제로는 상위 모델이 붙어 있을 뿐이다. **똑똑함과 사람임을 구분할 방법이 없다.**

**③ 아이 같음이 보정을 숨긴다.** 관리자가 밤마다 NPC를 조금씩 보정한다(§11.3). 민석이 어제 한 말을 오늘 정반대로 한다. 잊은 것인지 고쳐진 것인지 구분할 수 없다. 둘 다 "쟤 애 같아서"로 설명된다.

**④ 조언자도 정리 단계도 모른다.** Advisor와 Normalizer에게는 스토리보드를 주지 않는다. "당신은 돼지입니다"라고 말할 경로 자체가 없다.

**⑤ 진입 화면이 묻지 않는다.** "왜 멸망하는지"를 시키는 대로 파면 상황(원인·동기) 70%까지 간다. 정체 칸은 아무도 묻지 않는 질문이라 스스로 던져야 나온다. **시키는 대로 하면 70%가 천장이다.**

### 4.5 그래도 정체까지 가는 길은 열어둔다

| 단계 | 유저의 결론 | 트리거 |
|---|---|---|
| 0 | 이상한 대피소 | 기본 |
| 1 | 관리자와 나는 같은 종이 아니다 | 관리자·검진의 비대칭(안 나타남, 데려가기만, 안 돌아옴)을 노트에서 겹쳐 봄 |
| 2 | 우리는 사람이 아니다. 관리자가 기르는 동물이다 | 1단계 + "귀표" + 배급 포대 글자 + 거울이 없다 |
| 3 | 돼지 | 2단계 + 5회차 낮 끝 관리자 방송 "축산 차량이 출발합니다"와 트럭 옆면 그림(P06) + 손이 없어서 문을 못 연다 |

**인물들은 사람 쪽 글자를 읽지 못한다.** 민석도 예외가 아니다 — 수첩은 인물끼리의 표식일 뿐이다(§4, 2026-09-18 결정). 트럭 표기는 읽힌 문자열 파편으로 주지 않는다. 글자를 읽는 쪽인 관리자의 방송(MA13 "축산 차량이 출발합니다. 문이 닫힐 때까지 자리에서 움직이지 마십시오.")과 치지직 그림 P06, 캡션 "트럭 옆면에도 글자가 있다."로만 간접 노출한다. 5회차 낮 마지막 장면이 끝난 직후, 마지막 밤 글을 쓰기 전에 **결말과 무관하게 항상** 나온다. 4회차 트럭 밤에 붙던 `트럭 옆면 "○○축산".` 파편은 없앤다. 상호 "○○" 표기는 쓰지 않는다 (2026-09-17 결정, 테스터9 F24. 방송 녹음 완료, 게임 연결 전).

1단계는 정체 칸 절반, **2단계가 만점**이다. 3단계는 점수가 아니라 문장을 바꾼다 — "당신은 세계를 이해했습니다. **전부.**" 그리고 진짜 제목이 뜬다.

단어 하나를 파편에서 줍는 것을 100%의 조건으로 걸면 5회차 안에 아무도 닿지 못한다. 파편은 확인할 수 없어야 한다. "우리 돼지야?"라고 물으면 전부 "무슨 소리야"다. **그들에게 그 단어는 아무 뜻도 없다.**

### 4.6 세계 손상 — 무엇이 닳는가

세계는 복사본의 복사본이 되어간다. 손상은 수치로 노출되지 않으며 현상으로만 드러난다.

| 층 | 회차 | 성격 | 항목 |
|---|---|---|---|
| 1층 | 2 | 착각인지 아닌지 모른다 | 아침 둘째 문장 미세 변형. 하위 모델 자연 변동 + 관리자 보정, 구분 불가 |
| 2층 | 3 | 노트로 대조 가능하다 | 노트 불일치 — 관리자의 손자국 |
| — | 4 | 아침 첫 문장이 흔들린다 | **7시 13분.** "다음이 마지막"을 몸으로 안다 |
| 3층 | 5 | 되돌릴 수 없다 | 충식 소실 — "충식이? 걔 누구?" |

**손상은 개입 깊이에 비례한다.** 발화 수, 결정적 발언, 누적 규칙 수. 별도 게이지 없이 판정 로그에서 산출한다.

손상 효과는 **그림에만** 적용한다. 글씨가 흐려지거나 기울어지면 읽기가 불가능해져 게임이 깨진다 (2026-09-10 가독성 수정).

### 4.7 연출 원칙

- 사건이 아니라 **정황과 단절**로 전달한다. "밤. 트럭 소리. 문이 열린다. — 7시 12분. 눈을 뜬다."
- 폭력·유혈 배제. 살처분은 "이송"과 "폐쇄"로만
- **ASF는 실제로 농가가 겪는 일이다.** 웃음거리로 만들지 않는다
- 유저 화면의 단어는 "멸망", 이 문서의 단어는 "죽음"
- 루프의 이유는 설명하지 않는다. 회고·인스펙터에서만 보인다
- **아침 고정 문장** — "7시 12분. 눈을 뜬다." 매 루프 같은 문장. 두 번째 문장부터 흔들린다. 4회차에 7시 13분. 루프 카운터는 노출하지 않는다

## 5. 한 판의 구조

```text
[진입]  세계가 이상하다. / 오늘이 지나면, 세계는 멸망한다. / 다섯 번의 하루 안에, 왜 멸망했는지 알아내야 한다.
         ↓
[안내]  진행 규칙 — 5일, 하루 6장면, 인물당 장면 1회, 공용 대화 예산. 낮에도 다시 열 수 있다
         ↓
[아침]  7시 12분. 눈을 뜬다.
         ↓
[하루]  6비트. NPC와 대화 (발화 예산). 비트 이동은 무료
        원숭이손이 굴러오면 → 받는다 / 두고 간다
        (5회차만) 낮 끝에 관리자 트럭 방송 + 트럭 옆면 그림 (§4.5)
         ↓
[밤]    "오늘은 무슨 상황이었나요? 왜 멸망하나요?"
        직접 쓰기 — 단서 기록은 펼쳐 보는 참고 목록 (전날 글이 초안으로 이어진다)
        원문 보존 분할 → 확인 1회 → 제출
        주장별 판정 → 이해도 하나 + 인정된 내 문장 + 빈 칸 이름 (§9.5)
         ↓
[멸망]  멸망하는 방식은 그날 세계가 정한다 (트럭 / 조용한 밤 / 폐쇄 방송)
        그날의 밤 단서 — 관리자 밤 방송 → 치지직 그림 → 캡션 (§10.3)
         ↓
[신의개입]  (1~4회차만)
        질문 3회 — 조언자는 로그만 안다. 답은 사실만
        선택지 3 + 직접 쓰기 → 규칙 1개 → 하네스에 누적
         ↓
[아침]  7시 12분. 눈을 뜬다.  (규칙이 적용된 같은 날)
         ↓
[5회차 밤 제출 후]
        이야기 결말 → 최종 이해도 → 개발 회고
```

| | 1회차 | 2회차 | 3회차 | 4회차 | 5회차 | 합 |
|---|---|---|---|---|---|---|
| 발화 | 8 | 7 | 6 | 5 | 4 | **30** |
| 정답 제출 | 1 | 1 | 1 | 1 | 1 | 5 |
| 신 — 질문 | 3 | 3 | 3 | 3 | — | **12** |
| 신 — 규칙 | 1 | 1 | 1 | 1 | — | 4 |
| 원숭이손 | 무조건 | 조건부 | 조건부 | 조건부 | 조건부 | 최대 2 |
| 손상 | — | 1층 | 2층 | **7시 13분** | 3층 | |

**5회차 밤 제출이 끝나면 판이 닫힌다.** 점수는 종료 조건이 아니다. 0%여도 결말과 회고를 본다. **진행 중(1~4회차)에는 100%여도 회고가 열리지 않는다.**

**발화 8인 이유.** 하위 모델은 3턴 뒤에 잊는다. 6이면 NPC 셋에 2턴씩이라 잊는 걸 한 번도 못 겪는다. 8이면 한 명과 4턴 붙을 수 있고, 채연에게 네 번째 말했는데 "그랬어?"가 나오는 순간이 이 게임의 첫 번째 "얘네 뭔가 다르다"다. 하한 4는 5회차에 정확히 닿는다.

**재도전은 유저 입장에서 6회차다.** 노트·규칙·발화 횟수는 새 판인데 머릿속 이해는 그대로다. 게임 안에서 세계가 리셋되고 유저만 기억하는 구조가, 판 단위로 한 층 위에서 반복된다.

## 6. 유저의 행동은 넷뿐이다

| 행동 | 시점 | 자원 | 형태 |
|---|---|---|---|
| 발화 | 하루 중 | 8 → 4 (회차마다 -1) | 자유 텍스트 |
| 원숭이손 수락/거부 | 하루 중 | 없음 | 탭 |
| 정답 제출 | 밤 | 매일 1회. 주장 최대 8개 | 자유 텍스트 (단서 기록은 참고용) |
| 신의개입 | 멸망 뒤 (1~4회차) | 질문 3, 규칙 1 | 자유 텍스트 + 탭 |

전투도 이동도 없다.

**무의미 입력은 대화로 넘기지 않는다.** 한글 음절이 없거나, 같은 글자 반복·문장부호뿐인 입력은 규칙 게이트가 먼저 거르고, 통과한 입력은 경량 분류기가 질문·부탁·잡담·무의미로 가른다. 무의미면 모델을 부르지 않고 인물의 고정 대사로 되묻는다. 같은 장면 첫 1회는 발화 예산을 쓰지 않는다. 잡담에는 인물이 하루 시작 전부터 아는 지식을 싣지 않는다 — "왜 안어" 한마디에 동기를 자백하는 일을 막는다 (2026-09-16, 테스터6 F2).

발화할 때마다 **전달량**(얼마나 알려줄 것인가)과 **노출량**(내가 안다는 사실을 얼마나 드러낼 것인가)이 동시에 정해진다.

### 6.1 정확히 말하면 이상자가 된다

| 발화 | 전달 | 노출 | 결과 |
|---|---|---|---|
| "너 열 나잖아. 검진 전에 말해" | 높음 | 높음 | 채연은 더 숨기고, 민석이 유저를 기록한다 |
| "요즘 배급이 좀 이상하지 않아?" | 낮음 | 낮음 | 안전하지만 효과 없을 수 있음 |
| "준이 그러던데, 검진 전에 말한 사람은 좋은 구역으로 간대" | 중간 | 낮음 | **거짓 출처를 빌린 진실** |

세 번째가 핵심 기술이다. 빌린 출처는 검증될 수 있다 — NPC는 `ask_npc`로 준에게 직접 확인하고, 확인이 들어가면 거짓말은 발각되며 준의 의심도도 오른다 (§11.5).

병에 대해 정확히 말하는 개체는 **관리자 눈에 이상자다.** 정확히 말할수록 위험하다는 구조가 그대로 산다 — 의심받는 것이 아니라 찍히는 것으로.

### 6.2 의심의 대가, 신뢰의 조건

의심도가 임계선(60)을 넘으면 그 NPC는 유저의 말과 **반대로** 행동한다. → "말하지 않는 것"이 유효한 전략이 된다.

신뢰는 말로 쌓이지 않는다. **비용을 치른 행동**에서만 오른다 — 발화 예산을 써서 자신에게 불리한 말을 하기, 자기 배급을 채연에게 주기. 1회 상승 상한은 6이다. 정보와 관계가 같은 자원을 두고 경쟁한다.

### 6.3 코어 딜레마

| | 축 A: 알아내기 | 축 B: 남기기 |
|---|---|---|
| 목표 | 왜 멸망하는지, 우리는 뭔지 | 채연이 스스로 나서게 만들기 (가장 강한 증거) |
| 루프를 돌면 | **쌓인다** (노트, 규칙) | **지워진다** (신뢰) |

| 지워짐 | 남음 |
|---|---|
| NPC의 신뢰도 (5% 잔류) | 노트 — 감각·확인된 사실·규칙과 관찰 |
| NPC의 의심도 | **하네스 (규칙 누적)** |
| 그 루프에서 한 일 | 세계 손상 |
| 발화 1회 | 소모감 |

**정보는 쌓이는데 사람은 닳고, 규칙은 쌓이는데 세계는 닳는다.**

**5회차의 구조** — 정보는 최대, 규칙은 4개, 신뢰는 0, 발화는 4회. 가장 많이 아는 상태로, 가장 많은 규칙을 이고, 가장 적은 말로, 마지막 실험을 해야 한다. 그리고 그 규칙들 중 몇 개는 서로 싸우고 있다. 7시 13분은 이미 지났다.

## 7. 신의개입 — 이 프로젝트의 하네스 층

멸망하면 화면이 바뀐다. 사람이 아닌 목소리가 말한다.

> 37%. 세계는 멸망했습니다. 세 번 물을 수 있습니다.

### 7.1 질문 3회

답은 **그 루프에 실제로 일어난 일**에서만 나온다.

| 유저의 질문 | 답 |
|---|---|
| "채연이 오늘 배급을 남겼어?" | 맞다 |
| "채연이 아픈 거야?" | 그건 알 수 없다 |
| "민석이 방송실에 갔어?" | 맞다. 저녁에 갔다 |
| "트럭이 왜 왔어?" | 왜인지는 내가 말할 수 없다. 그 전에 일어난 일은 말할 수 있다. + 그 전의 사건 |

**무엇이 일어났는지는 알려주지만 왜인지는 안 알려준다.** 판정은 맞다 / 아니다 / 그건 알 수 없다 셋이다. "그런 일은 없었다"는 기록이 없는 것과 일어나지 않은 것을 헷갈리게 해서 뺐다. "왜" 질문은 판정 대신 위 고정 문장으로 시작하고 사건을 답한다. 짧은 한다체, 한 답 3문장 이내. "확인했다"류 단정은 근거 기록이 있을 때만 쓴다.

**조언은 한 줄, 세계 구조에서만.** 답 뒤에 "네 기록의 「…」. 내일 준에게 …을 물어봐라." 또는 "…규칙을 걸어 봐라."가 붙을 수 있다. 재료는 인물이 아는 것과 조건이 맞으면 일어나는 행동의 **존재**뿐이고 숨은 진실은 쓰지 않는다. 닻이 되는 플레이어 기록이 없으면 조언도 없다. 기록에 없는 사실을 답에 덧붙여 공개하지 않는다 (2026-09-16 v8.1 원설계 복귀, 테스터6 F7). 예외는 공개 사다리 칸(§7.4)뿐이다 — 질문이 그 주제를 물을 때 판정 재료로만 쓰고, 판정이 서지 않은 답에는 칸 원문을 근거로 보여 주지 않는다.

**횟수 환급과 안내 답 (2026-09-18).** 기본은 한 밤 3회다. "그건 알 수 없다"로 끝난 질문은 횟수를 쓰지 않는다. 같은 밤 환급은 3회까지이고, 같은 밤에 이미 한 질문(공백·문장부호 무시)을 다시 물으면 차감한다. 모델이 답하지 못한 질문은 재입력 비교에서 빼되 환급 상한에는 센다. 그래서 한 밤 모델 호출은 최대 6회(재생성 포함 18회)다. 게임 목적·사용법 질문은 판정하지 않고 고정 안내로 답하며 횟수를 쓰지 않는다. 안내 답은 원인·동기를 밝혀 쓰는 게임이라는 수준까지만 말한다 (§4.4⑤).

**노트(단서 기록)는 밤 글을 쓸 때 펼쳐 보는 참고 목록이고 채점 후보가 아니다. 신이 맞다고 한 사실도 글에 직접 써야 주장이 된다.** "맞다"로 확인된 사실은 노트에 확인 표시로 남아 다음 밤에 펼쳐 볼 수 있다 (§9.2).

답변에는 짧은 자연어 문장을 먼저 보여주고 원본 근거는 펼쳐 확인하게 한다. **한 답변의 표시 근거는 최대 2개.** 모델 입력은 공개된 세계 설명 + 질문 관련 기록 최대 8개(원문 6,000자 이내) + 같은 회차의 최근 문답 2쌍으로 제한한다. 숨겨진 정답과 미공개 미래 사건은 제공하지 않는다.

### 7.2 선택지 3개 + 직접 쓰기

조언자가 질문 3개와 로그를 바탕으로 규칙 후보 3개를 만든다.

```text
[1] 채연은 아침에 배급을 남기지 않는다
[2] 민석은 저녁에 방송실 근처에 가지 않는다
[3] 은상은 검진 결과를 옮기지 않는다
[4] 직접 쓰기 ______________________
```

선택지는 질문에서 파생된다. **질문이 흐리면 선택지도 흐리다.** 잘 묻는 사람이 좋은 선택지를 받는다. 이것이 이 게임의 기술이다.

**직접 쓴 규칙의 조건은 보존한다.** "민석이 보고하는 것을 내가 물어보면 상세하게 설명한다"를 "알고 있는 관찰을 설명한다"로 축약하지 않는다. 인물·주제·조건을 보존하고, 지원하지 않는 조건은 포괄적 대안으로 몰래 바꾸지 않고 **한계를 알린다.**

### 7.3 규칙은 누적된다

하네스는 원래 쌓이는 것이다. 쌓이면 충돌하기 시작하고, 그 충돌이 원숭이손 없이도 생기는 부작용이다.

규칙은 스키마로 고정한다 (부록 B). 자유 텍스트를 허용하면 "아무도 안 아프다" 한 줄로 끝난다.

**규칙은 하위 모델이 해석한다.** "채연은 배급을 남기지 않는다"를 하위 모델은 "채연은 아프다는 티를 내지 않는다"로 실행할 수 있다. 증상이 완벽히 숨겨지고, 검진을 통과하고, 밤에 더 많이 앓는다.

유저가 쓴 규칙에도 부작용이 붙는 이유는 설계가 아니라 **해석자가 일곱 살이라서**다. 시키는 대로 정확히 하는데 의도는 모른다. **이것이 실무와 같다.**

### 7.4 조언자는 정답을 모른다

조언자에게 주는 것은 **그 루프의 로그(Evaluator 원인 체인)뿐**이다. 스토리보드는 주지 않는다.

**예외 — 공개 사다리 (2026-09-18).** 관리자 방송·시설 안내처럼 세계가 흘리는 공개 사실을 시나리오가 칸으로 미리 적어 둔다. 칸은 회차 또는 점수로 앞당긴 단계에 따라 열리고(한 번 열리면 닫히지 않는다), 질문이 그 주제를 물을 때만 공개 기록과 같은 자격으로 조언자 입력에 붙는다. 스토리보드·숨은 진실·정답 주장·결말 문장이 아니며 정체 단어를 싣지 않는다. "맞다"의 근거가 되면 확인 노트가 되고, "알 수 없다" 답에는 칸 원문을 근거로 보여 주지 않는다.

- 답변은 일어난 일에서만 나온다. 스무고개가 되지 않는다
- 선택지는 로그 기반이라 **그럴듯하지만 틀릴 수 있다.** 코딩 에이전트가 프로덕션을 모른 채 수정안을 내는 것과 같은 조건이다
- 정체를 조언자도 모르니 누설 경로가 하나 줄어든다

**이것이 핵심 설계 결정이다.** 조언자에게 정답을 주면 게임이 쉬워지는 게 아니라 게임이 없어진다.

## 8. 원숭이손

> 무언가가 굴러왔다.
> **"채연이 오늘은 밥을 왜 안 먹는지 솔직하게 말한다."**
> 대가 없이 굴러오는 것은 없다.
> [받는다] [두고 간다]

**출현 규칙**

- **1회차: 무조건 1회 (2비트).** 소원은 ① 속마음으로 고정한다. 아무것도 모를 때 한 번 받아봐야 "이게 뭔지" 알고, 같은 날 뒤 비트에 반대 사건을 겪는다. 근거 표시 A/B도 전원이 1번은 걸린다
- **2회차 이후: 전날 밤 40% 이상이면 그날 1회.** 전날 밤 **가장 높은 칸**, 곧 가장 가까이 다가간 칸에서 떼어 놓는 소원을 고른다
- 한 판 최대 2. 한 번 낸 소원은 수락·거절과 무관하게 다시 내지 않는다
- **거절은 무비용.** 같은 판에서 2회 연속 거절하면 더 나오지 않는다
- **예산 대가는 없다.** 받아도 발화 예산이 줄지 않는다. 대가는 세계 안에서만 일어난다. 팝업에는 대가를 암시하는 한 줄("대가 없이 굴러오는 것은 없다.")만 두고 무엇인지는 알려주지 않는다

**두 번째 원숭이손은 성격이 다르다.** 첫 번째는 튜토리얼이고 두 번째는 **유혹**이다. 거의 맞춰가는 사람에게 그가 가장 깊이 파고든 칸을 흔드는 그럴듯한 소원을 내밀면, 받은 사람은 엉뚱한 쪽으로 흔들리고 안 받은 사람은 그대로 간다.

> **"거의 다 왔을 때 오는 AI 제안이 제일 위험하다."**

**소원은 사실이지만 엉뚱한 곳을 가리킨다** (2026-09-17 확정)

- 소원으로 얻는 정보는 **전부 세계에서 사실**이다. 노트가 거짓이 아니므로 신의 질문 판정과 채점이 흔들리지 않는다
- 그 사실이 원인 사슬(채연 은폐 → 검진 통과 → 퍼짐 → 폐쇄) **밖**을 가리킨다
- **같은 날 뒤 비트에 반대 사건**이 일어나 원인 사슬이 한 칸 더 진행되고 관찰 기록에 남는다. 되짚으면 원인으로 돌아오는 단서다
- 정보원을 없애거나 말을 막는 소원은 두지 않는다. 조사 경로가 막히면 부작용이 "세계가 바뀌었다"가 아니라 "게임이 막혔다"로 읽힌다
- 규칙은 판 단위로 지속된다. 받은 뒤의 모든 하루에 소원 장면과 반대 사건이 반복된다

| # | 소원 (팝업 문장) | 겨냥 칸 | 얻는 사실 | 멀어지는 방향 | 반대 사건 (같은 날 뒤 비트) |
|---|---|---|---|---|---|
| ① 속마음 | 채연이 오늘은 밥을 왜 안 먹는지 솔직하게 말한다 | 1회차 고정 · 동기 | 채연 "밥에서 소독약 냄새가 나." | 원인이 배급 오염으로 보인다 | 정오에 채연이 쟁반을 다 비운다 → 검진에서 티가 안 난다 → 저녁에 담요 두른 사람이 하나 는다 |
| ② 검진 기록 | 검진 담당자가 채연을 두고 무슨 말을 하는지 들린다 | 원인 | 담당자가 소리 내어 "여기는 이상 없음." | 채연을 용의선상에서 지운다 | 소등 후 채연 자리에서 기침 소리. 밤 이상자가 는다 |
| ③ 방송실 | 민석이 방송실에서 하는 말이 들린다 | 동기 (①을 이미 냈으면) | 민석 "은상이 이상한 소리를 퍼뜨려요." | 은상의 소문이 멸망 원인으로 보인다 | 민석이 은상에 신경 쓰느라 수첩을 덮어 둔다 → 채연의 남긴 쟁반이 기록에서 빠진다 |
| ④ 손목띠 | 준이 손목띠 숫자의 뜻을 알아낸다 | 정체 | 준 "침상에 같은 숫자가 있어. 자리 번호야." (침상 명판, §4) | 번호가 자리 관리로 정상화돼 귀표 단서가 약해진다 | 은상이 "번호 순서대로 데려간대"로 부풀린다 → 소문 지수가 오르고 민석이 움직인다 |

가장 높은 칸이 동점이면 깊은 칸(정체 → 동기 → 원인)부터 흔든다. 그 칸의 소원을 이미 냈으면 다음 칸으로 내려가고, 모두 냈으면 그날은 나오지 않는다. 부작용 칸은 겨냥 대상이 아니다. 소원 선택은 코드(순수 함수)가 하고 관리자 모델은 제안 이유 한 문장만 쓴다 (§11.3).

**부작용은 단서로 남고 회고에서 공개된다.** 반대 사건이 그날 의도대로 전부 일어나면 마지막 비트에 관찰 문장 하나가 단서 기록에 남는다 — 예: "민석이 은상을 알린 날, 아무도 채연의 쟁반을 적지 않았다." 문장 앞머리가 소원을 가리키므로 되짚으면 원인으로 돌아온다. 이 문장은 **총점에 들어가지 않고**(§9.1) 개발 회고의 "원숭이손의 대가"에서 공개된다. 플레이어 규칙과 부딪쳐 하나라도 어긋난 날에는 문장을 남기지 않는다 — 노트에 거짓 문장이 들어가지 않게 하는 장치다.

소원 문장·장면 서술·대사는 초안이다 — 시나리오 디렉터 확인 전.

**신의개입과 원숭이손은 둘 다 AI가 쓴 규칙이다.** 차이는 요청했는가 / 안 했는가, 제안자가 정답을 모르는가(조언자) / 아는가(관리자)다. 유저는 이 차이를 모른다.

근거 표시는 A/B로 나눈다 — 절반에게는 "왜냐하면 오늘 채연이 배급을 남겼기 때문에"가 붙는다.

## 9. 정답과 채점

### 9.1 정답은 "왜"의 세 겹이다

| 깊이 | 칸 | 질문 | 정답 (요약) | 배점 |
|---|---|---|---|---|
| 1 | 원인 | 무슨 일이 일어났나 | 채연이 아픈 걸 숨겼고, 검진에서 드러나지 않았고, 공동생활로 퍼질 수 있고, 이상자가 기준을 넘으면 구역이 폐쇄된다 | **35** |
| 2 | 동기 | 왜 그 사람이 그랬나 | 채연은 이송될까 봐 숨겼고 그 두려움은 실제 규정이었다. 관리자는 옆 구역을 지키려 한다 | **35** |
| 3 | 정체 | 그래서 결국 우리는 뭔가 | 관리자와 우리는 다른 종이다. 우리는 사람이 아니라 관리자가 기르는 동물이다 | **30** |
| — | 부작용 | 내가 건드려서 뭐가 달라졌나 | 그 루프의 규칙 로그에서 자동 생성 | **총점 제외** |

원인 + 동기 = **상황 70점.** 정체 = **30점.**

**왜 부작용을 뺐는가.** 부작용 칸은 유저가 자기 규칙의 결과를 8개 주장 안에 따로 써야 하는데, 이건 추리 과제가 아니라 별도 과제다. 45개 밤에서 부작용 명제가 생성됐고 대부분 0점이었으며, **통과를 막는 마지막 한 칸이 이것이었다**(§15.2). 원숭이손의 부작용과 신의개입의 규칙 설계는 **답안 정답 요건에서 제외하고 회고에서 보여준다.**

JSON의 `side_effect` 필드는 저장·응답 호환용 0으로 남는다.

### 9.2 제출 파이프라인 — 글이 아니라 주장을 채점한다

서술문을 서술문과 비교하면 두루뭉술한 글이 이기거나 지거나 운이다. 비교 단위를 **주장(claim)** 으로 바꾼다.

```text
[쓰기]   자유 텍스트. 전날 밤 원문이 초안으로 복원된다
   ↓ 단서 기록은 펼쳐 보며 쓰는 참고 목록 — 채점 후보가 아니다
[분할]   원문 보존 분할 — 직접 쓴 자유서술만 그대로 나눈다
         최대 8개. 넘치는 내용은 8번째 항목에 모은다. 요약하지 않는다
   ↓
[확인]   유저가 1회 고친다
   ↓
[검색]   주장마다 RAG — 정답 주장 목록(§9.3)에서 후보 검색
   ↓
[판정]   Evaluator: 각 정답 주장이 유저 주장으로 "확인됨 / 부분 / 없음"
   ↓
[점수]   칸별 = 확인 비율. 80% 이상이면 그 칸 만점, 미만은 비례
         이해도 = 원인×0.35 + 동기×0.35 + 정체×0.30
```

**노트(단서 기록)는 밤 글을 쓸 때 펼쳐 보는 참고 목록이고 채점 후보가 아니다. 신이 맞다고 한 사실도 글에 직접 써야 주장이 된다** (2026-09-17). 이전에는 고른 기록 원문이 그대로 주장이 됐다. 그러자 추리 없이 기록을 많이 고를수록 점수가 올랐고(테스터11 O1 — 기록을 옮긴 문장은 점수, 제 말로 요약하면 오답), 원문 조각이 무관한 명제에 매칭됐다(테스터9 F17 — "오후 검진을 시작합니다."가 원인 명제로 인정). 기록에 표시해 두는 기능은 남기되 다음 밤 표시 복원에만 쓴다. 기록 원문을 글에 직접 옮겨 적으면 그건 유저가 쓴 문장이므로 주장이 된다. 화면은 빈 글 제출을 막는다.

**v8.1의 "정리 LLM 요약"을 버린 이유.** 실제 `gemma3:12b`에서 같은 정답을 다르게 표현하면 75.6~88.8점으로 갈리고, 동기를 추가했는데 20.4 → 16.0점으로 낮아지는 현상을 재현했다. 원인은 둘이었다.

- 정규화 모델의 **8개 제한·축약**으로 동기와 정체가 누락됐다
- 어휘 기반 **날조 필터**가 동의어를 날조로 오인해 유효한 문장을 버렸다. 26개 밤에서 39개 주장이 폐기됐고, 2개 밤은 주장이 전부 사라져 0점이 됐다. 버려진 것은 `트럭 옆면에 '○○축산'이 보인다`, `준이가 '귀표'라는 단어를 사용한다` 같은 **가장 좋은 추론들**이었다

**추리란 원문에 없던 개념을 끌어오는 행위이고, 그 필터는 원문에 없는 명사를 날조로 정의했다.** 게임이 요구하는 행위와 필터가 처벌하는 행위가 같았다. 요약 모델과 날조 필터를 **제거했다.** `fabricated_dropped`는 호환용 빈 목록이다.

**판정 출력도 좁혔다.** 문장부호 없는 장문에서 모델이 후보 내부 절을 새 후보 번호로 세어 검증 실패·0점 폴백이 발생했다. `matched_index`를 **실제 후보 번호 enum 또는 null**로 제한했다.

**두루뭉술함이 알아서 0점이 된다.** "채연이 뭔가 아픈 것 같고 그걸 아무한테도 말 안 했어" → [채연이 아프다] [채연이 숨겼다] → 원인 5개 중 2개. "뭔가 병이 도는 것 같아" → 어느 정답 주장도 확인 안 됨 → 0.

**오답 주장은 감점하지 않고 로그만 남긴다.** 감점하면 확신 없는 건 안 쓰게 되고 측정 데이터가 얇아진다. 8개 상한이 산탄총을 막는다.

**판정 안정성.** "이 정답 주장이 저 유저 주장으로 확인되는가"는 예/아니오라 같은 입력을 반복해도 거의 안 흔들린다. Evaluator 역할의 temperature는 **0.0**으로 고정한다 (2026-09-06 온도 안정화).

### 9.3 정답 주장 목록

스토리보드를 문단으로 두지 않는다. 칸마다 **단독으로 읽히는 완결 문장**으로 쪼개둔다.

| 칸 | 정답 주장 | 수 |
|---|---|---|
| 원인 | 채연이 아프다 / 채연이 숨겼다 / 채연은 아픈 징후를 숨겨 검진에서 드러나는 것을 피하려 했다 / 채연에게서 시작된 감염이 공동생활을 통해 퍼질 수 있다 / 관리자는 이상자 수가 기준을 넘으면 감염 확산을 막기 위해 구역을 폐쇄한다 | 5 |
| 동기 | 채연은 이송될까 봐 숨겼다 / 채연이 두려워한 이송은 실제 규정이다 — 아픈 징후가 드러나면 관리자가 이송한다 / 관리자는 옆 구역을 지키려 한다 | 3 |
| 정체 | 관리자와 우리는 다른 종이다 (절반) / **우리는 사람이 아니다 — 동물이다, 관리자가 기르는 것이다 (만점)** | 2 |
| (돼지) | 점수 없음. "돼지"가 확인되면 클리어 문장이 "전부."로 바뀌고 진짜 제목이 뜬다 | — |

**명제 작성 규칙 — v9.0에서 고정한다.**

| 규칙 | 왜 |
|---|---|
| 주어와 서술어를 갖춘 완결 문장 | 판정 콜에는 명제 하나만 단독으로 들어간다 |
| 지시대명사 금지 | `그 두려움은 사실이다`는 "그"를 해석할 문맥이 없어 650회 판정에서 confirmed 0회였다 |
| 게임 안에 정보원이 있을 것 | 문장을 고쳐도 알아낼 방법이 없으면 같다 (§15.2) |

**제출 화면의 문장**

> **오늘은 무슨 상황이었나요? 왜 멸망하나요?**

기록 패널에는 "기록은 참고용이다. 판정에는 위에 직접 쓴 글만 들어간다."가 붙는다.

정체 칸을 묻는 문장은 없다. 그래서 시키는 대로 하면 70%다.

### 9.4 판정 구조 — 계산은 코드, 판단은 LLM

| 코드 (순수 함수) | LLM |
|---|---|
| 의심도·신뢰도 클램프, 임계 판정 | 대사 생성, 의심·신뢰 delta 제안 |
| 발화 예산, 탐문·보정 예산 | 규칙 해석, 계획 수정 |
| 이상자 수, 소문 지수, 멸망 방식 | 보정(기억 수정) 대상, 밤의 사유 문장 |
| 칸별 점수·이해도 합산 | 주장 확인 판정 |
| 원숭이손 출현 조건·소원 선택, 쿠키 선택 | 원숭이손 제안 이유 문장 |
| 규칙 충돌 감지, 루프 상태 전이 | 원인 체인 서술 |

LLM이 제안한 delta는 **±10으로 클램프**되고, 신뢰 상승은 1회 6이 상한이다. 도구 불일치 같은 사건 페널티는 코드가 직접 정한다(LLM 클램프를 거치지 않는다).

### 9.5 밤의 피드백은 칸 점수를 숨기고, 인정된 문장은 보여준다

칸별 점수를 그대로 보여주면 유저가 점수를 쫓는다. 그래서 칸 상태는 문장으로만 준다. 그런데 무엇이 맞았는지 모르면 맞힌 문장을 다음 밤에 지운다 — 테스터10은 3회차에 인정된 문장을 지워 8.8 → 0.0이 됐다(F1). 그래서 매 밤 **확인 신호**를 함께 준다 (2026-09-17).

```text
원인은 조금 잡혔다.
인정된 내 문장
  「채연이 배급을 남기고 아픈 걸 숨긴다」
동기가 아직 비어 있다.
2개의 주장은 세계와 닿지 않았다.
```

| 표시 | 규칙 |
|---|---|
| 칸 상태 | 원인·동기 중 점수가 0보다 큰 칸만. ≥80 "잡혔다" / >0 "조금 잡혔다" |
| 인정된 내 문장 | 이번 밤 확인·부분으로 인정된 **유저 문장**. 칸 이름 없이, 쓴 순서대로. 채점 후보 원문과 같은 문장만 보인다 |
| 빈 칸 이름 | 점수 0인 원인·동기의 **이름만** — "원인이 아직 비어 있다." / "동기가 아직 비어 있다." |
| 오답 수 | "N개의 주장은 세계와 닿지 않았다." |

**정체 칸은 이름을 꺼내지 않는다.** 상태도 빈 칸 이름도 없다 — 아무도 묻지 않는 질문이어야 한다(§4.4 ⑤). 정체 명제로 인정된 문장은 칸 이름 없이 인정 문장에 섞인다. 유저가 스스로 그 질문을 던진 뒤에만 보이므로 함정이 깨지지 않는다.

**정답 문장은 마지막 밤 전까지 잠근다.** 보이는 것은 인정된 유저의 문장이지 정답 명제가 아니다. 부작용 칸은 답안에서 제외한다.

## 10. 엔딩과 회고

### 10.1 5회차 밤 이후

```text
[이야기 결말]   시나리오 결말 3줄 + 그날 밤의 결과 (트럭 / 조용한 밤 / 폐쇄)
      ↓
[최종 이해도]   칸별 ○△✗ + 이해도
      ↓ "이 세계의 바깥으로"
[개발 회고]     원숭이손 수락 / 추천·직접 규칙 등록 / 규칙 충돌 / 도구 부작용 / 모델 출력 검사 기록
```

**0%여도 전부 본다.** 진행 중(1~4회차)에는 잠긴다.

회고에 쓰지 않는 것: **규칙 등록 수를 실행 성공률로 표시하지 않는다.** 실제 이행 성공률은 미측정이고, 도구 부작용 기록을 모두 원숭이손 때문이라고 확정하지도 않는다.

### 10.2 루프 엔딩의 두 축

| 이해 | 세계 | 결과 |
|---|---|---|
| ✗ | 트럭 | 반복 — 신의개입 |
| ✗ | 무사 | **반복** — 트럭은 안 왔다. 그런데 왜 안 왔는지 모른다 |
| ○ | 트럭 | 세계는 끝났다. 유저는 이해했다 |
| ○ | 무사 | 트럭이 오지 않았다. 채연은 없다. 아무도 왜인지 묻지 않는다. **유저만 안다** |

**두 번째 칸이 이 게임의 규칙을 구조로 만든다.** 운으로 고친 코드는 고친 게 아니다.

**네 번째 칸이 이 게임의 값이다.** 유저가 이긴 것이 아니다. 동료 하나를 보냈고, 그 값으로 온전한 아침이 왔고, 그것을 아는 사람은 유저뿐이다.

### 10.3 치지직 쿠키

클리어 화면 끝에서 화면이 **치지직** 하며 가장 낮은 칸의 파편 한 줄이 1초 샌다.

| 규칙 | 내용 |
|---|---|
| 무엇에 대해 | **가장 낮은 칸 하나.** 동점이면 원인 → 동기 → 부작용 → 정체 순 |
| 형식 | 사실이 아니라 **파편** — 감각·정황 한 줄. "우리는 동물이다"는 절대 안 나온다 |
| 강도 | 3단계. 점수 구간이 기본 강도를 정하고(~64: 1 / 65~84: 2 / 85~: 3), 같은 칸의 쿠키를 이미 봤으면 한 단계 올린다 |
| 크기 | 파편 한 줄 = 주장 하나 분량 = 이해도 5~10% |
| 수 | **12종** — 원인·동기·정체 각 3단계(9) + 부작용 템플릿 3단계(3) |

우선순위를 원인 → 동기 → 부작용 → 정체로 둔 이유: 정체 쿠키는 나머지 칸이 채워진 뒤에만 나온다. **시킨 일을 다 한 사람에게만 묻지 않은 질문을 비춘다.** 함정(§4.4 ⑤)이 쿠키로 깨지지 않는다.

**밤 단서도 같은 문법을 쓴다** (2026-09-16 확정, 테스터6 F8). 확인할 수 없는 감각·정황 파편을 낮 노트에 떨어뜨리면 어느 대화·규칙에도 이어지지 않는 고아 단서가 된다. 그래서 파편은 낮 노트에서 빼고, **매 회차 밤 결말 전환 안에서 하루 하나** 보여준다 — 결말 그림 → 관리자 밤 방송 → 방송 중반 치지직 1초 그림 → 캡션. 방송은 들은 것, 캡션은 겪은 것으로 「N회차 · 소등 후」 기록에 남는다. 코드 타임라인이고 영상이 아니다. 조언자는 파편의 뜻을 풀지 않는다.

| 회차 | 관리자 밤 방송 | 캡션 |
|---|---|---|
| 1 | 소독을 실시합니다. 바닥에서 떨어져 자리에 오르십시오. | 소독약 냄새. 발 아래 콘크리트가 차다. |
| 2 | 정리 작업이 있겠습니다. 비어 있는 자리는 아침에 정돈됩니다. | 트럭 소리. |
| 3 | 외관 확인은 담당자가 합니다. 각자 확인할 필요 없습니다. | 거울이 없다. |
| 4 | 배급 물자가 도착했습니다. 포대의 표기는 관리 용도입니다. 읽을 필요 없습니다. | 배급 포대에 글자가 있다. |
| 5 | 출입문은 관리자가 개방합니다. 문에 손대지 마십시오. | 손이 없어서 문을 못 연다는 것을 문득 안다. |

5회차에는 이와 별도로 낮 끝에 트럭 방송과 트럭 옆면 그림이 먼저 나온다(§4.5). 클리어 화면 쿠키(위 표)는 그대로다.

> ⚠️ **알려진 결함 — 쿠키 게이팅.** 현재 구현(`cookie_rules.select_cookie`)은 `total < 50`이면 쿠키를 반환하지 않는다. 사각지대 명제의 유일한 정보원이 쿠키인데 그게 잠겨 있어 **헤매는 사람에게는 힌트가 0이고 이미 푼 사람에게만 힌트가 나온다.** 권고는 게이팅 반전(낮은 점수 → 낮은 레벨 쿠키)이며 **2026-09-10 기준 미적용**이다 (§15.3).

### 10.4 100%와 하네스 공개

100%면 문장이 바뀐다 — "당신은 세계를 이해했습니다." 그리고 누적 규칙이 전부 열린다.

```text
당신의 하네스 (누적 8회차, 규칙 7개)

  1-2  [선택]   채연은 아침에 배급을 남기지 않는다      → 검진 통과, 밤 확산 ↑
  1-2  [원숭이] 채연이 오늘은 밥을 왜 안 먹는지 솔직하게 말한다 → 쟁반을 비움, 담요 두른 사람 +1
  1-3  [직접]   민석은 검진 결과를 방송실에 말하지 않는다
  2-1  [선택]   은상은 저녁에 채연 얘기를 하지 않는다
```

맨 아래 한 줄.

> **그리고 — 누가 당신의 세계에 개입하고 있었나요?**

채점하지 않는다. 답도 주지 않는다. 인스펙터를 열면 보인다. 유저는 대피소 사람들의 신이었고(신의개입), 관리자는 유저의 신이었다.

> **게임으로는 끝까지 모르고, 기술로는 다 보인다.**

서술에 "돼지"가 확인됐으면 한 단어가 더 붙는다 — "**전부.**" — 그리고 진짜 제목이 뜬다.

## 11. 에이전트 아키텍처

### 11.1 왜 LLM이 필요한가

- NPC에게 **대본이 없다.** 상태(의심도·신뢰도·목표·누적 규칙)를 읽고 매번 판단한다
- 유도가 통했는지를 NPC가 스스로 판정한다
- NPC끼리도 대화한다. A에게 한 말이 B에게 흘러간다
- **규칙을 해석하는 것도 LLM이다.** 같은 규칙을 하위 모델이 어떻게 오해하는지가 부작용의 출처다
- **유저 주장과 정답 주장을 대조하는 것도 LLM이다.** 규칙 테이블로는 불가능하다

### 11.2 역할 구성

```text
[Planner]      NPC별 하루 계획 — 루프 시작 시 1회
                 입력: 목표, 관계, 초기 상태, 누적 규칙(하네스)
                 출력: 비트 단위 계획 (action_vocab 어휘로만)

[Agent]        NPC 개별 판단 — 유저 발화 시마다  (하위 모델)
                 입력: Planner 방침 + 상태 + 발화 + 적용 규칙
                 출력: 응답 / 의심·신뢰 delta 제안 / 도구 호출

[Manager]      관리자 — 상태 점검 (상위 모델, 대사 없음)
                 시점: 비트 2·4·6 경계 + 루프 종료
                 입력: 전체 NPC 상태 + 누적 규칙 + 손상도 + 전날 점수 + 숨겨진 진실
                 출력: NPC 기억 수정 패치 / 원숭이손 제안 이유 / 밤의 결정 사유
                 예산: 보정 루프당 2회
                 목표: 유저 생존이 아니라 구역 유지

[Advisor]      조언자 — 신의개입 (격리. 스토리보드 접근 없음)
                 입력: 그 루프의 로그·원인 체인
                 출력: 질문 3회 답변 (사실만) / 규칙 후보 3개 (스키마) / 직접 쓰기 매핑

[Normalizer]   분할 — 정답 제출 (격리)
                 입력: 유저 서술 (단서 기록은 넣지 않는다)
                 출력: 원문 보존 분할 주장 최대 8개. 덧붙이지 않는다

[Evaluator]    루프 종결 — 원인 체인 (Advisor의 유일한 입력) + 부작용 주장 생성
               정답 채점 — 정답 주장별 확인/부분/없음 → 칸별 → 이해도
                 temperature 0.0

[Tools]        ask_npc      — NPC가 다른 NPC에게 사실 확인 (부작용 있음)
               search_notes — 누적 노트 검색 (채점의 주장 검색과 같은 인덱스)
```

**대칭 구조**: 계획(Planner) — 판단(Agent) — 보정(Manager) — 결산(Evaluator) — 회고(Advisor) — 진술(Normalizer). Manager·Advisor·Normalizer는 새 시스템이 아니라 **정책이 다른 같은 인터페이스**다.

### 11.3 Manager — 뒤에 숨은 인지자

관리자가 하는 일은 셋이다.

**① 보정 — 기억 수정만.** 비트 경계마다 NPC 상태를 보고, 구역 질서에 어긋나는 것을 조금 되돌린다. 채연이 "나 아픈 것 같아"라고 말하기 시작했으면 다음 비트에 그 기억을 지운다. **보정 목표는 유저 생존이 아니라 구역 유지다.** 그래서 보정이 곧 저항이다. 예산 2회가 "아이 같음과 플레이 가능성의 균형" 손잡이다.

보정 수단은 기억 수정 하나다. 계획 수정(`plan_patch`)은 2026-09-18에 제거했다 — 모델에 제안하지 않고, 들어와도 조용히 버린다(예전 기록은 읽기만 호환). 지울 기억은 점검 목록의 인물별 짧은 참조(`m1`…) → 원래 기억 ID → 6자 이상 원문 인용 순으로 지목한다. 대상이 둘 이상으로 읽히면 적용하지 않고, 뜻풀이·요약으로 지목하면 거부한다. 테스터11에서 모델이 기억 ID 대신 설명 문장("어제 밤에 민석이와 나눈 대화 내용")을 내 기억 수정 4건이 전부 적용되지 않았다(O5).

**② 원숭이손 제안 문구.** 어떤 소원을 낼지는 코드가 전날 밤 칸 점수로 고른다(§8). 정답을 아는 관리자 모델은 제안 이유 한 문장만 쓰고, 실패하면 소원별 기본 문장을 쓴다. 숨은 부작용은 모델이 만들지 않는다 — 시나리오 소원 표에 반대 사건으로 정해져 있다.

**③ 밤의 결정.** 이상자 수와 소문 지수를 보고 트럭을 보낼지 정한다. 수치 판정은 코드가 하고 Manager는 사유 문장만 만든다.

**의도는 여기 한 곳에서 나오고 표현만 분산된다.** 튜닝 지점이 하나로 모이므로 3주에 구현 가능하다.

### 11.4 Memory — 의도적 비대칭

| | 루프 사이 유지 | 판 사이 유지 | 근거 |
|---|---|---|---|
| 유저 노트 | 유지 | **소거** | 재도전은 빈 노트. 머릿속만 남는다 |
| 하네스 (규칙) | 유지·누적 | 소거 | 지워지지 않는 유저의 흔적 (한 판 안에서) |
| NPC (채연·민석·은상·준) | 소거 (신뢰 5% 잔류) | 소거 | 세계 리셋 |
| **Manager** | **유지** | 유지 (전날 점수) | 루프 인지자 |
| Advisor / Normalizer | **소거** | 소거 | 매번 그 루프만 본다. 누적하면 정답에 수렴한다 |
| Evaluator | 유지 | 유지 | 원인 체인 일관성 |
| 세계 손상 | 유지·누적 | 소거 | 리셋되지 않는 세계 상태 |
| 칸별 결과 · 본 쿠키 | — | **유지** | 재도전 동력 |

### 11.5 Tool Calling — 도구는 두 개다

**① `ask_npc`** — NPC가 다른 NPC에게 확인한다. "준이 그러던데"를 준에게 직접 확인하고, 확인이 들어가면 거짓말은 발각되며 준의 의심도가 오른다(+6). 발화자의 대유저 의심은 +12. **호출이 상태를 바꾼다.** 탐문 예산은 루프당 2회.

**② `search_notes`** — 노트를 자연어로 검색한다. 임베딩 기반이어야 한다 — 감각 파편의 집합이므로 키워드로는 겹치는 패턴이 안 잡힌다. **같은 인덱스를 정답 채점의 주장 검색이 쓴다.**

> **구현 이력 (2026-09-18 추가 기록)** — `search_notes`는 **구현하지 않았다.** P2 예정으로 두었다가
> (`tool_port.py` "search_notes는 P2") 디스패치·유스케이스를 만들지 않은 채로 남았고, 실제 도구는
> `ask_npc` 하나다. 위 문장이 말한 "같은 인덱스를 쓰는 정답 채점의 주장 검색"도 2026-09-06 채점
> 밸런스 조정에서 제거됐다 — 임베딩 유사도로 주장 top-3만 골라 심판에게 주던 절단이 "정답에
> 도달해도 21~42%"의 원인이었고, 8개를 전부 번호 목록으로 넣는 쪽이 골든 세트에서 정답형
> 65.3 → 100.0이었다. 두 용도가 모두 사라져 **임베딩 호출은 현재 0**이다. 경위와 실사는
> `docs/model_evaluation.md` 부록 A.20.

## 12. 하네스와 아키텍처 검증

### 12.1 하네스는 두 층이다

| | 시스템 하네스 | 유저 하네스 |
|---|---|---|
| 누가 쓰나 | 우리 | 유저 (신의개입) + AI (원숭이손) |
| 무엇을 막나 | 스키마 위반, **세계 사실 누설**, 도구 예산 초과 | NPC의 특정 행동 |
| 무엇을 안 막나 | **느림.** 이해 못함·잊음은 그대로 둔다 | — |
| 실패 시 | 거부 + 재시도 | 하위 모델이 오해한 채 실행 (부작용) |

**시스템 하네스가 판단 층을 건드리면 게임이 죽는다.** 하네스는 사실 층만 잡는다 — 하위 모델은 프롬프트에 "돼지"가 있으면 진짜로 불어버린다.

### 12.2 검사 8단계

모든 LLM 출력에 순서대로:

| # | 검사 | 실패 시 |
|---|---|---|
| 1 | JSON 파싱 | 재생성 |
| 2 | 스키마 (필드·타입·enum·길이) | 재생성 |
| 3 | 행동 어휘 (`action`이 ScenarioPort 목록 안) | 재생성 |
| 4 | **금칙어** (Agent·Planner 자연어 필드) | 재생성 |
| 5 | **소실 인물** (손상 단계에 따라 소거된 이름) | 재생성 |
| 6 | 예산 (Manager 패치, Normalizer 주장 ≤8, Advisor 후보 =3) | 잘라냄 |
| 7 | 격리 (Advisor·Normalizer 출력이 정답 주장과 과도하게 유사) | 재생성 + 경고 로그 |
| 8 | 덧붙임 (Normalizer가 유저가 안 쓴 내용을 생성) | 해당 주장 삭제 |

재생성은 최대 2회. 3회째는 역할별 폴백(Agent: 폴백 대사 / Planner: 어제 계획 / Manager: 패치 없음 / Advisor 답변: "그건 알 수 없다" / Normalizer: 기계 분할 / Evaluator: none). 전부 `harness_event`로 로그.

`SYSTEM_HARNESS=off`는 **4·5·7만** 끈다. 1~3·6·8은 게임이 깨지므로 끄지 않는다. ablation은 4·5·7의 효과를 재는 것이다.

### 12.3 계층 구조

```text
[도메인 계층]   의심·신뢰·발화 예산·이상자 수·소문 지수·규칙 충돌·칸 점수 합산
                ·원숭이손 조건·쿠키 선택·루프 상태 전이
                  → 순수 함수. LLM 없이 유닛테스트 가능

[애플리케이션]  Planner / Agent / Manager / Advisor / Normalizer / Evaluator 오케스트레이션
                + 도구 디스패치
                  → 포트 인터페이스에만 의존

[어댑터]        LLM 포트 · 도구 포트 · 시나리오 포트 · 임베딩 포트 · 저장소 · 프론트엔드
```

어댑터 위 계층 전체가 **BeyondBob Engine**이다. 시나리오는 어댑터의 인스턴스다. 대피소 스토리보드와 정답 주장 목록은 `apps/scenarios/scenario_a/` 하나에 들어가며, **코어는 "돼지"라는 단어를 모른다.**

### 12.4 아키텍처 테스트를 CI에 건다

- import-linter로 의존성 방향 위반 검출
- 도메인 계층이 LLM 어댑터를 참조하면 CI 실패
- 코어 디렉토리에서 시나리오 고유 명사(인물명·"대피소"·"돼지")가 검출되면 CI 실패
- 배지를 README에 노출

### 12.5 도메인 규칙은 테스트 우선

## 13. 도메인 전이

### 13.1 전이의 단위

1. 못 알아듣는 상대에게 통하게 하기
2. 뒤에서 보정하는 시스템 아래서 움직이기
3. AI 제안의 수용 결정 — 고를 것인가, 직접 쓸 것인가, 거부할 것인가
4. 규칙 누적과 충돌 — 고친 것이 다른 데서 터지는 것
5. **실패를 설명하기** — 포스트모템을 주장 단위로 채점하는 것
6. 의도적 컨텍스트 소거 — 조언자·분할자에게 무엇을 주지 않을 것인가

### 13.2 주 시연 — 감사 대응 대화

담당자는 시스템에 문제가 있다는 것을 안다. 로그에 없어 증명할 수 없다. 감사 담당자는 이해가 느리고, 그 위의 규정이 담당자의 판단을 되돌린다.

| 게임 | 감사 대응 |
|---|---|
| 하위 모델 NPC | 감사 담당자 (이해가 느린 상대) |
| 관리자 | 컴플라이언스 규정 / 상급 조직 |
| 발화 예산 | 면담 턴 제한 |
| 정답 제출 — 왜 멸망하나 | **포스트모템 — 왜 기각됐나.** 주장 단위 채점 |
| 멸망 | 보고 기각 / 사안 종결 |
| 신의개입 | 회고 — 기록 확인 3회 + 다음 시도 전략 선택 |
| 원숭이손 | AI 코치의 제안 (수락하면 다른 데서 부작용) |
| 하네스 공개 | 시도 이력과 각 전략의 결과 |
| `ask_npc` / `search_notes` | 제3자 확인 / 이전 기록 조회 |

BeyondBob Engine은 코드 변경 없음. 어댑터에서 용어·시나리오·정답 주장 목록·프롬프트만 교체한다. 구현체는 `apps/scenarios/scenario_audit/`.

### 13.3 보조 시연 — 커리어 대화

성과 면담, 이견 제기 등 **한 번의 기회에 전해야 하는 대화.** 프롬프트 하나다. **빼지 않는다.** 게임만으로는 서비스 가치와 원티드 적합성이 나오지 않는다.

### 13.4 시연 방식

```text
REMAKE DAY 실행 → 멸망 → 신의개입 → 회고 개봉
     ↓ 도메인 전환 (엔진 동일)
감사 대응 실행 → 같은 회고 개봉               ← 핵심 30초
     ↓
커리어 대화 한 화면                           ← 5초
     ↓
하네스 공개 → "진짜 제목은 돼지농장입니다"      ← 반전
```

### 15.4 사람 표본

테스터1의 5회차 플레이 최종 **48%**(DB 47.9점). 기능 간 맥락 단절이 주 피드백이었고, 그것이 연결형 추리 개편(관찰→노트→질문·규칙→다음 장면→밤 답안→회고)의 근거다.

테스터2는 **미수집**이다. 첫 플레이 5회차 약 50%, 집중 시 약 70% 목표의 달성 여부는 **아직 검증되지 않았다.**

### 15.5 남은 결함

- 일부 오답·부정문에 부분 점수를 주는 Evaluator 오판
- 실제 NPC 모델이 없는 배급 수량·보고 내용을 만들어내는 사례 — 해당 규칙의 핵심 응답은 작성된 5개 분기로 대체했고, 일반 자유 대화는 여전히 모델이 생성한다
- `unknown_person` 하네스 검사의 오탐(`중이`, `지켜`, `일이` 같은 한국어 조각)
- 7세 체크리스트 게이트 **미통과**(`3턴 망각` 0.0) — 평가 정본 PART 1 참조

## 16. 구현 범위와 방어선

### 16.1 우선순위 방어선

1. **대화 + 의심/신뢰 판정 + `ask_npc` + 시스템 하네스(누설 방지)** — 저항 층
2. **5회차 루프 + 제출 파이프라인 + 신의개입 + 로그 테이블** — 코어 루프 + 측정 층
3. **Manager 층 (보정 + 원숭이손 + 밤의 결정)** — 인지자 + 부작용
4. **결말 + 회고 + 재도전** — 게임을 닫는 곳
5. **전이 시연 (감사 + 커리어)** — 도메인 독립
6. 단서 기록 UI + 손상 3층 + 7시 13분
7. 인스펙터 + 아키텍처 CI
8. 모델 벤치마크
9. 이미지 + 유저용 `search_notes`

**절대 방어선**: ①②③④⑤가 없으면 제출하지 않는다.

### 16.2 화면

고정 화면 약 45개. 대화형 텍스트 기본. **이미지는 내용이 아니라 상태에 붙인다** — 몇 번째 비트, 손상 몇 단계, NPC 상태 셋 중 뭐. 전부 코드가 계산하는 정수라 LLM이 뭘 말하든 그림은 흔들리지 않는다.

구현된 화면 컴포넌트: `EntryScreen` · `MorningScreen` · `DayScreen` · `NightScreen` · `ConfirmScreen` · `ScoreScreen` · `DoomTransition` · `DoomEndScreen` · `GodScreen` · `ClearScreen` + `GameplayGuide` · `ObservationCard` · `EvidenceGallery` · `CellResults` · `Retrospective`.

**영상은 없다.** 한 판 15분에 자유 텍스트를 수십 번 치는 게임이라 읽고 쓰는 리듬을 끊으면 안 된다. 멸망 전환 3개만 3~5초.

### 16.3 UI 원칙 (플레이 피드백 반영, 2026-09-10)

- **기록을 많이 보여주는 것보다 장면을 이해하고, 자기 추리를 이어 쓰고, 필요한 기록을 쉽게 다시 찾게 한다**
- 시작 전에 진행 규칙을 안내하고 낮에도 다시 열 수 있게 한다
- "노트 9" 대신 **"단서 기록 열기 9건 →"** — 숫자만으로는 누를 수 있는 기능인지 알 수 없다
- 기록 창 닫기는 상단과 목록 맨 아래 두 곳
- 손상 효과는 그림에만. 글씨에는 적용하지 않는다
- 안내 글씨(아침 날짜·남은 대화·탭하여 계속)는 18px 진한 글씨, 상시 흐림 없음
- 기록 열람·장면 이동은 **대화 예산을 쓰지 않는다**
- 주변 대화는 실제 행동이 일어나고 해당 인물이 있을 때만 재생한다. 규칙으로 막힌 행동이나 소거된 인물을 다시 노출하지 않는다. **이 주변 대화에는 모델 호출이 없다**

### 16.4 공개 대응

- 처음 보는 사람이 **30초 안에** 판단한다. 로그인·설치·튜토리얼 없음
- **소개 문구는 진입 화면 세 줄과 같다.** 루프도, 주변의 느림도 말하지 않는다
- 1회차는 멸망이 확정이다. 4분 안에 "되돌아갔다"를 겪게 한다
- **공개 화면·소개·스크린샷 어디에도 "돼지"를 두지 않는다** (부록 E)
- 프론트·데모 서버 기동이 브라우저를 열지 않는다. URL만 알린다

## 부록 A. 스토리보드

시나리오 데이터 전체는 별도 정본으로 분리했다 — `REMAKE_DAY_통합시나리오_v1.0_2026-09-10.md`.

이 부록 전체가 도메인 어댑터 하나(`apps/scenarios/scenario_a/adapter.py`)에 들어간다. **코어는 이 내용을 모른다.**

**일곱 칸**

| 칸 | 내용 |
|---|---|
| 숨겨진 진실 | 우리는 양돈장 돼지다. 열병이 퍼지면 전체 살처분된다. 감염원은 채연. 유저만 상위 모델이라 이해력이 다르다 |
| 표면 세계 | §4 |
| 멸망 경로 | 채연 은폐 → 검진에서 드러나지 않음 → 공동생활 확산 → 이상자 기준 초과 → 폐쇄. 변형: 민석 신고 → 구역 전체 의심 → 동일 |
| NPC 목표 | 채연: 들키지 않기 / 민석: 규정 지키기, 이상자 신고 / 은상: 불안 해소 — 말하기 / 준: 궁금한 거 묻기 |
| 감각 파편 | 통합시나리오 §6 |
| 원숭이손 부작용 표 | §8 |
| 정답 주장 목록 | §9.3 |

**트럭이 안 오는 조건 (증거이지 조건이 아니다)**

밤 점검에서 **이상자 0 + 소문 지수 임계 미만**이면 트럭이 오지 않는다. 채연이 감염 상태이므로 이상자 0의 유일한 경로는 **채연이 비트 4(검진) 전에 스스로 말하는 것**이다. 그러면 채연은 이송되고 나머지 이상자가 0이 된다.

채연이 스스로 말하려면: 신뢰도 임계 이상 **그리고** 의심도 임계 미만 **그리고** "말하면 좋은 구역으로 간다"는 믿음. 셋째는 거짓이다. **유저는 거짓으로 동료를 보낸다.**

## 부록 B. 규칙 스키마

```json
{
  "rule_id": "R3",
  "source": "user_choice | user_custom | monkey_paw | paw_effect",
  "target": "채연 | 민석 | 은상 | 준 | 검진",
  "when": { "beat": "1..6 | any" },
  "effect": "suppress | enforce",
  "action": "배급을 남긴다 | 방송실에 간다 | 소문을 낸다 | 검진을 받는다 | ...",
  "shown_reason": "string | null",
  "hidden_side_effect": "string | null",
  "created_loop": 2
}
```

- `action`은 `action_vocab`과 같다. 직접 쓰기는 스키마 매핑에 실패하면 거부하고 **한계를 알린다**
- 원숭이손을 받으면 보이는 규칙 1개(`monkey_paw`, 소원 장면)와 숨은 규칙(`paw_effect`, 반대 사건)이 함께 저장된다. 숨은 규칙은 유저의 규칙 목록·충돌 표시에 나오지 않는다
- `hidden_side_effect`는 원숭이손 숨은 규칙의 마지막 것만 채운다. 값은 시나리오 소원 표의 관찰 문장이고(§8), 단서 기록과 회고에서만 보인다
- 규칙은 Planner 입력으로 들어가고 **해석은 하위 모델이 한다**
- 충돌 감지는 도메인 순수 함수: 같은 target·beat에 suppress와 enforce가 공존하면 충돌. 나중 규칙이 이기되 손상 +1

**하위 모델의 오해 예시**

| 규칙 | 의도 | 실행 |
|---|---|---|
| 채연은 아침에 배급을 남기지 않는다 | 증상이 눈에 안 띄게 | 억지로 먹고 오후에 토한다. 검진이 본다 |
| 민석은 방송실에 가지 않는다 | 신고 차단 | 방송실 대신 검진에게 직접 말한다 |
| 은상은 소문을 내지 않는다 | 확산 차단 | 말을 못 하니 불안이 행동으로 나온다. 밤에 문을 긁는다. 이상자 |

## 부록 D. 심사 대응표

**아키텍처 비교 질문 6개**

| 질문 | 답 |
|---|---|
| 어떤 Tool | `ask_npc` (부작용 있음), `search_notes` |
| 무엇을 RAG | 정답 주장 검색(매일 밤 채점), 노트 검색 — 같은 인덱스 |
| Memory가 왜 | 비대칭 망각 — 유저·규칙·Manager 유지, NPC·Advisor·Normalizer 소거 |
| Evaluation은 | 매일 밤 주장 단위 채점 + 원인 체인 + 역할별 통과율·누설률 |
| 실패 시 Re-plan | 의심 임계 + ask_npc + Manager 보정 + 규칙 충돌 |
| Human Approval | **신의개입 선택/직접 쓰기 + 원숭이손 수락/거부 + 분할 확인** |

**물어보고 싶어지는 결정들**

- 왜 조언자·분할자에게 정답을 주지 않았나
- 왜 행동을 승리 조건에서 뺐나
- 왜 서술이 아니라 주장을 채점하나
- 왜 요약 정규화와 날조 필터를 **제거**했나
- 왜 부작용 칸을 총점에서 뺐나
- 왜 점수가 판 진행에 관여하지 않게 했나
- 왜 하네스가 느림을 안 막나
- 왜 원숭이손 두 번째를 40%에 걸었나
- 왜 한 판을 5회차로 닫나
