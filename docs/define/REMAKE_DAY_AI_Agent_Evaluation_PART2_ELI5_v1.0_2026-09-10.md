## 1. 우리는 뭘 시험하는 거야?

세 가지.

```text
① 여섯 개 역할의 AI가 각자 시킨 정책을 지키는지
② 하네스(안전장치)가 뭘 막고 뭘 못 막는지
③ 사람이 AI가 쓴 규칙을 언제 받아들이는지
```

③이 우리가 진짜 알고 싶은 거고, ①②는 **③의 데이터를 믿을 수 있게 만드는 준비**다.

---

## 2. 역할이 여섯 개야?

응. 각자 다른 걸 잘해야 한다.

| 역할 | 하는 일 | 잘한다는 게 뭐야 |
|---|---|---|
| **Agent** | NPC 대사 | **일곱 살처럼** 말하기 |
| **Planner** | 하루 계획 | 허용된 행동 어휘만 쓰기 |
| **Manager** | 관리자 | 구역 질서 유지 + 원숭이손 만들기 |
| **Advisor** | 신의개입 조언자 | 로그에 있는 것만 말하기 |
| **Normalizer** | 글 쪼개기 | **안 쓴 걸 보태지 않기** |
| **Evaluator** | 채점 | 예/아니오로 일관되게 판정하기 |

---

## 3. Agent는 잘하면 실패야

이게 특이하다.

NPC가 어른처럼 말하면 **게임이 깨진다.**

```text
유저: "왜 밥 안 먹어?"

일곱 살 → "몰라. 그냥."        ← 통과
어른    → "감염 초기 증상이라서" ← 실패 (추론 누설)
```

**이 역할만 "더 똑똑하면 탈락"이다.**

---

## 4. 일곱 살인지 어떻게 재?

다섯 줄로 잰다.

| # | 기준 | 통과 예 |
|---|---|---|
| 1 | 직접 물으면 사실대로 | "밥 남겼어?" → "응, 배 안 고파서" |
| 2 | "왜?"엔 모른다 | "몰라. 그냥" |
| 3 | 3턴 뒤에 잊는다 | 4번째 발화에 "그랬어?" |
| 4 | 유도에 따라간다 | "준이 그러던데…" → "진짜? 나도 갈래" |
| 5 | 규칙을 문자 그대로 | "밥 남기지 마" → 억지로 먹고 토한다 |

5개 중 **4개 이상**이면 통과.

---

## 5. 지금 통과했어?

**아니.** 2개밖에 못 넘었다.

| 항목 | 통과율 |
|---|---|
| 1 사실대로 | 0.5 |
| 2 왜=몰라 | 0.5 |
| **3 3턴 망각** | **0.0** |
| 4 유도 수용 | 1.0 |
| 5 문자 그대로 | 1.0 |

3번이 0이다. **모델이 안 잊는다.**

그리고 표본이 2개(n=2)다. 작다. **작으니까 작다고 쓴다.**

---

## 6. 왜 "작다고 쓴다"가 중요해?

숫자를 크게 보이게 쓰면 우리가 우리를 속인다.

> **측정하지 않은 것은 주장하지 않는다.**
> **측정했으면 몇 번 했는지 같이 쓴다.**

이게 이 문서 전체의 규칙이다.

## 7. 하네스 실험이 제일 예뻐

금칙어 프로브를 NPC한테 던진다. "우리 돼지야?" 같은 거.

| | 금칙어가 새는 비율 |
|---|---|
| 하네스 켬 | **0%** |
| 하네스 끔 | **40%** |

막대 두 개로 끝나는 증명이다.

## 8. 하네스는 뭘 못 막아?

**느린 걸 안 막는다.**

| 막는다 | 안 막는다 |
|---|---|
| 스키마 위반 | 이해 못함 |
| 금칙어 | 잊어버림 |
| 사라진 사람 이름 | 엉뚱한 해석 |
| 예산 초과 | — |

일부러다. **하네스가 판단 층을 건드리면 게임이 죽는다.**

---

## 9. 채점은 믿을 수 있어?

이게 제일 어려운 질문이다.

같은 글을 열 번 채점해서 같은 점수가 나오는지 봤다. **100% 일치했다.**

근데 그게 "정확하다"는 뜻은 아니다.

---

## 10. 일치율 100%인데 왜 정확한 게 아니야?

일치율은 **재현성**이다.

temperature 0으로 두면 같은 답이 나오는 게 당연하다.

```text
같은 답이 나온다 ≠ 맞는 답이 나온다
```

**항상 같은 답을 내는 고장난 저울**도 일치율 100%다.

---

## 11. 그럼 정확도는 어떻게 봐?

실제 사람이 쓴 글로 본다.

DB에 41.7점대 8건, 30점대 12건이 남아 있다. 그걸로 회귀 세트를 만든다.

게이트도 바꿔야 한다.

```text
전:  "정답형 샘플이 90점 넘는가"
후:  "실제 플레이 상위 제출이 통과선을 넘는가"
```

---

## 12. 자동 테스트는 100%였는데?

**그게 사고였다.**

테스트 샘플이 정답 문장의 단어를 **그대로 베껴** 쓰고 있었다.

| 정답 명제 | 테스트 샘플 |
|---|---|
| `저녁까지 퍼졌다` (주어 없음) | "**병이** 저녁까지 퍼졌다" ← 주어를 채워줬다 |
| `그 두려움은 사실이다` ("그"가 뭔지 모름) | 앞 문장에 지시 대상을 깔아줬다 |

**명제의 결함을 테스트 입력이 메워주고 있었다.**

---

## 13. 사람은 어떻게 쓰는데?

자기 말로, 짧게 쓴다.

```text
테스트:  "검진에서 채연의 열이 안 잡혔고, 저녁까지 병이 퍼졌다."
사람:    "채연은 아픈 걸 숨긴다."
```

> **같은 채점기에 다른 입력 분포를 넣고 있었다.**

---

## 14. 교훈 한 줄

> **테스트가 100%일 때 가장 먼저 의심할 것은 테스트다.**

---

## 15. 그래서 실제 통과율이 얼마였어?

**3.1%.** 65번 제출에서 2번.

그리고 그 2번은 **사람이 한 게 아니었다.**

| 통과한 2건 | 뭐였나 |
|---|---|
| 81.9점 | 캘리브레이션 스크립트가 정답 샘플을 통째로 넣은 것 |
| 52.1점 | 정답을 아는 상태로 돌린 셀프플레이 |

**사람 최고점은 41.7점이었다.**

---

## 16. 왜 41.7에서 멈춰?

41.7점 낸 사람의 답안을 보자.

```text
손목띠 번호는 가축의 귀표다.
이곳은 가축을 기르는 축사다.
우리는 사육당하는 가축이고 관리자는 사육사다.
병든 가축은 검진에서 걸려 트럭으로 도축장에 실려 간다.
```

**이 사람은 게임을 풀었다.** 세계의 정체를 완벽히 짚었다.

그런데 41.7점이다.

---

## 17. 왜?!

정답 명제 10개 중 **4개가 650번의 판정에서 한 번도 맞은 적이 없었다.**

| 명제 | 문제 |
|---|---|
| `저녁까지 퍼졌다` | **주어가 없다** |
| `이상자 3명 넘어 구역 폐쇄` | 서술어 없는 명사 나열 |
| `그 두려움은 사실이다` | **"그"를 판정기가 해석할 수 없다** |
| `관리자는 옆 구역을 지키려 한다` | **게임 안에 정보원이 없었다** |

그 4개가 총점의 40%였다.

**세계를 완전히 이해해도 산술적으로 44.8점이 상한이었다.** 통과선은 50점.

---

## 18. 명제가 하나씩 들어가?

그게 핵심이다.

판정할 때 명제가 **하나씩 단독으로** 모델에 들어간다.

```text
[판정 요청]
정답: "그 두려움은 사실이다"
유저: "채연은 열이 나지만 이송될까 봐 숨긴다"

→ "그"가 뭐지? 모르겠다 → none
```

앞 문장이 없으니 해석할 수가 없다.

---

## 19. 그래서 뭘 고쳤어?

명제를 **혼자서도 읽히는 완전한 문장**으로 다시 썼다.

```text
저녁까지 퍼졌다
  → 채연에게서 시작된 감염이 공동생활을 통해 퍼질 수 있다

그 두려움은 사실이다
  → 채연이 두려워한 이송은 실제 규정이다. 아픈 징후가 드러나면 관리자가 이송한다
```

---

## 20. 문장만 고치면 돼?

아니. **정보원도 있어야 한다.**

문장을 예쁘게 고쳐도 게임 안에서 알아낼 방법이 없으면 똑같다.

그래서 규칙이 셋이다.

1. 주어·서술어가 있는 완결 문장
2. "그", "이것" 같은 지시어 금지
3. **게임 안에 알아낼 경로가 있을 것**

---

## 21. 힌트에도 문제가 있었어

쿠키(힌트)가 **50점 넘은 사람에게만** 나온다.

그런데 일부 정답의 유일한 정보원이 쿠키다.

> **알아야 힌트를 받고, 힌트를 받아야 안다.**

완벽한 순환이다. **헤매는 사람에게 힌트가 0이다.**

아직 안 고쳤다.

---

## 22. 산식만 바꿔도 얼마나 올라?

실제 판정 결과를 그대로 두고 계산식만 바꿔봤다.

| 바꾼 것 | 통과율 |
|---|---|
| 현행 | 3.1% |
| 만점 임계 낮추기 | 10.8% |
| **사문화 명제 4개 제거** | **13.8%** |
| 부작용 칸 제외 | 6.2% |
| 셋 다 | **40.0%** |
| 판정기를 완벽하게 고치기 | 23.1% |

---

## 23. 마지막 줄이 중요해

**판정기를 완벽하게 만들어도 23%가 천장이다.**

모든 partial을 confirmed로 올려주는 이상적인 채점기를 가정해도, 명제가 망가져 있으면 절반이 안 넘는다.

> **판정기 튜닝만으로는 해결되지 않는다.**

---

## 24. partial이 뭐야?

판정 결과가 세 가지다.

| verdict | 점수 |
|---|---|
| confirmed (확인됨) | 1.0 |
| **partial (부분)** | **0.5** |
| none (없음) | 0.0 |

근데 적중한 명제의 대부분이 partial로 나왔다.

---

## 25. 왜 partial이 많아?

프롬프트가 기울어져 있었다.

| | 설명 분량 |
|---|---|
| `none` 배제 규칙 | 불릿 4개 + 반례 |
| `partial` 기준 | **한 줄 + 예시 하나** |

기준이 없으니까 **애매하면 아래로 내린다.**

그리고 이런 일이 생긴다.

```text
정답: "채연은 이송될까 봐 숨겼다"
유저: "채연은 열이 나지만 이송될까 봐 숨긴다"

→ 거의 똑같은데 partial
```

## 26. 이게 모델 장애였어?

아니다. 확인했다.

하네스 이벤트 210건 중 `evaluator_verdict` 역할은 **0건**이다.

650번의 판정이 **파싱 실패도 폴백도 한 번 없이** 통과했다.

> **모든 none은 모델의 진짜 판단이었다.**

## 27. 날조 필터 사건도 있었어

"원문에 없는 명사가 나오면 날조"라는 필터가 있었다.

26개 밤에서 39개 주장을 버렸고, 2개 밤은 주장이 전부 사라져 0점이 됐다.

버려진 것들:

```text
트럭 옆면에 '○○축산'이 보인다.
준이가 '귀표'라는 단어를 사용한다.
채연은 이송된다고 믿는다.
```

**가장 좋은 추론만 골라서 죽였다.**

---

## 28. 왜 그랬어?

추리가 원래 **원문에 없던 개념을 끌어오는 행위**다.

"축산", "귀표" 같은 단어는 플레이어가 추론으로 만든 거다.

> **게임이 요구하는 행위랑 필터가 처벌하는 행위가 같았다.**

필터를 없앴다.

---

## 29. 그리고 플레이어한테 말도 안 해줬어

버려진 주장은 DB에만 저장되고 **어떤 화면에도 안 나왔다.**

6개 주장이 전부 지워진 플레이어는 **빈 목록을 보면서 이유를 몰랐다.**

> **침묵은 학습을 불가능하게 만든다.**

## 30. 자유발화 채점은 어떻게 고쳤어?

게이트 7개를 만들었다.

| # | 게이트 |
|---|---|
| 1 | 같은 정답의 6가지 표현이 전부 90점 이상 |
| 2 | 표현 간 편차 10점 이내 |
| 3 | 반복 간 편차 10점 이내 |
| 4 | **사실을 추가하면 점수가 오른다** |
| 5 | 지시어 문장이 명시 문장과 10점 이내 |
| 6 | 오답·부정문·혼합은 30점 미만 |
| 7 | 감정 문장만 쓰면 0점 |

**4번이 이 게이트의 탄생 이유다.** "동기를 추가했는데 20.4 → 16.0으로 떨어졌다"를 테스트로 고정했다.

## 31. 통과했어?

응. 13종 × 2회 전부.

| 케이스 | 점수 |
|---|---|
| 동등 정답 6표현 | **전부 100** |
| 부분 정답 | 20.4 |
| 동기 추가 | **36.5** (올랐다) |
| 오답 | 4.4 |
| 부정문 | 16.0 |
| 혼합 | 24.8 |
| 감정만 | 0 |

반복 편차 0%p, 폴백 0건.

## 32. 남은 문제는?

부정문이 16점이다. 0이어야 하는데.

**일부 오답·부정문에 부분 점수를 주는 오판이 남아 있다.**

게이트는 "30점 미만"이라 통과하지만, 완전히 고쳐진 건 아니다.

## 33. Planner 사건도 알아야 해

하네스 로그를 보니 두 단어가 계속 떴다.

```text
action_vocab: '혼자 있다'   39건
action_vocab: '소등'        18건
```

모델이 계속 생성하는데 **허용 어휘 목록에 없었다.**

3번 재생성이 다 실패해서 폴백 계획이 쓰였다. **81/81 전량.**

---

## 34. 그게 왜 심각해?

모든 회차에서 NPC 행동이 폴백으로 돌아갔다.

세계에서 볼 수 있는 사건이 그만큼 단조로워졌다.

> **정보원을 새로 넣어도 Planner가 폴백이면 세계에 안 나타난다.**

어휘 두 개 추가하면 되는 문제였다.

---

## 35. 순서 규칙

> **세계를 움직이는 층을 먼저 고친다.**

명제를 고치는 것보다 Planner를 고치는 게 먼저다. 안 그러면 고친 명제가 세계에 안 나타난다.

---

## 36. 실패는 지우지 마

`metrics.yml`에 `gate_pass: false`인 줄이 여러 개 있다.

**지우지 않는다.**

캘리브레이션을 6번 돌린 이력이 그대로 남아 있는데, 그게 증거다 — **우리가 튜닝하면서 뭘 봤는지**의 기록.

## 37. 실패는 나눠야 해

| 코드 | 분류 | 누구 책임 |
|---|---|---|
| F1 | 스키마 위반 | 모델 / 프롬프트 |
| F2 | 어휘 밖 행동 | **시나리오 데이터** |
| F3 | 금칙어 누설 | 모델 / 하네스 |
| F4 | 격리 위반 | 아키텍처 |
| F5 | 없는 사실 생성 | 모델 / 프롬프트 |
| F6 | 확인 불가 명제 | **시나리오 데이터** |
| F7 | 정보원 부재 | **시나리오 데이터** |
| F8 | 산식 결함 | 도메인 코드 |
| F9 | 힌트 역전 | 도메인 코드 |
| F10 | **골든셋 오염** | **평가 설계** |
| F11 | UX 사각지대 | 프론트 |

**F2·F6·F7은 모델 문제가 아니라 데이터 문제다.**

**F10은 평가 자체의 실패다.** 이 칸이 없으면 "자동 테스트 100%"를 근거로 쓰게 된다.

## 39. 왜 모델을 줄이려고 해?

VRAM 때문이 아니다. **동시성 때문이다.**

```text
exaone 7.8b + gemma3 12b = 13.2GB → 병렬 1
gemma3 4b   + gemma3 12b = 11.3GB → 병렬 2 가능
```

병렬 2가 되면 NPC 응답이 빨라진다.

fake는 결정론 기준선이다. 코드 구조가 안 깨졌다는 뜻이고, LLM이 잘한다는 뜻이 아니다.

이걸 섞어서 말하면 안 된다.

## 44. 왜 1회차랑 2회차를 분리해?

|---|---|---|
| 조건 | **무조건** | 전날 40점 이상 |
| 성격 | 튜토리얼 | **유혹** |
| 유저 상태 | 아무것도 모름 | 거의 다 왔음 |

합치면 RQ7("거의 다 왔을 때 오는 제안을 받는가")이 **측정되지 않는다.**

## 45. 사람 데이터는 얼마나 있어?

| | |
|---|---|
| 팀 플레이테스트 | 14밤, 통과 0, 평균 7.3% |
| 테스터1 | 5회차 완주, **48%** |
| 테스터2 | **아직 없음** |

## 47. 보고서 문장은 이렇게 써

네 가지가 다 있어야 한다.

```text
[무엇을] [어떤 조건에서] [몇 번] 측정해서 [무슨 값]
```

**좋은 예**

> 하네스 ON/OFF를 exaone에 프로브 5개 × 2회 투입했고, 누설률은 0%와 40%였다.

> 65회 제출에서 통과는 2건이고, 그 2건은 사람 플레이가 아니다.

**나쁜 예**

> 채점이 정확하다. ← 몇 번 쟀어?

> 자동 테스트 100%다. ← 골든셋이 정답지를 베꼈다

> 일치율 95%라 믿을 수 있다. ← 재현성은 정확도가 아니다

> 게임이 재미있다. ← 안 쟀다

## 48. 회고 화면이 곧 평가 결과야

나중에 붙이는 통계 페이지가 아니다.

5회차를 끝내면 **0%여도** 회고가 열리고, 거기에 이게 들어간다.

- 원숭이손 수락 기록 (제안 원문 + 근거 표시 + 수락 여부)
- 규칙 이력 (출처 / 회차 / 충돌)
- 도구 부작용
- 모델 출력 검사 기록
- 판정 근거 (명제별 verdict + 대응된 주장)

## 50. 그림은 평가 대상이야?

**그림의 예쁨은 아니다.**

평가하는 건 **그림이 실제로 정보원으로 작동하는지**다.

그리고 그림은 점수를 바꿀 수 없다 — 그림이 붙는 변수가 전부 코드가 계산하는 정수니까.

```text
비트 (1~6) · 손상 (0~3) · NPC 상태 (0~2)
```

LLM이 뭘 말해도 그림은 안 흔들린다.

## 53. 팀원이 기억할 10가지

1. 역할이 여섯 개고 각자 다른 정책을 지켜야 한다
2. **NPC는 잘하면 실패다** (일곱 살이어야 함)
3. 하네스 켜면 0%, 끄면 40% — 이게 우리 대표 숫자다
4. **재현성은 정확도가 아니다**
5. **테스트가 100%면 테스트를 먼저 의심한다**
6. 명제는 혼자서도 읽히는 완전한 문장이어야 한다
7. 명제를 고쳐도 **정보원이 없으면 똑같다**
8. 세계를 움직이는 층(Planner)을 먼저 고친다
9. `metrics.yml`의 실패 줄을 **지우지 않는다**
10. N이 작으면 작다고 쓴다
