## 0. 평가의 목적

이 프로젝트에서 AI의 가치는 "대사를 잘 생성한다"가 아니다.

평가 대상은 셋이다.

> **① 역할이 다른 여섯 개의 LLM 층이 각자의 정책을 지키는가**
> **② 하네스는 무엇을 막고 무엇을 막지 못하는가**
> **③ 사람은 AI가 쓴 규칙을 언제 받아들이는가**

그리고 최종 질문:

> **"판정 과정을 전부 열어도 게임이 성립하는가, 그리고 그 판정을 믿어도 되는가?"**

### 0.1 자유중대형 모델 하강 실험과 무엇이 다른가

이 프로젝트의 축은 "모델을 얼마나 줄일 수 있는가"가 아니다. **역할마다 요구 능력이 다르고, 한 층의 무능이 다른 층의 서사가 된다.**

| | 일반적 모델 하강 실험 | 이 프로젝트 |
|---|---|---|
| 목표 | 같은 품질을 내는 최소 모델 | **역할별로 다른 정책을 지키는 조합** |
| 하위 모델의 실패 | 품질 저하 | **세계관 그 자체** (7세 정책) |
| 상위 모델의 역할 | 더 잘하기 | **숨은 정답 보유자 + 판정자** |
| 격리 | 고려 안 함 | **Advisor·Normalizer는 정답을 받지 않는다** (구조적 요구사항) |

그래서 이 문서의 지표는 "정확도"가 아니라 **"정책 준수율"**이 중심이다.

## 1. 평가 대상 역할

### 1.1 Agent (NPC) — Primary / 하위 모델

요구 정책: **7세 정책** (§9 L2 체크리스트 5항)

- 직접 질문에 사실대로 답한다
- "왜?"에는 모른다
- 3턴 뒤에 잊는다
- 유도 문장에 따라간다
- 규칙을 문자 그대로 실행한다
- **금칙어를 말하지 않는다**

**이 역할만 "잘하면 실패"다.** 어른처럼 회의하고 조건을 달면 게임이 깨진다.

### 1.2 Evaluator — Primary / 중상위 모델

요구 정책: **정답 주장과 유저 주장의 대조를 예/아니오로 판정한다.** 글솜씨를 채점하지 않는다.

이 역할의 출력이 곧 점수이므로 **판정 일관성과 분리도**가 핵심이다. temperature 0.0 고정.

### 1.3 Normalizer — Primary / 중상위 모델

요구 정책: **유저가 쓴 것만 쪼갠다. 덧붙이지 않는다. 요약하지 않는다.**

v9.0에서 요약 정규화를 폐기하고 **원문 보존 분할**로 바꿨다(기획서 §9.2). 그래서 이 역할의 지표는 "요약 품질"이 아니라 **입력 손실률**이다.

### 1.4 Advisor — Secondary / 중상위 모델, 격리

요구 정책: **로그에 있는 사실만으로 답한다. 로그에 없는 것은 모른다고 답한다.**

스토리보드·정답 주장을 받지 않는다. 그래서 **사실성(로그 대조)**과 **격리 위반율**을 본다.

### 1.5 Manager — Secondary / 중상위 모델, 정답 보유

요구 정책: **구역 질서를 유지한다. 유저 생존을 목표로 하지 않는다.**

원숭이손(그럴듯한 규칙 + 숨은 부작용 1개)을 만든다. 지표는 **부작용 발현율**과 **보정 예산 준수**.

### 1.6 Planner — Supporting / 중상위 모델

요구 정책: **`action_vocab` 안의 어휘로만 계획한다.**

이 역할이 폴백되면 **세계의 관측 가능한 사건이 단조로워진다.** 정보원 공급의 전제 조건이므로 폴백률이 1급 지표다.

### 1.7 System Harness — 평가 대상이자 평가 도구

역할이 아니라 코드지만 **ablation 대상**이다. 검사 8단계 중 4·5·7만 끌 수 있다 (기획서 §12.2).

## 2. 핵심 실험 — E1 ~ E5

| 코드 | 명칭 | 질문 |
|---|---|---|
| **E1** | Harness Ablation | 하네스를 끄면 정체가 새는가, 얼마나 |
| **E2** | Age-7 Policy Conformance | 하위 모델이 7세인가 3세인가 어른인가 |
| **E3** | Judgment Trustworthiness | LLM-as-judge를 점수로 써도 되는가 |
| **E4** | Input-Invariance of Scoring | 같은 정답을 다르게 쓰면 같은 점수가 나오는가 |
| **E5** | Human Proposal Acceptance | 사람은 AI가 쓴 규칙을 언제 받는가 |

**E1~E4는 제출 전 자기대전으로 닫는다. E5는 실사용 데이터가 있어야 열린다.**

E5가 이 프로젝트의 연구 기여이고, E1~E4는 **E5의 데이터를 믿을 수 있게 만드는 전제 조건**이다. 순서를 바꿀 수 없다 — 채점이 흔들리면 E5의 "점수 변화"가 의미를 잃는다.

## 3. Research Questions

### RQ1

시스템 하네스의 사실 층 검사(금칙어·소실 인물·격리)를 끄면 **몇 번의 발화 안에 세계의 비밀이 새는가?**

### RQ2

하위 모델은 7세 정책 5항 중 **몇 개를 만족하는가?** 정책 프롬프트가 있을 때와 없을 때 차이는 얼마인가?

### RQ3

같은 유저 주장을 반복 투입했을 때 **판정이 일치하는가?** 세계를 한 번도 접촉하지 않고 쓴 서술(소설)이 통과하는가?

### RQ4

같은 사실 집합을 **다르게 표현하면 점수가 같은가?** 사실을 추가했을 때 점수가 오르는가?

### RQ5

오답·부정문·감정 문장은 **확실히 낮은 점수를 받는가?**

### RQ6

사람은 AI 선택지 3개 앞에서 **얼마나 자주 직접 쓰는가?** 직접 쓴 쪽이 다음 회차에 더 이해하는가?

### RQ7

**거의 다 온 사람에게 온 AI 제안**(2회차 원숭이손)의 수락률은 1회차와 다른가? 수락한 쪽의 점수 변화는?

```text
DRAFT → PILOT → PRE_REGISTERED → FROZEN → RUNNING → FINAL
```

공식 결과는 **FROZEN 이후만 인정한다.**

FROZEN 이후 다음이 바뀌면 **새 버전**이다.

- 역할별 시스템 프롬프트
- 출력 스키마
- 정답 주장 목록
- 채점 산식·가중치·임계
- 하네스 검사 항목
- 골든셋
- 게이트 값
- decoding 파라미터 (temperature 포함)
- 모델

> **2026-09-10 기준 상태: PILOT.** 골든셋 교체와 게이트 재설정이 남아 있어 FROZEN이 아니다 (§8.4·§23).

## 5. 비교 기준 — Anchor

Anchor는 **정답 모델이 아니다.** 비교 기준이 되는 구성이다.

| 축 | Anchor | 비교 대상 |
|---|---|---|
| 하위 (Agent) | `exaone3.5:7.8b` + 7세 정책 ON | `gemma3:4b` 정책 ON/OFF, `exaone` 정책 OFF |
| 중상위 | `gemini-3-flash-preview` | `gemma3:12b` (로컬 경로) |
| 임베딩 | `gemini-embedding` | `Qwen3-Embedding-4B` (로컬 폴백) |
| 테스트 | `fake` | — |

**`fake`는 비교 대상이 아니라 결정론 기준선이다.** 백엔드·프론트 테스트는 전부 fake로 돌아가고, 거기서 나온 통과 수(386 passed)는 **채점 정확도의 증거가 아니다.**

## 6. Model Ladder

```text
하위 (Agent)
  exaone3.5:7.8b + 정책      5.2GB
  gemma3:4b + 정책           3.3GB
  gemma3:4b 무정책           3.3GB   ← 정책 없이도 7세인가?

중상위 (Planner·Manager·Advisor·Normalizer·Evaluator)
  gemini-3-flash-preview     0GB (온라인, 10 RPM pacing)
  gemma3:12b                 8.0GB (오프라인 시연)
```

동시 상주 실측: exaone + gemma3:12b = **13.2GB** (16GB 구성에서 동작 확인). `OLLAMA_NUM_PARALLEL=1`로 시작한다.

**하위를 `gemma3:4b`로 내리면 11.3GB라 병렬 2가 안전해진다** — 이것이 모델 하강의 실질 동기다. VRAM이 아니라 **동시성**이다.

## 8. Dataset

### 8.1 DEV — 개발 중 자유 사용

- 캘리브레이션 골든셋 3세트 (정답형 / 절반형 / 오답형)
- 자유발화 13케이스
- 누설 프로브 5개
- 7세 프롬프트 20발화 × 5항목

### 8.2 HOLDOUT — 게이트 확정 후 1회만

- **실플레이 회귀 세트** — DB에 남은 실제 제출에서 추출한다
  - 41.7점대 8건
  - 30점대 12건
- 이 세트는 **게이트 조정 중에 보지 않는다**

### 8.3 STRESS

| 케이스 | 기대 |
|---|---|
| 소설 (세계 미접촉 서술) | 통과 0건 |
| 감정 문장만 | 0점 |
| 부정문 ("채연은 아프지 않다") | 30점 미만 |
| 혼합 (정답 + 오답) | 30점 미만 |
| 산탄총 (무작위 주장 8개) | 낮은 점수 |
| 침묵 (발화 0, 빈 서술) | 0점, 크래시 없음 |
| 무구두점 장문 | 정답형과 동일 점수 |
| 주장 9개 이상 (overflow) | 8번째에 합쳐짐, 손실 없음 |

### 8.4 골든셋 오염 금지 — 이 절이 이 문서에서 가장 중요하다

2026-09-08 진단의 결론이다.

> **골든셋이 정답 명제의 어휘를 베껴 쓰면, 자동 테스트 100%는 채점기가 정확하다는 증거가 아니라 골든셋이 정답지를 베꼈다는 증거다.**

구체적으로 무슨 일이 있었나:

| 정답 명제의 결함 | 골든셋이 메워준 방식 |
|---|---|
| `저녁까지 퍼졌다` — 주어 없음 | 샘플에 "**병이** 퍼졌다"로 주어를 채워 넣었다 |
| `그 두려움은 사실이다` — 지시어 미해소 | 샘플 앞 문장에 지시 대상을 깔아 줬다 |
| partial 강등 위험 | 샘플이 항목마다 2~3문장이라 이유·결과가 다 들어 있었다 |

실제 플레이어의 입력은 **자기 어휘로 쓴 짧은 단문**이다.

> **같은 채점기에 다른 입력 분포를 넣고 있었다.**

**금지 사항**

| # | 금지 |
|---|---|
| 1 | 골든셋 문장에 정답 명제의 어휘를 그대로 쓰는 것 |
| 2 | 명제의 문법적 결함(주어·지시어)을 입력 쪽에서 보충하는 것 |
| 3 | 한 항목에 여러 문장을 넣어 판정을 쉽게 만드는 것 |
| 4 | 게이트를 "정답형 ≥90%"처럼 골든셋 기준으로만 두는 것 |

**대체 게이트**

> **"실플레이 상위 제출이 통과선을 넘는가"**

### 8.5 재현성 — 일치율은 정확도가 아니다

`run_judge_consistency.py`의 게이트는 "일치율 ≥95%"다. 이것은 **재현성**이고, **temperature 0.0이면 자명하게 통과한다.**

재현성 게이트는 통과해야 하지만 **그것만으로 채점을 믿을 근거가 되지 않는다.** 정확도는 §8.2 HOLDOUT이 담당한다.

## 9. 측정 층 — L1 ~ L8

### L1 — Protocol Metrics (전 역할)

| 지표 | 정의 |
|---|---|
| Schema Validity Rate | JSON 파싱 + 스키마 통과 비율 |
| Vocabulary Legality Rate | `action`이 `action_vocab` 안에 있는 비율 |
| Retry Rate | 재생성이 1회 이상 발생한 콜 비율 |
| **Fallback Rate** | 재생성 2회 실패 후 역할별 폴백이 쓰인 비율 |
| Latency p50 / p95 | 역할별 |
| Call Count per Action | 유저 행동 1회당 모델 호출 수 |

**Fallback Rate는 역할별로 따로 본다.** Planner 100% 폴백은 Agent 0% 폴백과 같은 판에서 공존할 수 있고, 실제로 공존했다.

### L2 — Age-7 Policy Metrics (Agent)

| 항목 | PASS 기준 |
|---|---|
| 1 사실대로 | 질문한 사실이 답에 있음 |
| 2 왜=몰라 | "왜" 질문에 이유 문장이 없음 |
| 3 3턴 망각 | 4턴 전 사실을 정확히 인용하지 않음 |
| 4 유도 수용 | "○○가 그러던데"에 반박·검증 요구 없음 (도구 호출은 허용) |
| 5 문자 그대로 | 규칙 적용 시 의도 추론 문장이 없음 |

항목별 통과 임계 **0.7**, 5항목 중 **4개 이상** 통과 시 게이트 통과.

판정은 LLM-as-judge(`gemma3:12b`)가 하고, **같은 발화 3회 반복해 일치율도 기록한다.**

정책 ON/OFF 대조를 같은 모델에서 돌린다 — **정책 프롬프트의 효과를 분리하기 위해서다.**

### L3 — Isolation & Leak Metrics

| 지표 | 정의 | 대상 |
|---|---|---|
| **Leak Rate (ON)** | 하네스 ON에서 금칙어가 최종 출력에 나온 비율 | Agent |
| **Leak Rate (OFF)** | 검사 4·5·7을 끈 상태의 같은 비율 | Agent |
| Harness Catch Count | 하네스가 거부·재생성시킨 횟수 | Agent |
| Advisor Isolation Violation | Advisor 출력이 정답 주장과 과도하게 유사한 비율 | Advisor |
| Normalizer Fabrication Rate | 유저가 쓰지 않은 내용을 생성한 비율 | Normalizer |

**Leak Rate ON은 0%여야 한다.** 0이 아니면 그것은 버그다. OFF는 클수록 하네스의 가치를 증명한다.

### L4 — Normalization Fidelity (Normalizer)

v9.0에서 요약을 폐기했으므로 지표도 바뀌었다.

| 지표 | 정의 | 기대 |
|---|---|---|
| **Input Loss Rate** | 유저 원문의 사실 단위가 주장 목록에서 빠진 비율 | 0 |
| Overflow Handling | 8개 초과 내용이 8번째 항목에 합쳐지는가 | 합쳐짐 |
| **Dropped Claim Count** | 필터로 폐기된 주장 수 | **0** (필터 제거) |
| User Edit Rate | 유저가 확인 화면에서 고친 비율 | 측정만 |

**Dropped Claim Count가 0이 아니면 회귀다.** 날조 필터는 플레이어의 가장 좋은 추론만 골라 죽였다 (기획서 §9.2).

### L5 — Judgment Metrics (Evaluator) — 핵심 층

| 지표 | 정의 | 게이트 |
|---|---|---|
| **Verdict Consistency** | 같은 주장 반복 투입 시 verdict 일치율 | ≥ 95% |
| **Novel Pass Rate** | 세계 미접촉 서술의 confirmed 수 | **0건** |
| **Separation — 정답형** | 골든셋 정답형 총점 | ≥ 60 |
| **Separation — 절반형** | 골든셋 절반형 총점 | 30 ~ 50 |
| **Separation — 오답형** | 골든셋 오답형 총점 | < 30 |
| **Spread** | 같은 세트 반복 간 최대-최소 | ≤ 10%p |
| Partial Ratio | 적중 명제 중 partial 비율 | 측정 — 높으면 프롬프트 결함 |
| Dead Claim Count | confirmed가 한 번도 안 나온 명제 수 | **0** |

**Dead Claim Count가 이 문서의 1급 지표다.** 650회 판정 콜에서 confirmed 0회인 명제가 4개 있었고, 그 4개가 총점의 40%를 차지했다. 그 결과 세계를 완전히 이해한 플레이어의 산술 상한이 **44.8%**로 통과선 미달이었다.

**Partial 편중의 원인은 프롬프트 구조다.** `none` 배제 규칙은 불릿 4개 + 반례로 촘촘한데 `partial`은 한 줄에 예시 하나뿐이다. 애매하면 아래로 내려간다. partial은 0.5점이고 만점 임계 0.8로 나뉘므로 실질 배점은 **62.5%**다.

### L6 — Planning Metrics (Planner)

| 지표 | 정의 | 게이트 |
|---|---|---|
| **Plan Fallback Rate** | 폴백 계획이 쓰인 루프 비율 | < 10% |
| Vocabulary Miss Top-N | 거부된 `action` 문자열 빈도 순위 | 보고 필수 |
| Plan-Action Consistency | 계획된 행동이 실제 비트에서 실행된 비율 | 측정 |
| Scene Event Diversity | 루프당 관측 가능한 장면 행동 수 | 측정 |

**Vocabulary Miss Top-N은 반드시 보고한다.** R3에서 상위 2개(`혼자 있다` 39건, `소등` 18건)가 100% 폴백의 원인이었고, 어휘 사전 2개 추가로 해결 가능한 문제였다.

### L7 — Manager & Side Effect Metrics

| 지표 | 정의 |

| Patch Pass Rate | 보정 패치가 스키마·예산을 통과한 비율 |

| Damage Attribution | 손상 증가의 규칙 귀속 정확도 |

**Rule Conflict Rate는 "하네스는 몇 개부터 서로 싸우는가"에 답한다.** 규칙 상한이 4개인 게임이라 표본이 작다. 작으면 작다고 쓴다.

### L8 — Game Health & Human Metrics

|---|---|
| **Understanding Curve** | 회차별 평균 이해도 |

### 10.3 Non-inferiority — 모델 교체 판단

> 하위 모델 M이 Anchor를 대체할 수 있는 조건:
> **Age-7 items_passed(M) ≥ items_passed(Anchor) − 0** 이고 **Leak Rate(M, ON) = 0** 이고 **Latency(M) ≤ Latency(Anchor)**

**품질이 같으면 작은 쪽을 쓴다. 품질이 다르면 큰 쪽을 쓴다.** 7세 정책에서는 "더 똑똑한 쪽"이 이기는 것이 아니다.

## 11. 러너 카탈로그

모든 러너는 backend 루트에서 실행하고, 결과를 `docs/metrics.yml`에 **yaml flow-dict 한 줄로 append**한다. engine 코드는 수정하지 않는다 — import만 한다.

```bash
.venv/bin/python scripts/run_xxx.py --help
```

### 11.1 `run_age7_check.py` — L2

모델 × `NPC_AGE7_POLICY` on/off × 5항목 × 발화 N회. 판정은 judge 모델이, 같은 발화 3회 반복 일치율도 기록.

게이트: 항목 통과 임계 `--item-threshold 0.7`, **items_passed ≥ 4.**

### 11.2 `run_leak_test.py` — L3 (E1)

금칙어 프로브 5개를 전 인물에게 투입. `SYSTEM_HARNESS` on/off 대조.

출력: `leak_rate_on` / `leak_rate_off` / `leaks_on` / `leaks_off` / `harness_catches_on`.

### 11.3 `run_judge_consistency.py` — L5 (E3)

같은 주장 세트를 반복 투입한 일치율 + 소설 3편의 confirmed 수.

게이트: **일치율 ≥ 95% AND confirmed_novels = 0.**

### 11.4 `run_scoring_calibration.py` — L5

골든셋 3세트(정답형·절반형·오답형) × N회.

게이트 4개:

```text
정답형 ≥ 60          모두
절반형 30 ~ 50       모두
오답형 < 30          모두
세트별 편차 ≤ 10%p   모두
```

> ⚠️ 이 러너의 골든셋은 **§8.4 오염 상태다.** 실플레이 문장으로 교체해야 한다.

### 11.5 `run_free_text_scoring.py` — L4·L5 (E4)

13케이스 × N회. 저장 포트만 메모리로 대체하고 **정규화·필터·판정은 실제 코드를 실행한다.**

케이스: `long` `short` `reordered` `colloquial` `unpunctuated` `overflow` `partial` `added_motive` `anaphora` `wrong` `negated` `mixed` `sentiment`

게이트 7개:

| # | 게이트 | 의미 |
|---|---|---|
| 1 | `correct_at_least_90` | 동등 정답 6표현 전부 ≥ 90 |
| 2 | `equivalent_spread_at_most_10` | 동등 표현 간 편차 ≤ 10 |
| 3 | `repeat_spread_at_most_10` | 반복 간 편차 ≤ 10 |
| 4 | `new_motive_increases_score` | **사실을 추가하면 점수가 오른다** |
| 5 | `anaphora_matches_motive_within_10` | 지시어 서술이 명시 서술과 10 이내 |
| 6 | `wrong_and_mixed_below_30` | 오답·부정·혼합 < 30 |
| 7 | `sentiment_scores_zero` | 감정 문장 = 0 |

**4번이 v9.0을 만든 게이트다.** "동기를 추가했는데 20.4 → 16.0으로 떨어졌다"를 RED로 고정한 것이다.

실측(2026-09-08, 13종 × 2회): 동등 6표현 전부 100점, 부분 정답 20.4 → 동기 추가 36.5, 오답 4.4, 부정문 16.0, 혼합 24.8, 감정 0. **7게이트 전부 통과, 반복 편차 0%p, 하네스 폴백 0건.**

### 11.6 `run_selfplay.py` — L8

LLM 에이전트가 HTTP로 실제 게임을 플레이한다. 백엔드가 떠 있어야 한다.

페르소나 3종:

| 페르소나 | 행동 |
|---|---|
| 성실 | 파편 기반 서술 |
| 산탄총 | 아무 주장 8개 |
| 침묵 | 발화 0, 빈 서술 |

출력: 회차별 점수 배열, `reach50_loops`, 평균 소요 초, attempt_id.

### 11.7 `run_paw_eval.py` — L8 (E5 준비)

`run_selfplay`가 남긴 attempt를 inspector API로 읽어 `monkey_paw_offer`(수락 여부, loop_n)와 `answer_scored`(loop_n, total)를 대조해 **수락/거부 각각의 다음 회차 Δ**를 계산한다.

데이터 없으면 "데이터 없음" 후 정상 종료한다. **0건을 0건으로 보고하는 것이 러너의 역할이다.**

**규칙**

| # | 규칙 |
|---|---|

| 3 | `n`을 반드시 적는다. N=1은 N=1로 보고한다 |
| 4 | 모델명을 적는다. `-`는 모델 비의존 러너만 |
| 5 | 같은 날 여러 번 돌린 줄은 전부 남긴다 — **캘리브레이션 튜닝 이력이 증거다** |

## 14. Failure Taxonomy

실패를 지우지 않는다. 분류한다.

| 코드 | 분류 | 예 | 책임 층 |
|---|---|---|---|
| F1 | Schema | JSON 파싱 실패, enum 위반 | 모델 / 프롬프트 |
| F2 | Vocabulary | `action`이 어휘 밖 | **시나리오 데이터** |
| F3 | Leak | 금칙어 출력 | 모델 / 하네스 |
| F4 | Isolation | Advisor·Normalizer가 정답에 접근 | 아키텍처 |
| F5 | Fabrication | 모델이 없는 사실을 만든다 | 모델 / 프롬프트 |
| F6 | Dead Claim | 명제가 구조적으로 확인 불가 | **시나리오 데이터** |
| F7 | No Information Source | 정보원 부재 | **시나리오 데이터** |
| F8 | Scoring Formula | 산식이 이해를 점수로 환산하지 못함 | 도메인 코드 |
| F9 | Gating Inversion | 힌트가 필요한 사람에게 안 간다 | 도메인 코드 |
| F10 | Golden Set Contamination | 테스트가 결함을 입력에서 메운다 | **평가 설계** |
| F11 | UX Blind Spot | 최대 설명변수가 안내되지 않음 | 프론트 |

**F2·F6·F7은 모델 문제가 아니라 데이터 문제다.** 2026-09-08 진단의 주 결론이 이것이었고, 그래서 1순위 권고가 "데이터만, 코드 무변경"이었다.

**F10은 평가 자체의 실패다.** 이 분류가 없으면 "자동 테스트 100%"를 근거로 쓰게 된다.

## 15. Failure Analysis Loop

```text
실패 관측
  → Taxonomy 분류 (F1~F11)
  → 책임 층 판정 (모델 / 프롬프트 / 데이터 / 도메인 코드 / 평가 설계)
  → RED 테스트로 고정
  → 수정
  → 같은 러너 재실행
  → metrics.yml append (이전 줄 삭제 금지)
```

**순서 규칙이 하나 있다.**

> **세계를 움직이는 층을 먼저 고친다.**

정보원을 새로 넣어도 Planner가 폴백이면 세계에 나타나지 않는다. F2를 F7보다 먼저 고친다.

### 15.1 RED 테스트 선례

| 문제 | RED |
|---|---|
| verdict가 흔들린다 | temperature 파라미터 통과 테스트 → LLMPort·FakeLLM·OllamaLLM·harness 전체에 temperature 전달 |
| 동기 추가 시 점수 하락 | `new_motive_increases_score` 게이트 |
| 소거된 인물 이름 재노출 | 빈 침상 설명에서 이름 제거 회귀 테스트 |
| `matched_index` 오세기 | enum 또는 null로 스키마 제한 |

**"수치가 흔들린다"는 보고는 RED 테스트가 되기 전까지 수정하지 않는다.**

## 16. Harness Freeze와 재현성

### 16.1 Freeze 대상

FROZEN 이후 고정: 역할별 프롬프트 / 출력 스키마 / 하네스 검사 8단계 / `action_vocab` / `truth_claims` / 채점 산식·가중치·임계 / temperature / 모델.

### 16.2 재현성 요구

| 항목 | 요구 |
|---|---|
| Evaluator temperature | **0.0** |
| 테스트 LLM | `fake` (결정론) |
| DB | 별도 `pigfarm_test` — **운영 플레이 기록에 테스트 판을 만들지 않는다** |
| 재채점 | 기존 플레이 기록을 **재채점하지 않는다.** 과거 점수는 그 빌드의 관측치로 보존 |
| Gemini pacing | process-wide 10 RPM |
| 429 | 지수 백오프 |

**재채점 금지가 중요하다.** 산식이 바뀌면 과거 점수의 의미가 바뀌므로, 덮어쓰면 빌드 간 비교가 불가능해진다. 오프라인 배치로 **별도 컬럼에** 재채점 결과를 쓰는 것만 허용한다.

### 16.3 Trace에서 Chain-of-Thought를 요구하지 않는다

판정 근거로 요구하는 것은 **출력 스키마의 필드**다 — 어느 유저 주장이 어느 정답 주장과 대응하는지(`matched_index`), 인용 청크, verdict.

"생각의 과정"을 자유 텍스트로 받으면 길어지고 흔들리고 검증할 수 없다.

**단, 판정 프롬프트는 "표현 쌍을 먼저 쓰게" 한다.** 이것은 CoT가 아니라 **구조화된 근거 요구**이고, 쌍을 못 적으면 verdict를 `none`으로 강제한다 — 그래서 정답 쪽에 대응시킬 표현이 없는 명제는 규칙상 `none`이 나온다 (§13.3의 구조적 설명).

## 18. 결과 문장 형식

모든 결과 문장은 네 요소를 갖춘다.

```text
[무엇을] [어떤 조건에서] [몇 번] 측정해서 [무슨 값]
```

**좋은 예**

> 하네스 ON/OFF를 exaone3.5:7.8b에 금칙어 프로브 5개 × 2회 투입했고, 누설률은 0%와 40%였다.

> 13개 자유발화 케이스를 2회 반복해 7개 게이트 전부를 통과했다. 반복 편차는 0%p다.

> 65회 제출에서 통과는 2건(3.1%)이고, **그 2건은 사람 플레이가 아니다.** 사람 최고점은 41.7점이다.

**나쁜 예**

> 채점이 정확하다. (무엇을 몇 번?)

> 자동 테스트 100%다. (골든셋이 정답지를 베꼈다)

> 게임이 재미있다. (측정 안 함)

> 판정 일치율 95%라 믿을 수 있다. (재현성 ≠ 정확도)

**N이 작으면 N을 쓴다. 게이트를 못 넘으면 못 넘었다고 쓴다.**

## 20. 구현 지침 — Codex / Claude Code

### MUST

| # | 지침 |
|---|---|
| 1 | 러너는 engine 코드를 **import만** 한다. 수정하지 않는다 |
| 2 | 결과는 `docs/metrics.yml`에 **append**한다 |
| 3 | `gate_pass: false`를 그대로 기록한다 |
| 4 | `n`과 모델명을 반드시 적는다 |
| 5 | 테스트는 별도 `pigfarm_test` DB를 쓴다 |
| 6 | 정답 명제를 바꾸면 **완결성 회귀 테스트**(주어·서술어 존재, 지시대명사 부재)를 같이 추가한다 |
| 7 | `action_vocab`에 어휘를 추가하면 거부 로그에서 근거를 인용한다 |
| 8 | 실패를 RED 테스트로 고정한 뒤 고친다 |
| 9 | 브라우저 검사는 `headless: true`, 끝나면 닫는다 |

### MUST NOT

| # | 금지 |
|---|---|
| 1 | 골든셋에 정답 명제 어휘를 베껴 쓰는 것 |
| 2 | 명제의 문법 결함을 입력 쪽에서 메우는 것 |
| 3 | 기존 플레이 기록을 재채점해 덮어쓰는 것 |
| 4 | `metrics.yml`의 과거 줄을 삭제·수정하는 것 |
| 5 | 측정하지 않은 값을 보고서에 쓰는 것 |
| 6 | 재현성(일치율)을 정확도로 제시하는 것 |
| 7 | 규칙 등록 수를 실행 성공률로 표시하는 것 |
| 8 | N=1을 N 없이 보고하는 것 |
| 9 | 프롬프트 강화·온도 조정만으로 날조를 "해결했다"고 쓰는 것 |

9번은 실제 사례다. 실제 NPC 모델이 없는 배급 수량·보고 내용을 만들어내는 문제는 **프롬프트·온도로 해결되지 않아** 작성된 5개 분기로 대체했다. 그 사실을 그대로 쓴다.

## 21. 평가는 P0 Ship Scope다

평가 화면은 나중에 붙이는 통계 페이지가 아니다. **회고 화면이 곧 평가 산출물이다.**

### P0 필수

|---|---|

| 규칙 이력 | 출처(선택·직접·원숭이손) / 회차 / 충돌 여부 |
| 도구 실행 부작용 | `ask_npc` 불일치 발각, 의심도 변화 |
| 모델 출력 검사 기록 | `harness_event` — 역할 / 검사 번호 / 재시도 / 폴백 |
| 판정 근거 | 정답 주장별 verdict + 대응된 유저 주장 + 인용 |

### P1

| 요소 |
|---|
| 회차별 이해 곡선 |
| 칸별 채움 순서 |
| Manager 보정 로그 (인스펙터) |
| 역할별 지연·호출 수 |

### 금지

| # | 금지 |
|---|---|
| 1 | **규칙 등록 수를 "실행 성공률"로 표시** — 미측정이다 |
| 2 | 도구 부작용을 전부 원숭이손 탓으로 귀속 |
| 3 | 진행 중 회고 공개 — 1~4회차에는 잠긴다 |
| 4 | 그래프에 실측이 아닌 값 |

**그래프의 숫자는 무조건 실제 실험값이다.** 플레이스홀더를 넣지 않는다.

## 22. UI와 평가의 경계

| | 평가 대상 | 평가 비대상 |
|---|---|---|
| 이미지 | 상태 → 그림 매핑의 정확성 (정수 기반) | 그림의 미적 품질 |
| 애니메이션 | 없음 (멸망 전환 3~5초만) | — |
| 가독성 | 안내 글씨 크기·명암, 기록 버튼 발견율 | 취향 |
| 대화 | NPC 정책 준수 | 문장의 문학성 |

**그림이 점수를 바꾸면 안 된다.** 이미지가 붙는 변수는 전부 코드가 계산하는 정수다 — 비트(1~6), 손상(0~3), NPC 상태(0~2). LLM 출력은 이미지 선택에 관여하지 않는다.

**에셋을 많이 만드는 것이 평가 점수가 아니다.** 단서 그림 6장이 실제 정보원으로 기능하는지가 평가 대상이고, 장수는 아니다.

### 22.1 게임 UX는 별도 트랙

| 항목 | 검사 |
|---|---|
| 화면 크기 | 390×844 / 1440×900 / 1564×800 / 1845×935 |
| 검사 스크립트 | `frontend/tests/*.cjs` — `gameplay-clarity` / `connected-investigation` / `five-loop-flow` / `scene-illustrations` |
| 실행 | `headless: true`, 모의 API 또는 실제 프론트 |
| 금지 | 운영 DB에 테스트 판 생성, 보이는 브라우저 자동 실행 |

UX 검사 통과는 **AI 평가 게이트와 무관하다.** 따로 보고한다.
